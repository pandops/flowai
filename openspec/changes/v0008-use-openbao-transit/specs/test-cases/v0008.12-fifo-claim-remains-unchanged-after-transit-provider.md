# Test case: v0008.12-fifo-claim-remains-unchanged-after-transit-provider

## Intent

Regression boundary: the FIFO claim, lifecycle, image precedence,
tenancy, and capacity-independence invariants that v0002 ships are
unchanged after the v0008 provider swap. The OpenBao Transit
configuration MAY be live during the test; it MAY be sealed;
either way the non-crypto surfaces behave exactly as v0002 mandates.

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

`state-registry` — `### Requirement: State Registry observes Executor capacity without gating discovery or claim`.

`state-registry` — `### Requirement: State Registry enforces Executor scope as a registration-time decision`.

## Preconditions

- The State Registry and PostgreSQL run with the v0008 binary.
- An authenticated system administrator has created `team-a` and
  `team-b` through `POST /admin/teams`; an authenticated
  team-owned Executor `executor-1` is registered for `team-a` with
  one tag, `scope = team`, and a saturated `running_count =
  max_capacity`.
- The OpenBao Transit server is configured with the documented
  key and is reachable over mTLS.

## Steps

1. Through the listener authorized for `team-a`, ingest three
   pending tasks (`task-T1`, `task-T2`, `task-T3`) for `team-a`
   with the same required tag and the same `ingested_at` so the
   FIFO tie-break depends on `task_id`.
2. Through the listener authorized for `team-b`, ingest one
   pending task (`task-F1`) for `team-b` with the same tag.
3. `executor-1` requests discovery; the response names only the
   three same-team tasks in `(ingested_at ASC, task_id ASC)` order
   with no foreign task, foreign count, foreign cursor, or foreign
   timing.
4. `executor-1` posts `POST /v1/executors/{executor-1}/claim` with
   `task_id = task-T2` and a fresh `command_id = C-1`; the State
   Registry rejects the claim with `409 older_task_must_be_claimed_first`
   without appending an event.
5. `executor-1` posts the same claim with `task_id = task-T1` and
   `command_id = C-1`; the State Registry accepts with `200
   claimed`, persists the FIRST lifecycle event `created` with
   `executor_id = executor-1` and payload meaning `task task-T1
   loaded by executor-1`, persists `tasks.exolved_image` and
   `tasks.image_source` from the four-level precedence, and
   removes `task-T1` from the response of a second discovery call.
6. `executor-1` repeats step 5 with the same `(task_id = task-T1,
   command_id = C-1)`; the State Registry returns the original
   `200 claimed` body with no new event and no field update.
7. Inspect the canonical event log, the persisted `tasks`
   projection, the `secret_versions` table, and the audit entries.

## Expected outcome

- The FIFO `(ingested_at ASC, task_id ASC)` ordering rule still
  applies; the saturated `running_count = max_capacity`
  observation never gates the claim; the foreign `team-b` task
  never appears in `executor-1`'s discovery response; the older-
  task rejection returns `409 older_task_must_be_claimed_first`
  without an event; the claimed task receives exactly one `created`
  event whose payload matches the documented meaning; the
  successful claim persists `tasks.resolved_image` and
  `tasks.image_source` in the same transaction; the `secret_versions`
  row produced by v0008 carries `crypto_provider = 'transit'` (if
  this test creates one) or remains unchanged from prior runs.
- The `tasks.owner_command_id` is set to `C-1` on the claimed task
  and remains immutable for the row's lifetime; the same `(T1,
  C-1)` retry produces no new event and no field update.
- No assertion of this test relies on a Transit decrypt operation;
  the cryptographic surfaces remain a regression boundary whose
  verification contract is the v0002 and v0008 open-environment
  tests, not this test.
