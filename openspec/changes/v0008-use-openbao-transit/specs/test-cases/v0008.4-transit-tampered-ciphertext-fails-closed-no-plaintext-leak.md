# Test case: v0008.4-transit-tampered-ciphertext-fails-closed-no-plaintext-leak

## Implements

`state-registry` — `### Requirement: State Registry pins the non-revealing 404 shape to every provider failure class`.

`state-registry` — `### Requirement: State Registry uses local AES-256-GCM authenticated encryption for secret values`.

## Intent

Verify that a ciphertext tampered with after write, or whose
`associated_data` bytes diverge from the canonical `team_id`,
logical secret identifier, and version binding, fails closed with
the same non-revealing `404 environment_unknown_or_unavailable`
shape and never lets plaintext, provider error bodies, or Transit
endpoint detail escape through audit, log, or response body.

## Preconditions

- A `team-a` task is claimed by `executor-1`; a same-team environment
  holds a Transit-encrypted secret whose `crypto_provider =
  'transit'` and whose opaque `key_id` / `key_version` are recorded.
- The signed open-environment scope token is valid under every
  canonical authorization check.

## Steps

1. Open the environment with the valid token; record the response
   body for the success baseline.
2. Replace the persisted ciphertext byte sequence with one whose
   first byte is incremented; reload the State Registry; attempt the
   open with the same valid token and observe the response.
3. Replace the canonical `secrets.environment_id` binding used at
   write time to a different same-team environment id; reload the
   State Registry; attempt the open with the same valid token and
   observe the response.
4. Replace the canonical `secrets.version` to a different same-team
   logical secret version; reload the State Registry; attempt the
   open with the same valid token and observe the response.
5. Capture the application log, audit entries, and error responses
   for steps 2, 3, and 4.

## Expected outcome

- Step 1 returns `200` with the decrypted env-style values in memory
  only.
- Steps 2, 3, and 4 each return the same non-revealing `404
  environment_unknown_or_unavailable` shape; the State Registry
  performs zero plaintext disclosure to the response body, audit, or
  application log; the Transit-call counter increments at most once
  per request, on the decrypt path, and the Transit response is
  the documented failure class.
- Step 5 contains no plaintext, no ciphertext byte, no nonce byte, no
  tag byte, no `associated_data` value, no Transit token, no Transit
  endpoint, namespace, mount path, or `key_name`, and no raw Transit
  error body; only the `provider_invalid_aad_or_ciphertext` outcome
  status class plus identifier-level metadata may be present.
- The persisted row continues to carry `crypto_provider = 'transit'`;
  the failed decrypt does not flip it to a different provider, the
  stored ciphertext is unchanged after the failure, and no
  `audit_entries` row is appended twice for the same attempt.
