# Test case: v0008.2-transit-secret-write-persists-opaque-key-id-version

## Implements

`state-registry` — `### Requirement: State Registry routes every secret write and read through a pluggable crypto provider`.

`state-registry` — `### Requirement: State Registry stores team-owned secrets with immutable versions`.

## Intent

Verify that the public opaque `key_id` and `key_version` envelope
recorded on every `secret_versions` row matches the
provider-neutral integer `<N>` extracted from the Transit ciphertext
`vault:v<N>:...` form, and that v0002 OpenAPI field names and patterns
remain unchanged (`SecretVersion.key_id` is a string matching
`^[A-Za-z0-9][A-Za-z0-9._:-]*$`, `key_version` is an integer
`>= 1`).

## Preconditions

- A `team-a` task is claimed; the State Registry is configured with
  the documented Transit configuration; a freshly issued Transit key
  has produced exactly one ciphertext under that key for a single
  prior test write.
- The ActiveProvider response carried a Transit ciphertext whose
  embedded key version parses to `3` under the deployment-configured
  `version_template` (the deployment defaulted to the documented
  `vault:v<N>:...` shape), because the operator pre-ran two rotate
  operations so the canonical Transit key now has three key
  versions; new writes that do not specify `key_version` use the
  latest permitted version the deployment allows.

## Steps

1. Through trusted API Gateway context for `team-a`, store a secret
   under a team-wide environment.
2. Read the canonical `SecretVersion` for the new row through
   trusted API Gateway context.
3. Inspect, in process memory, the embedded key version in the row's
   persisted ciphertext under the deployment-configured
   `version_template` parser; do not leak either to a log or audit
   entry.

## Expected outcome

- `SecretVersion.key_id` is a non-empty string that matches
  `^[A-Za-z0-9][A-Za-z0-9._:-]*$` and is at most 64 characters; the
  value is opaque to the operator and the State Registry's internal
  lookup resolves it to the deployment-time `(mount_path,
  key_name)` pair without exposing `key_name` to any response,
  audit, or log.
- `SecretVersion.key_version` is the integer `3` and matches the
  embedded key version of the row's persisted ciphertext.
- The persisted row carries `crypto_provider = 'transit'` and an
  opaque ciphertext whose embedded version matches `key_version`;
  the Transit ciphertext form is internal-only and does not appear
  in the public response, the audit entry, or the application log.
- The persisted `key_id` and `key_version` match the canonical
  record on every reread; restart, re-read, or any unrelated write
  leaves them unchanged.
