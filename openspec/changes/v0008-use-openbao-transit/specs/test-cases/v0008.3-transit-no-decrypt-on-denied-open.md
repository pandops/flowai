# Test case: v0008.3-transit-no-decrypt-on-denied-open

## Implements

`state-registry` — `### Requirement: State Registry pins the non-revealing 404 shape to every provider failure class`.

`state-registry` — `### Requirement: State Registry opens environments only for assigned same-team Executors`.

## Intent

Verify that every invalid or unavailable open-environment request
returns the v0002 single non-revealing `404
environment_unknown_or_unavailable` shape with zero Transit decrypt
operations and zero Transit error disclosure in logs, audit, or
response bodies; the canonical authorization order remains mTLS,
trusted API Gateway identity / Executor identity, scope-token envelope
(MAC under allow-listed HS algorithms, `kid == key_id`, `audience`,
`issued_at` / `expiry`, every canonical claim), same-team assignment,
and non-terminal task state — and every denial happens before the
active provider is called.

## Preconditions

A `team-a` task is claimed by authenticated `team-a` Executor
`executor-1`; a same-team environment and a Transit-encrypted secret
exist; a Transit-call counter is observable in the test harness.

## Steps

1. Send a request without a token, with an empty token, with a
   malformed token, and with a token missing any required claim.
2. Send a token whose `team_id`, `project_id`, `task_id`,
   `environment_id`, `executor_id`, or `audience` claim differs from
   canonical records.
3. Send a token whose MAC has been tampered with after signing.
4. Send a token whose protected header `alg` is outside the
   allow-listed `HS256`/`HS384`/`HS512` HMAC set, whose `kid`
   differs from the payload `key_id`, or whose `key_id` falls outside
   the documented active key window.
5. Send a token whose `expiry` is more than five minutes after
   `issued_at`, whose `expiry` is not strictly later than `issued_at`,
   or whose `issued_at` is in the future beyond
   `server_now + 30 seconds`.
6. Send a token under a different Executor identity whose
   otherwise-valid same-team claims would pass canonical checks.
7. Replay an unused but still-valid token for a task that has reached
   terminal state.
8. Observe the Transit-call counter and the application log and
   audit entries for every call.

## Expected outcome

Every invalid or unavailable open attempt (steps 1 through 7) returns
the same non-revealing `404 environment_unknown_or_unavailable`
response shape; the Transit-call counter records zero Transit
`POST /v1/<mount>/decrypt/<key_name>` operations for any invalid case;
the application log, audit entries, and error responses contain no
plaintext, no ciphertext byte, no nonce byte, no tag byte, no
`associated_data` value, no Transit token, no Transit endpoint or
namespace, no Transit mount path or `key_name`, no raw Transit error
body, and no Transit ciphertext form. The response shape and code
are identical across every invalid case so the endpoint cannot be
used as a validation oracle. A separately issued valid token in a
later step (covered by `v0008.1`) executes exactly one provider
decrypt operation only after every canonical authorization check
passes.
