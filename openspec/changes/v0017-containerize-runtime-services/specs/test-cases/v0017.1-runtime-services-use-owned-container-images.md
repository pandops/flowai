# v0017.1 — Runtime services use service-owned container images

## Contract

State Registry, Docker OpenHands Executor, and K8s OpenHands Executor build
and run from production container definitions owned by their service
directories. A host binary or in-process server cannot stand in for a real
service during integration or cross-service E2E execution.

## Steps

1. Build all three service images from their service-owned build definitions.
2. Start PostgreSQL and the State Registry image.
3. Start the Docker Executor image with the selected runtime socket.
4. Load and deploy the K8s Executor image as a Pod.
5. Execute one task with each concrete Executor.
6. Assert lifecycle results through State Registry public APIs.
7. Record each running image identity and assert no corresponding host service
   process or in-process server supplied the tested endpoint.

## Expected result

- Every real service is backed by its expected image.
- Both concrete Executors complete a task through the containerized State
  Registry.
- Substituting any real service with a host process fails the test.

## Implementation reference

Not implemented. This definition remains change-local until implementation
starts.
