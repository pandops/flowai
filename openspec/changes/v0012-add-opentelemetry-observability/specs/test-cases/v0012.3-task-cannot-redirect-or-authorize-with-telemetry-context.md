# Test case: v0012.3-task-cannot-redirect-or-authorize-with-telemetry-context

## Implements

`platform-observability` — `### Requirement: FlowAI propagates trace context without treating it as authority`.

`platform-observability` — `### Requirement: Concrete Executors configure agent telemetry from trusted platform state`.

## Intent

Verify the security failure path for forged baggage and task-controlled
telemetry destinations.

## Preconditions

- The E2E stack has trusted Collector A and an inspectable attacker-controlled
  endpoint B.
- A `team-a` task environment contains every supported `OTEL_*`, OpenHands
  telemetry alias, and `LMNR_*` redirection setting targeting B.
- The caller can send baggage claiming `team-b` and a foreign Executor.

## Steps

1. Submit and execute the `team-a` task while sending the forged baggage.
2. Inspect the created OpenHands container environment through the E2E runtime
   harness without exposing secret values in test output.
3. Inspect Collector A, endpoint B, and the canonical task result.

## Expected outcome

Authorization remains bound to the authenticated `team-a` identities; the
runtime contains only trusted platform telemetry settings; Collector A receives
the allowed spans; endpoint B receives no telemetry connection or payload; and
the task cannot observe backend credentials from a team-owned environment.
