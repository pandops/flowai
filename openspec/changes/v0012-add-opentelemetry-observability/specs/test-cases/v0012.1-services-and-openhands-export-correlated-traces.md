# Test case: v0012.1-services-and-openhands-export-correlated-traces

## Implements

`platform-observability` — `### Requirement: Platform workloads export telemetry through a platform-owned OpenTelemetry Collector`.

`platform-observability` — `### Requirement: FlowAI propagates trace context without treating it as authority`.

`platform-observability` — `### Requirement: Concrete Executors configure agent telemetry from trusted platform state`.

## Intent

Verify the happy path in which one real task produces service and OpenHands
spans through the same test Collector with synchronous W3C correlation and
stable cross-trace identifiers.

## Preconditions

- State Registry, `executor_docker_openhands`, PostgreSQL, the pinned OpenHands
  image, and an E2E Collector with an inspectable test exporter are running.
- Telemetry is enabled with HTTP/protobuf OTLP and deterministic always-on E2E
  sampling.
- A team, source system, task type, Executor, and executable task are registered.

## Steps

1. Submit the task through the supported listener API with a known valid
   `traceparent`.
2. Allow the Executor to claim and finish the task through the normal public
   State Registry and OpenHands surfaces.
3. Query the E2E Collector's supported inspection surface for spans carrying
   the returned task identifier.

## Expected outcome

The canonical task reaches `finished`; the Collector contains spans whose
resources identify State Registry, `executor_docker_openhands`, and
`openhands-agent-server`; synchronous Executor/Registry client and server spans
share valid parentage; OpenHands includes conversation, agent-step, LLM, or tool
spans; and the execution and OpenHands spans are correlated by the canonical
task, command, Executor, and conversation identifiers even if OpenHands uses a
separate root. No workload exports directly to the test storage backend.
