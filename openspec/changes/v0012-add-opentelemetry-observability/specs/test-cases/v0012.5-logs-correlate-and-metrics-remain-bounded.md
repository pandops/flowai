# Test case: v0012.5-logs-correlate-and-metrics-remain-bounded

## Implements

`platform-observability` — `### Requirement: Logs and metrics correlate safely with traces`.

## Intent

Verify correlated structured logs and bounded metric cardinality across many
tenant and task identifiers.

## Preconditions

- The instrumented E2E stack exposes its supported metrics inspection surface
  and captures JSON service logs.
- At least two teams, multiple tasks, and multiple Executor identities are
  available while using the same normalized operations.

## Steps

1. Execute the same successful and failing operations across the distinct
   teams, tasks, conversations, requests, and Executors.
2. Select a sampled request span and its corresponding JSON log entry.
3. Scrape metrics and enumerate every series and label value produced by those
   operations.

## Expected outcome

The selected log carries the exact valid `trace_id` and `span_id` of its active
span; logs outside a valid span do not invent identifiers; metric series use
only documented bounded labels; and no task, command, conversation, Executor,
operator, source, project, environment, secret, request, or team identifier or
name occurs as a metric label value.
