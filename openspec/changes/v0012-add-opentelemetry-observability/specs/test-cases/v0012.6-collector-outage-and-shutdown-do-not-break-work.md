# Test case: v0012.6-collector-outage-and-shutdown-do-not-break-work

## Implements

`platform-observability` — `### Requirement: Platform workloads export telemetry through a platform-owned OpenTelemetry Collector`.

`platform-observability` — `### Requirement: Every service owns telemetry lifecycle and implementation`.

## Intent

Verify degraded operation and bounded shutdown when the telemetry destination is
unavailable.

## Preconditions

- State Registry and the Executor are configured with a short telemetry flush
  deadline and a Collector endpoint that can be stopped.
- A task can be submitted, claimed, and completed while the Collector is down.

## Steps

1. Stop the Collector and execute a task through the normal external APIs.
2. Call both services' readiness endpoints during export failure.
3. Send graceful shutdown to the Executor and State Registry and measure exit
   time while capturing sanitized operational logs.

## Expected outcome

The task reaches its expected terminal state; both services preserve their
business readiness semantics; neither API response nor durable row changes
because export failed; shutdown stops new work, attempts flush, and exits within
the configured deadline; and operational logs contain no endpoint credentials,
headers, task content, or raw exporter response body.
