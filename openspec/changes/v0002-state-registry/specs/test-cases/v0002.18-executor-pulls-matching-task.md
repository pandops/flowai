# Test case: v0002.18-executor-pulls-matching-task

## Implements

`executor` — `### Requirement: Docker Executor discovers and requests approval for same-team matching tasks`.

## Intent

Verify the Docker Executor starts only an exact-tag `created` task after explicit State Registry approval.

## Preconditions

A `team-a` `created` task has tag `openhands`, another `team-a` task has tag `k8s`, and the Docker Executor identity is bound to `team-a`, registered with exactly `openhands`, and has a local slot.

## Steps

1. Start discovery and observe the Executor request only its authenticated team and exact registered tag.
2. Observe it choose the same-team matching `task_id` and request approval.
3. After `200 approved`, capture the ordered `running` event before container startup.
4. Read both tasks and the approved task's event history through trusted Gateway context for `team-a`.

## Expected outcome

Discovery returns only the same-team `openhands` task; approval succeeds; the Executor's `running` event has non-null assigned `executor_id`, `team_id = team-a` that State Registry verifies against the authenticated Executor team, and returns `202 accepted`; one container starts; the approved task projects through `[created, dispatched, running]`; and the `k8s` task remains `created` and unassigned.
