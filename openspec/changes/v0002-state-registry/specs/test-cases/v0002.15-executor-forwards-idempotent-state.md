# Test case: v0002.15-executor-forwards-idempotent-state

## Implements

`executor` — `### Requirement: Docker Executor forwards state to the State Registry`.

## Intent

Verify task and Executor event forwarding uses complete envelopes and stable scoped identifiers across retries.

## Preconditions

The Docker Executor is bound to `team-a` and owns a `team-a` `running` task whose local OpenHands runtime can complete successfully.

## Steps

1. Complete the runtime and capture the `finished` event posted to `POST /v1/tasks/{task_id}/events` with non-null `executor_id`, `team_id = team-a`, stable `event_id`, `event_type`, `occurred_at`, and `payload`.
2. Capture the resulting idle self event posted to `POST /v1/executors/{executor_id}/events` with non-null `executor_id`, `team_id = team-a`, and its own scoped `event_id`.
3. Simulate an ambiguous response and observe the Executor retry one event unchanged.
4. Verify no request contains `accepted_sequence`, then read task and Executor state and histories through trusted Gateway context for `team-a`.

## Expected outcome

State Registry verifies `team_id = team-a` against the authenticated Executor team on every event write. The original and retried posts return the same `202 accepted` result; each scoped `event_id` appears exactly once in its team-owned stream; ordering follows strictly increasing `(occurred_at, event_id)` tuples; no `accepted_sequence` is sent or accepted; the task projects to `finished`; and the local capacity slot is free.
