# Test case: v0002.22-stale-approval-returns-conflict

## Implements

`state-registry` — `### Requirement: State Registry approves task start atomically within a team`.

## Intent

Verify an Executor cannot start a task dispatched to another Executor from a stale discovery result.

## Preconditions

Two `team-a` Executors with the same single tag discovered one `team-a` `created` task; the first received `200 approved`, and the second retains the stale `task_id`.

## Steps

1. Request approval for the same `task_id` from the second same-team Executor.
2. Read the canonical task and history through trusted Gateway context for `team-a`.
3. Observe whether the second Executor posts `running` or starts a runtime.

## Expected outcome

The second request returns `409 task_already_dispatched`; the task remains in `team-a`, `dispatched`, and assigned immutably to the first Executor; history remains exactly `[created, dispatched]`; and the second Executor starts no runtime and appends no event.
