# Test case: v0002.20-service-transport-is-mutually-authenticated

## Implements

`state-registry` — `### Requirement: State Registry uses mutually authenticated encrypted transport`.

## Intent

Verify protected APIs reject untrusted transport identities before request processing.

## Preconditions

State Registry trusts listener, Executor, and API Gateway client certificates whose identities are bound to service role and authorized team context; PostgreSQL and OpenBao server identities are configured for verification.

## Steps

1. Call protected HTTP and WebSocket APIs with each trusted service identity and its authorized team context.
2. Repeat without a client certificate, with an expired certificate, with the wrong service-role certificate, and with a credential not authorized for the submitted team.
3. Exercise encrypted PostgreSQL and OpenBao connections with valid and invalid server certificate chains.

## Expected outcome

Trusted identities reach team authorization checks over encrypted transport; every untrusted, expired, wrong-role, or wrong-team connection fails before protected request data is read or changed; and State Registry rejects PostgreSQL or OpenBao server identity and chain failures.
