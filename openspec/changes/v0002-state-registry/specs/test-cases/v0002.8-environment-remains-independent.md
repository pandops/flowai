# Test case: v0002.8-environment-remains-independent

## Implements

`state-registry` — `### Requirement: State Registry remains independent from execution and identity management`.

## Intent

Verify that consolidated environment ownership does not make State Registry an execution service or expose plaintext to unauthorized actors.

## Preconditions

A `team-a` `created` task references a same-team environment, and an eligible Executor bound to `team-a` is registered with the task's exact required tag.

## Steps

1. Receive `200 approved` for the same-team task from State Registry.
2. Read the approved task through trusted Gateway context for `team-a` and inspect the approval response as the assigned Executor.
3. Observe State Registry outbound calls during approval.

## Expected outcome

The approval returns only an environment identifier and a signed team-bound scope token containing `team_id`, `project_id` (required claim; null only when the canonical environment has no project scope), `task_id`, `environment_id`, `executor_id`, `audience` (literal `state-registry.environment.open`), `key_id`, `issued_at`, and `expiry`; the Gateway task read returns `200` without plaintext values; State Registry makes no runtime-control call; and project/task scope narrows use only inside `team-a`.
