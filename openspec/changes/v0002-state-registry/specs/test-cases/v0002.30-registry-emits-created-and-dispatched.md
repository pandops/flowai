# Test case: v0002.30-registry-emits-created-and-dispatched

## Implements

`state-registry` — `### Requirement: State Registry emits registry-owned lifecycle events`.

## Intent

Verify the `created` and `dispatched` events are registry-owned, carry no assigned Executor, and project state in the same transaction that persists the canonical task.

## Preconditions

State Registry and PostgreSQL are running; a listener and Executor are each bound to `team-a`; the Executor has tag `openhands`; no task exists for `(team-a, jira, JIRA-300)`; trusted Gateway context for `team-a` can read tasks and events.

## Steps

1. Submit a task with `team_id = team-a`, `source = jira`, `source_task_id = JIRA-300`, `required_tag = openhands`, and payload.
2. Read task and history immediately after ingestion.
3. Request approval from the same-team, same-tag Executor.
4. Read task and history immediately after approval.

## Expected outcome

Ingestion atomically persists immutable `team_id = team-a` with one Registry-owned `created` row whose `executor_id = null` and whose team inherits from the task row. Approval atomically sets same-team `tasks.executor_id`, `approved_at`, projected `dispatched`, and one Registry-owned `dispatched` row whose `executor_id = null` and whose team inherits from the task row. History is `[created, dispatched]` ordered by `(occurred_at, event_id)` with no Executor-emitted rows.
