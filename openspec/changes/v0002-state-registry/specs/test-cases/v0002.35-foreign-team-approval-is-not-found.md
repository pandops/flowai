# Test case: v0002.35-foreign-team-approval-is-not-found

## Implements

`state-registry` — `### Requirement: State Registry approves task start atomically within a team`.

`state-registry` — `### Requirement: State Registry returns non-revealing not-found for foreign resources`.

## Intent

Verify the approval failure path treats a foreign task identifier as unknown and performs no dispatch mutation.

## Preconditions

A `team-b` task is `created` with tag `openhands`; a `team-a` Executor is registered with that tag; a separate nonexistent task identifier is available.

## Steps

1. Request approval for the `team-b` task as the `team-a` Executor.
2. Request approval for the nonexistent identifier using the same identity.
3. Read the `team-b` task and history through trusted Gateway context for `team-b`.

## Expected outcome

Both approval probes return the same non-revealing `404` status and body shape. The foreign task remains `created`, unassigned, and has only its original `created` event; no approval, audit disclosure, or timing-visible ownership signal is produced.
