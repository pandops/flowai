# Test case: v0002.17-executor-remains-non-authoritative

## Implements

`executor` — `### Requirement: Docker Executor uses one immutable team identity`.
`executor` — `### Requirement: Docker Executor remains local and non-authoritative`.

## Intent

Verify the Executor uses one immutable `team_id` binding throughout its process lifetime, rejects mismatched team data and `team_name`-based authorization, and still retains no durable canonical state or plaintext secret.

## Preconditions

A Docker Executor is bound to immutable `team_id = team-a` and receives same-team approval for a `team-a` task with a team-bound scoped environment.

## Steps

1. Run the same-team task to completion.
2. Restart the Executor and observe that its service identity remains bound to `team_id = team-a`.
3. Attempt to inject a State Registry response, scope token, or control whose `team_id` differs from `team-a`; observe the Executor rejects each locally without starting a runtime or injecting environment values.
4. Attempt to inject a `team_name = team-b` field while keeping `team_id = team-a`; observe the Executor does not treat it as authorization.
5. Inspect local durable storage and read `team-a` State Registry records through the trusted Gateway path.

## Expected outcome

The Executor accepts only data whose `team_id` matches its authenticated immutable team binding; it rejects foreign-team responses, foreign-team scope tokens, and any payload relying on `team_name` for authority without starting a runtime or injecting plaintext. Canonical team ownership, task, assignment, events, environment metadata, and secret versions remain only in State Registry; the Executor retains no durable canonical state or plaintext secret, never authorizes teams, and never changes `team_id` across restart.
