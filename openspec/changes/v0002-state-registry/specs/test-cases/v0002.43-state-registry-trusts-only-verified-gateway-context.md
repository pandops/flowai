# Test case: v0002.43-state-registry-trusts-only-verified-gateway-context

## Implements

`state-registry` — `### Requirement: State Registry requires trusted team-scoped API Gateway context`.

`state-registry` — `### Requirement: State Registry enforces team-bound service identities`.

## Intent

Verify operator surfaces trust only the authenticated Gateway service identity plus its verified one-team context.

## Preconditions

A trusted Gateway identity can forward verified `operator_id`, immutable `team_id = team-a`, and `request_id`; the optional display-only `team_name` is forwarded only when the verified operator team carries one; an untrusted direct client can copy arbitrary headers and payload fields.

## Steps

1. Through trusted Gateway identity, perform an authorized task read, subscription, control, environment write, and secret write using the verified context.
2. Repeat each call directly without the Gateway credential while copying all context fields.
3. Through the trusted Gateway identity, submit a context whose canonical operator team check failed or whose context represents more than one team.
4. Read `team-a` resources and audits through a valid trusted context.

## Expected outcome

Valid Gateway-mediated requests are authorized solely by immutable `team_id` and audited with `operator_id` and `request_id`. Direct copied headers and invalid or multi-team contexts are rejected without reading or changing tenant data; unauthenticated payload fields never broaden access.
