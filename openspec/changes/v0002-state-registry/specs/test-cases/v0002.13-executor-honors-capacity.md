# Test case: v0002.13-executor-honors-capacity

## Implements

`executor` — `### Requirement: Docker Executor runs bounded OpenHands containers`.

## Intent

Verify the Executor locally limits approvals and running containers without relying on State Registry capacity gating.

## Preconditions

Three `team-a` `created` tasks have required tag `openhands`; the Docker Executor identity is bound to `team-a`, configured for exactly one tag, `openhands`, and local capacity of two containers.

## Steps

1. Start the Executor and observe same-team, exact-tag discovery and approval HTTP calls while no containers are running.
2. Observe the Executor's `running` event posts and Docker containers while two tasks are active.
3. Complete one runtime and observe its terminal event, the freed local slot, and the next discovery and approval request.
4. Read the three canonical task views and event histories through trusted Gateway context for `team-a`.

## Expected outcome

Before a slot is freed, exactly two same-team approvals return `200 approved`, exactly two containers run, and the third task remains `created` with `executor_id = null`; the Executor makes no third approval request while locally full. Every Executor event envelope contains `task_id`, `executor_id`, `team_id = team-a`, `event_id`, `event_type`, `occurred_at`, and `payload`; State Registry verifies the submitted `team_id` against the authenticated Executor team for every write. After one terminal event frees a slot, the third approval succeeds, and no more than two task containers run concurrently; State Registry never gates on capacity or returns a capacity rejection.
