# Test case: v0002.12-service-identity-is-enforced

## Implements

`state-registry` — `### Requirement: State Registry enforces team-bound service identities`.

## Intent

Verify listener, Executor, gateway, and assignment authorization at every protected State Registry surface.

## Preconditions

Listener and Executor identities are each bound to exactly one immutable team; trusted API Gateway context contains one verified `operator_id`, `team_id`, display-only `team_name`, and `request_id`; two same-team Executors and a task assigned to the first Executor exist.

## Steps

1. Attempt listener ingestion using another source identity or a `team_id` outside the listener binding.
2. Attempt approvals, task-event writes (with and without matching envelope `team_id`), control reads, and environment opens using an unassigned or foreign-team Executor.
3. Attempt Gateway-only reads, subscriptions, controls, environment writes, and secret writes without the trusted Gateway identity or with caller-selected tenant headers.

## Expected outcome

Every impersonating, foreign-team, unassigned, or untrusted-Gateway request is rejected without revealing or changing protected state; point probes of foreign identifiers are indistinguishable from unknown identifiers; task and self event writes whose envelope `team_id` does not match the authenticated Executor team are rejected with `403 team_mismatch`; and correctly authenticated one-team requests remain authorized solely by canonical `team_id`.
