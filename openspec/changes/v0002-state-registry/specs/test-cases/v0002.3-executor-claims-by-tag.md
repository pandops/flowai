# Test case: v0002.3-executor-claims-by-tag

## Implements

`state-registry` — `### Requirement: State Registry lists created tasks by team and required tag`.

## Intent

Verify exact-tag discovery returns only matching `created` tasks without reserving or assigning them.

## Preconditions

Two `team-a` `created` tasks exist with the single required tags `openhands` and `k8s`; an Executor identity bound to `team-a` is registered with exactly one tag, `openhands`.

## Steps

1. Request `GET /v1/executors/{executor_id}/tasks?tag=openhands` as the registered `team-a` Executor.
2. Request `GET /v1/executors/{executor_id}/tasks?tag=k8s` as the same Executor.
3. Read both canonical task views through trusted API Gateway context for `team-a`.

## Expected outcome

The matching discovery returns `200` with only the same-team `openhands` task; the unregistered-tag request is rejected without revealing tasks; both task reads return `200` with immutable `team_id = team-a`, `current_state = created`, and `executor_id = null`; and discovery changes neither state nor assignment.
