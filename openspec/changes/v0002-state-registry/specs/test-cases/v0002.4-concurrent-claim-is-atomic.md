# Test case: v0002.4-concurrent-claim-is-atomic

## Implements

`state-registry` — `### Requirement: State Registry approves task start atomically within a team`.

## Intent

Verify that concurrent eligible Executors cannot dispatch one task twice.

## Preconditions

One `team-a` `created` task has required tag `openhands`; two Executors are each bound to `team-a`, registered with exactly the tag `openhands`, and can discover the task.

## Steps

1. Request same-team discovery from both Executors and retain the same returned `task_id`.
2. Send concurrent `POST /v1/executors/{executor_id}/approvals` requests for that `task_id`.
3. Read discovery, the canonical task, and its event history through trusted Gateway context for `team-a`.

## Expected outcome

Exactly one approval returns `200 approved` and the other returns `409 task_already_dispatched`; the task remains owned by `team-a` and has exactly one immutable same-team `executor_id`; discovery no longer returns the task; and the ordered event types are exactly `[created, dispatched]` with one `dispatched` event whose `executor_id` is `null`.
