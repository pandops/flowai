# Test case: v0002.32-persistence-survives-restart

## Implements

`state-registry` — `### Requirement: State Registry persists team ownership in normalized 3NF PostgreSQL`.

## Intent

Verify durable team-owned State Registry state survives restart with immutable ownership, team-scoped deduplication, assignment, ordered events, Executor observations, environments, logical secrets and versions, controls, and audit entries. Exact 3NF structure remains an integration-level migration assertion.

## Preconditions

State Registry and PostgreSQL are running; listener, two Executors, and trusted Gateway context are authorized for `team-a`; Executors each register `team_id = team-a` and tag `openhands`; a `team-a` environment, logical secret, and encrypted secret version exist; no task exists for `(team-a, jira, JIRA-310)`.

## Steps

1. Submit and approve a `team-a` task; append valid ordered `running` and `failed` task events from assigned `executor-1` carrying `executor_id = executor-1`, `team_id = team-a` (verified by State Registry against the authenticated Executor team), and the standard envelope fields; append one self event with non-null `executor_id` and `team_id = team-a`; create a team-scoped cancel control; and read its audit entry.
2. Restart State Registry while preserving PostgreSQL.
3. Resend the original `(team-a, jira, JIRA-310)` listener submission.
4. Read the task, task events, Executor and self events, environment, secret and version metadata, control, and audit entry through trusted Gateway context for `team-a`.

## Expected outcome

The retry returns the existing team-owned task without another `created` event. Every resource retains immutable `team_id = team-a`; `tasks.executor_id` remains assigned; task history remains strictly ordered with the Registry-owned `created` and `dispatched` rows carrying `executor_id = null` and inherited team ownership while the Executor-owned rows preserve their submitted `team_id`, non-null assigned `executor_id`, and other fields; `executor_events.executor_id` remains non-null with `team_id = team-a`; environment and logical `secrets`/`secret_versions` relationships survive; and control and audit records remain team-scoped and plaintext-free.
