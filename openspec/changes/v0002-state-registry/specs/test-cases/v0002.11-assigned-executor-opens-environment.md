# Test case: v0002.11-assigned-executor-opens-environment

## Implements

`state-registry` — `### Requirement: State Registry opens environments only for assigned same-team Executors`.

## Intent

Verify successful scoped decryption and rejection of invalid or unassigned requests.

## Preconditions

A `team-a` task is assigned to `team-a` Executor `executor-1` and references a same-team environment with non-secret values and an encrypted secret; approval returned a signed scope token containing `team_id`, `project_id` (required claim; null only when the canonical environment has no project scope), `task_id`, `environment_id`, `executor_id`, `audience` (literal `state-registry.environment.open`), `key_id`, `issued_at`, and `expiry`.

## Steps

1. Open the environment as `executor-1` with a valid token whose signature and every claim match canonical records.
2. Repeat as another Executor and with a foreign-team Executor identity.
3. Repeat with invalid signature, algorithm outside the allow-listed `HS256`/`HS384`/`HS512` HMAC set, protected-header `kid` that does not equal the payload `key_id`, audience, premature-beyond-skew `issued_at`, `expiry` not strictly later than `issued_at`, `expiry` more than five minutes after `issued_at`, team, project, task, environment, executor, and assignment bindings.

## Expected outcome

Only the assigned same-team Executor with every valid claim receives env-style values and a plaintext-free team audit entry; every other request returns no values and triggers no OpenBao decryption; foreign identifiers use the non-revealing `404` shape where a point resource is probed.
