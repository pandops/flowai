# Test case: v0002.29-assignment-ownership-survives-restart

## Implements

`state-registry` — `### Requirement: State Registry normalizes team-owned entity relationships`.

## Intent

Verify the assigned Executor remains immutable and is the only accepted event owner before and after a State Registry restart.

## Preconditions

One `team-a` `created` task has tag `openhands`; `executor-1` and `executor-2` are each bound to `team-a` and registered with that tag; trusted Gateway context for `team-a` can read task and event state.

## Steps

1. Approve the task as `executor-1`.
2. Attempt `running` as unassigned same-team `executor-2`, carrying `team_id = team-a`.
3. Post valid `running` as assigned `executor-1` carrying `team_id = team-a`.
4. Restart State Registry while preserving PostgreSQL.
5. Retry approval and a task event as `executor-2`, supplying `team_id = team-a`.
6. Read task and history as `team-a`.

## Expected outcome

State Registry verifies `team_id = team-a` against the authenticated Executor team on every event write; the wrong-owner writers are rejected with `403 not_assigned`. The wrong-owner `team_id = team-a` event is rejected because it does not match `tasks.executor_id`; the assigned-owner `running` succeeds; post-restart re-approval returns `409 task_already_dispatched`; the task retains immutable `team_id = team-a` and `executor_id = executor-1`; history is exactly `[created, dispatched, running]`; and every Executor-emitted row has non-null assigned `executor_id` with submitted `team_id` equal to the task team.
