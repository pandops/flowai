# Test case: v0002.21-approval-hides-task-from-discovery

## Implements

`state-registry` — `### Requirement: State Registry approves task start atomically within a team`.

## Intent

Verify successful approval dispatches a `created` task and immediately removes it from common discovery.

## Preconditions

A `team-a` `created` task has required tag `openhands`, and two Executors are each bound to `team-a` and registered with exactly that tag.

## Steps

1. Discover the task by exact equality with authenticated `team_id = team-a` and tag `openhands`.
2. Request approval from the first same-team Executor.
3. Repeat discovery from both eligible same-team Executors.
4. Read the canonical task and history through trusted Gateway context for `team-a`.

## Expected outcome

Approval returns `200 approved`; both subsequent discovery requests return `204` or an empty same-team collection without the task; the task stays owned by `team-a`, projects to `dispatched`, and has the first Executor as sole immutable `executor_id`; and `[created, dispatched]` contains one registry-emitted `dispatched` row with `executor_id = null`.
