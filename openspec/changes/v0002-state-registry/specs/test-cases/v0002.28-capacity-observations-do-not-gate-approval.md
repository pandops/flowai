# Test case: v0002.28-capacity-observations-do-not-gate-approval

## Implements

`state-registry` — `### Requirement: State Registry observes Executor capacity without gating discovery or approval`.

## Intent

Verify the Registry treats saturated capacity values as observations and still discovers and approves an otherwise eligible task.

## Preconditions

A `team-a` `created` task has tag `openhands`; `executor-1` is bound to `team-a`, registered with that one tag, and observed at `max_capacity = running_count = 1`.

## Steps

1. Read `executor-1` through trusted Gateway context for `team-a`.
2. Discover same-team tasks by exact registered tag.
3. Request approval for the discovered `task_id`.
4. Read task and history through the same Gateway team context.

## Expected outcome

The stored observations remain informational; discovery returns the same-team matching task; approval returns `200 approved` and never any capacity-related rejection; the task projects to `dispatched` with same-team `executor-1`; and history is exactly `[created, dispatched]`.
