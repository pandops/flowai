# Test case: v0002.25-invalid-transition-rejected

## Implements

`state-registry` — `### Requirement: State Registry rejects invalid or out-of-order lifecycle transitions`.

## Intent

Verify a terminal-to-terminal transition is rejected without appending an event or changing the current-state projection.

## Preconditions

A `team-a` task is assigned to authenticated same-team Executor `executor-1`, projects to `finished`, and has exactly `[created, dispatched, running, finished]` ordered by `(occurred_at, event_id)`.

## Steps

1. Retain the projected state and event identifiers.
2. Post a fresh terminal event after `finished` carrying the same `team_id = team-a` as the authenticated Executor team.
3. Post a fresh event whose `(occurred_at, event_id)` is older than or equal to the latest accepted tuple, once without and once with caller-supplied `accepted_sequence`.
4. Post a fresh event whose submitted `team_id` does not equal the authenticated Executor team.
5. Read the task and history through trusted Gateway context for `team-a`.

## Expected outcome

The terminal-after-terminal request returns `409 invalid_task_transition`; both out-of-order requests are rejected; `accepted_sequence` is not accepted as a recovery override; the cross-team request is rejected with `403 team_mismatch` because the submitted `team_id` does not match the authenticated Executor team. Projected state, immutable assignment, and ordered history remain unchanged; and none of the fresh event identifiers is appended.
