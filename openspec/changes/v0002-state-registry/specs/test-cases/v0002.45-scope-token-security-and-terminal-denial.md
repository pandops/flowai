# Test case: v0002.45-scope-token-security-and-terminal-denial

## Implements

`state-registry` — `### Requirement: State Registry opens environments only for assigned same-team Executors`.

`state-registry` — `### Requirement: State Registry signs open-environment scope tokens with an allow-listed HMAC and a server-controlled rotating key`.

`state-registry` — `### Requirement: State Registry enforces team-bound service identities`.

## Intent

Verify State Registry signs open-environment scope tokens with HMAC-SHA-256 (or a stronger HMAC algorithm) under a server-controlled rotating key identified by `key_id`, presents them only through `GET /v1/environments/{environment_id}/open?task_id={task_id}` with the compact signed token carried in the `X-FlowAI-Scope-Token` header, and rejects every invalid or unavailable open attempt with the same non-revealing `404 environment_unknown_or_unavailable` shape and zero OpenBao calls before any decryption.

## Preconditions

A `team-a` task is assigned to authenticated `team-a` Executor `executor-1` and references an applicable `team-a` environment and encrypted secret; a separate assigned same-team task on `team-a` is already in terminal state; a second `team-a` Executor identity is authenticated; OpenBao Transit is reachable and call counting is observable.

## Steps

1. Obtain a freshly signed open-environment scope token issued by State Registry for `executor-1` carrying non-null `team_id = team-a`, `project_id` (required claim; null only when the canonical environment has no project scope), `task_id`, `environment_id`, `executor_id = executor-1`, expected `audience` (literal `state-registry.environment.open`), `issued_at`, `expiry` strictly later than `issued_at` and no more than five minutes after `issued_at` with `issued_at <= server_now + 30 seconds`, a `key_id` inside the documented active key window that equals the protected-header `kid`, a protected header carrying `alg` (allow-listed `HS256`/`HS384`/`HS512`), `kid`, and `typ` (`scope-token+json`) with `kid == payload key_id`, and an allow-listed HMAC (`HS256`/`HS384`/`HS512`) MAC produced by State Registry.
2. Call `GET /v1/environments/{environment_id}/open?task_id={task_id}` with `executor-1`'s authenticated identity and the compact signed token carried in the `X-FlowAI-Scope-Token` request header; no scope-token fields appear in the body and the query `task_id` equals both the payload `task_id` claim and the canonical assigned task.
3. Send a request without a token, with an empty token, or with a token missing any required claim.
4. Send a token whose `team_id`, `project_id`, `task_id`, `environment_id`, `executor_id`, or `audience` claim differs from canonical records.
5. Send a token whose MAC has been tampered with after signing.
6. Send a token whose protected header `alg` is outside the allow-listed `HS256`/`HS384`/`HS512` HMAC set, a token whose protected-header `kid` differs from the payload `key_id`, or a token whose `key_id` falls outside the documented active key window including a retired key identifier.
7. Send a token whose `expiry` is more than five minutes after `issued_at`, a token whose `expiry` is not strictly later than `issued_at`, and a token whose `issued_at` is in the future beyond the tolerated clock-skew window (`server_now + 30 seconds`).
8. Send a token under a different assigned Executor identity whose otherwise-valid same-team claims would pass canonical checks.
9. Replay an unused but still-valid token for a task that has since reached terminal state.
10. Retransmit the same valid token for the same assigned identity before `expiry`; on each replay, observe whether State Registry decrypts and returns values subject to the full canonical checks.
11. Observe the OpenBao call counter for every call.

## Expected outcome

The valid token (step 2) returns `200` with authorized env-style values in memory only after State Registry first verifies that the protected-header `kid` equals the payload `key_id`, then recomputes the signature under the declared allow-listed HMAC algorithm and compares it under constant-time comparison, then confirms `key_id` is inside the documented active key window, then validates `issued_at <= server_now + 30 seconds` and `expiry > issued_at` and `expiry - issued_at <= 5 minutes` against the expected literal `audience`, then verifies every canonical claim (including that `project_id` is required but nullable only when the canonical environment has no project scope), then confirms the calling authenticated Executor is the currently assigned same-team Executor, and then confirms the referenced task is in a non-terminal state; the response carries no plaintext outside memory, the audit entry records team, actor, action, resource, request, and outcome without token plaintext, claims, key material, or derived key bytes, and exactly one OpenBao decrypt call is observed. Every invalid or unavailable open attempt (steps 3 through 9) returns the same non-revealing `404 environment_unknown_or_unavailable` response shape, performs zero OpenBao calls, and never reveals forbidden algorithm, `kid`/`key_id` mismatch, unknown/retired `key_id`, tampered MAC, expired or premature issuance, `expiry` not strictly later than `issued_at`, exceeded lifetime, audience or canonical-claim mismatch, another identity, terminal task state, or not-assigned status; application logs, audit entries, and error responses contain no token plaintext, individual claim values beyond identifier-level metadata, MAC bytes, key material, or derived key bytes. A same assigned identity retry within TTL (step 10) succeeds only when every check still passes; the retry SHALL NOT bypass canonical claim, transition, or assignment checks, SHALL NOT extend TTL, and SHALL NOT revive an expired token. The uniform `404 environment_unknown_or_unavailable` shape prevents a token-validation oracle across algorithm, `kid`/`key_id` equality, key, MAC, `issued_at`/`expiry` window, audience, claim, identity, terminal, and not-assigned failure modes.
