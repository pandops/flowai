# Test case: v0002.33-cross-team-deduplication-is-independent

## Implements

`state-registry` — `### Requirement: State Registry deduplicates listener tasks within a team`.

## Intent

Verify the cross-team edge case where identical external source identities create independent canonical tasks because `team_id` is part of the deduplication key.

## Preconditions

Listener identities are separately bound to `team-a` and `team-b`; neither team has a task for `(jira, SHARED-33)`.

## Steps

1. Submit `(team-a, jira, SHARED-33)` through the `team-a` listener identity.
2. Submit `(team-b, jira, SHARED-33)` through the `team-b` listener identity.
3. Retry both submissions unchanged.
4. Read each returned task and history through trusted Gateway context for its owning team.

## Expected outcome

The first submissions return different canonical `task_id` values with immutable owning teams and one `created` event each. Each retry returns its own team's existing task without a duplicate event; neither response or read crosses team ownership.
