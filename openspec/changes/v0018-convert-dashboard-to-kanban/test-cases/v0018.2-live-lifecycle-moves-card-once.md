# Test case: v0018.2-live-lifecycle-moves-card-once

## Implements

- `web-ui`: `Web UI renders an actionable task dashboard`

## Intent

Prove through real container service boundaries that committed lifecycle
events move one task card and its counts exactly once without a reload.

## Preconditions

- Required service images are built from the current source before the suite.
- The test starts fresh State Registry, Web UI/Gateway-path, and required
  dependency containers and addresses them only through published container
  ports.
- A selected-team pending task exists and the board subscription is active.

## Steps

1. Record the pending and created counts and locate the pending task card.
2. Cause the authorized platform path to claim the task so State Registry
   commits its canonical `created` state.
3. Observe the board without reloading.
4. Deliver or observe a replay of the already-applied stream frame.
5. Inspect network requests made by the board interaction.

## Expected outcome

- The card leaves `pending` and appears once in `created`.
- Pending decreases once and created increases once.
- Replaying the frame changes neither card multiplicity nor counts.
- The card still links to the same immutable task detail.
- The Web UI sends no task lifecycle mutation request.
