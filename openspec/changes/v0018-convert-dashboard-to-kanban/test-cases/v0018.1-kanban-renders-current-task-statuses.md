# Test case: v0018.1-kanban-renders-current-task-statuses

## Implements

- `web-ui`: `Web UI renders an actionable task dashboard`

## Intent

Prove that `/dashboard` is a bounded task Kanban whose cards and counts reflect
canonical selected-team task states and that Statistics is a separate route.

## Preconditions

- The Web UI image is built from the current source before the suite starts.
- The test starts a fresh Web UI container connected to a deterministic
  containerized adapter fixture.
- The selected team has one task in each of `pending`, `created`, `running`,
  `finished`, and `failed`, plus enough finished tasks to require pagination.

## Steps

1. Open `/dashboard` for the selected team.
2. Wait for the initial boundary, status snapshots, and counts to settle.
3. Inspect lifecycle headings, task cards, counts, calendar controls, and the
   first page of the `finished` column.
4. Activate “Load more” in `finished`.
5. Activate one task card.

## Expected outcome

- Exactly five initial lifecycle columns render in canonical order.
- Every seeded task appears exactly once in its `current_state` column.
- Each heading reports the canonical total while the loaded card window stays
  bounded to 25 until progressive loading is requested.
- Loading `finished` does not reset or reorder another column.
- No week/month calendar or launch chart is present on `/dashboard`.
- Separate Dashboard and Statistics navigation items are present.
- The activated card opens the selected-team task detail.
