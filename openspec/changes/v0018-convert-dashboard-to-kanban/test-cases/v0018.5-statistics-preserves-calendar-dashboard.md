# Test case: v0018.5-statistics-preserves-calendar-dashboard

## Implements

- `web-ui`: `Web UI renders an actionable task dashboard`

## Supersedes

- `qa-e2e/test-cases/v0006.16-dashboard-status-drilldown.md`
- `qa-e2e/test-cases/v0006.30-dashboard-counts-new-task-live.md`

## Intent

Prove that the previous dashboard is relocated to Statistics without losing
its calendar, navigation, drill-down, or live-update behavior.

## Preconditions

- The Web UI image is built from current source and runs in a fresh container
  connected to a deterministic containerized adapter fixture.
- The selected team has tasks across the current and previous ISO week and
  calendar month.

## Steps

1. Activate the `Statistics` navigation item.
2. Inspect the route, current week and month views, totals, status counts,
   launch chart, and zero-count daily buckets.
3. Navigate to an earlier week and month, then use browser Back and Forward.
4. Activate one date bucket and inspect the Task History date filter.
5. Return to Statistics, ingest one same-team task, and replay its live frame.

## Expected outcome

- Statistics opens at `/statistics`; Dashboard remains available separately at
  `/dashboard` and renders the Kanban.
- The former dashboard's week/month labels, navigation, complete calendars,
  totals, counts, chart, URL state, and browser-history restoration remain
  unchanged.
- Date activation opens Task History with the exact UTC `date=YYYY-MM-DD`.
- The new task updates the applicable total, pending count, and day bucket once
  without a reload; replay does not double-count it.
- No foreign-team statistics appear.
