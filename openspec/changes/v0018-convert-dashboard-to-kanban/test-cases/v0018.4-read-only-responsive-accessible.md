# Test case: v0018.4-read-only-responsive-accessible

## Implements

- `web-ui`: `Web UI renders an actionable task dashboard`

## Intent

Prove that the live board remains read-only, keyboard-operable, understandable
to assistive technology, and usable on a narrow viewport.

## Preconditions

- The Web UI image is built from current source and runs in a fresh container
  connected to a deterministic containerized adapter fixture.
- The selected team has cards in multiple lifecycle columns.
- The browser emulates a narrow viewport and reduced-motion preference.

## Steps

1. Open `/dashboard` and traverse its controls and cards using only keyboard.
2. Inspect accessible column names/counts and card link names.
3. Navigate horizontally across all lifecycle columns.
4. Inspect the board for drag handles, drop targets, and inline state controls.
5. Cause one canonical live transition while focus remains on the board.

## Expected outcome

- Focus follows deterministic column/card order and every card link is usable.
- Status headings expose both canonical status name and total.
- Every column remains reachable without cards becoming unusably narrow.
- No drag, drop, or inline lifecycle mutation control exists.
- The transition is announced politely, does not steal focus, and requires no
  movement animation under reduced motion.
