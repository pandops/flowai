# Test case: v0006.6-invalid-configuration-rejected

## Implements

`api-gateway` — `### Requirement: Gateway runs configured single-team no-auth proxy mode`

## Intent

Failure-path test verifying fail-closed behavior when the configured bootstrap operator context or configured team context is missing or ambiguous.

## Preconditions

- Gateway can be started with test deployment configuration.
- State Registry records whether it receives a child request or WebSocket subscription.

## Steps

1. Start the Gateway with a missing or empty `operator_id` while `team_id` is valid and attempt a REST request.
2. Start the Gateway with an empty `team_id` while `operator_id` is valid and attempt a WebSocket upgrade.
3. Start the Gateway with multiple candidate operator identities and attempt a REST request.
4. Start the Gateway with valid `operator_id` and `team_id`, omit
   `team_name`, and attempt a REST request.
5. Start the Gateway with valid required identities but an explicitly empty
   `team_name` and attempt a REST request.
6. Inspect State Registry request/subscription observations.

## Expected outcome

Steps 1-3 and 5 are rejected before proxying, and State Registry observes no
child request for those invalid configurations. Step 4 succeeds, State
Registry receives the trusted operator/team/request context without an
`X-FlowAI-Team-Name` header, and the response is forwarded unchanged.
