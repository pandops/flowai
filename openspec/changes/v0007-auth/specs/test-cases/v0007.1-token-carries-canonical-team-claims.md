# Test case: v0007.1-token-carries-canonical-team-claims

## Implements

`auth` — `### Requirement: Gateway resolves Keycloak groups before issuing operator-team bearer tokens`

## Intent

Happy-path test verifying Keycloak group resolution, accessible-team listing, selection, and one-team token issuance.

## Preconditions

- Keycloak maps `operator-1` to canonical groups `group-alpha` and `group-beta`.
- State Registry maps them to `team-alpha` / `Alpha Team` and `team-beta` / `Beta Team`.

## Steps

1. Log in as `operator-1` through API Gateway and Keycloak.
2. Verify the accessible-team response.
3. Select `team-alpha` and inspect the issued working token's verified claims.

## Expected outcome

The Gateway returns both canonical teams in deterministic order. The working token contains canonical `operator_id=operator-1`, exactly one immutable `team_id=team-alpha`, `team_name=Alpha Team`, the API Gateway audience, and a future expiry; it contains no second team or Keycloak group list.
