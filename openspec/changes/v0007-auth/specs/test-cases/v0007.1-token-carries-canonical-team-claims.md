# Test case: v0007.1-token-carries-canonical-team-claims

## Implements

`auth` — `### Requirement: Gateway issues canonical operator-team bearer tokens`

## Intent

Happy-path and ambiguity test verifying canonical operator/team token claims and one-team issuance.

## Preconditions

- Canonical auth state maps operator `operator-1` to exactly one active `team-alpha` with display name `Alpha Team`.
- A second fixture resolves valid credentials to multiple active teams.

## Steps

1. Log in as `operator-1` through API Gateway.
2. Inspect the issued token's verified claims.
3. Attempt login with the ambiguous-team fixture.

## Expected outcome

The first token contains canonical `operator_id=operator-1`, exactly one immutable `team_id=team-alpha`, optional `team_name=Alpha Team`, the API Gateway audience, and a future expiry; the ambiguous login is rejected and issues no token.
