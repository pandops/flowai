# Test case: v0007.17-state-registry-resolves-groups-to-teams

## Implements

`state-registry` — `### Requirement: State Registry resolves Keycloak groups to canonical teams`

## Intent

Happy-path and boundary test verifying deterministic group-to-team resolution and Gateway-only access.

## Preconditions

- Active mappings exist from `group-alpha` to `team-alpha` / `Alpha Team` and `group-beta` to `team-beta` / `Beta Team`.
- An unknown group and a duplicate `group-alpha` are available as inputs.

## Steps

1. Call `POST /v1/auth/team-resolutions` as authenticated API Gateway with duplicate known groups and one unknown group.
2. Repeat the call directly from the browser and from a non-Gateway service identity.
3. Inspect responses and confirm no database mutation occurred.

## Expected outcome

The trusted call returns exactly one entry for each known mapped team ordered by `(team_name ASC, team_id ASC)`; unknown and duplicate groups add no entries. Every untrusted call is rejected before reading rows, and no call mutates state.
