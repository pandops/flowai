# Test case: v0022.6-team-target-reference.md

## Implements

`state-registry` — `### Requirement: State Registry stores safe team-owned LiteLLM target references`.

## Intent

Verify same-team exact aliases can be registered while invalid and foreign references remain non-revealing.

## Preconditions

Two teams, known model/A2A aliases, a disabled alias, safe metadata, a key-provisioner fixture, and OpenBao exist.

## Steps

1. Register known same-team model and A2A aliases through Gateway.
2. Attempt wrong-kind, disabled, unknown, foreign, and local-agent-ID-collision operations.
3. Inject final database failure after virtual-key creation and OpenBao storage.
4. Read the successful records, revoked-key state, inaccessible orphan state, and audit output.

## Expected outcome

Valid records contain canonical IDs and safe metadata only; invalid and foreign cases are non-revealing; colliding agent IDs create no ambiguity; a post-secret failure exposes no active target or credential, revokes its LiteLLM key, and leaves only an inaccessible orphaned immutable secret version plus plaintext-free audit.
