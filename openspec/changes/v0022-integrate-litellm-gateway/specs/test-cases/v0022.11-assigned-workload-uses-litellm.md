# Test case: v0022.11-assigned-workload-uses-litellm.md

## Implements

`executor` — `### Requirement: Assigned agent workloads use the pinned LiteLLM target`.

## Intent

Verify only the assigned workload gets its pinned runtime key and failure never uses a direct provider.

## Preconditions

A claimed task, assigned/unassigned Executors, a key canary, LiteLLM failure fixture, and deny-and-record provider endpoint exist.

## Steps

1. Attempt environment open and launch from the unassigned Executor.
2. Launch through the assigned Executor and inspect its environment, logs, probes, and events.
3. Trigger LiteLLM failure and inspect direct-provider records.

## Expected outcome

Only the assigned workload receives the canary in its process environment; all other outputs redact it; the task fails with a sanitized event and no direct-provider call occurs.
