# Test case: v0005.4-approved-task-runs-as-pod-with-running-then-terminal-events

## Implements

`executor` — `### Requirement: K8s Executor runs only Kubernetes Pods`.

## Intent

Verify the same-team approved task causes the K8s Executor to emit a
`running` event before creating the Kubernetes Pod, creates the Pod with the
canonical FlowAI `task_id`, and emits exactly one terminal `finished` or
`failed` event whose envelope matches the seven-field shape, all scoped to
the Executor's bound `team_id`.

## Preconditions

State Registry and PostgreSQL are running. An authenticated Executor service
identity `k8s-exec-A` bound to `team_id = team-A` is registered with exactly
one `authorized_tag = k8s-cluster-A`, `max_capacity = 1`, and `running_count
= 0`. One `created` task has `team_id = team-A` and `required_tag =
k8s-cluster-A` and references an environment identifier. A Kubernetes API
fake is wired so the test can capture Pod create/wait calls.

## Steps

1. As `k8s-exec-A`, request
   `GET /v1/executors/k8s-exec-A/tasks?tag=k8s-cluster-A` and capture the
   matching `task_id`.
2. As `k8s-exec-A`, request
   `POST /v1/executors/k8s-exec-A/approvals` for that `task_id` and capture
   the response (including the environment reference and team-bound scope
   token).
3. As `k8s-exec-A`, post a `running` event to
   `POST /v1/tasks/{task_id}/events` carrying `task_id`,
   `executor_id = k8s-exec-A`, `team_id = team-A`,
   `event_id = 0190-k8s-running-0001`, `event_type = running`,
   `occurred_at = 2026-07-13T16:00:00Z`, and
   `payload = {"pod_name":"pod-1"}`.
4. Have the K8s Executor create the Kubernetes Pod with the agent runtime
   and observe the Pod create call.
5. Have the K8s Executor emit exactly one terminal event when the Pod
   terminates successfully, posting a `finished` event with the same
   envelope shape (`task_id`, `executor_id`, `team_id = team-A`,
   `event_id = 0190-k8s-finished-0001`, `event_type = finished`,
   `occurred_at = 2026-07-13T16:05:00Z`,
   `payload = {"exit_code":0}`).
6. Read the canonical task and `GET /v1/tasks/{task_id}/events` through
   the API Gateway.

## Expected outcome

Step 1 returns `200` with the matching `task_id`. Step 2 returns
`200 approved` and includes the environment reference and a
team-bound, project-bound, task-bound scope token. Step 3 returns
`202 accepted`. The Kubernetes Pod is created ONLY after the `running`
event post returns `202 accepted`, and the Pod carries a label referencing
the canonical FlowAI `task_id`. Step 5 returns `202 accepted`. The final
task read returns `200` with `current_state = finished` and
`executor_id = k8s-exec-A`; the event read returns exactly four events
ordered `[created, dispatched, running, finished]`. The `running` and
`finished` rows each carry `team_id = team-A`, the seven-field envelope,
and the submitted `event_id`, `occurred_at`, and `payload` values
unchanged. `created` and `dispatched` carry `executor_id = null`.
