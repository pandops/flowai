# Test case: v0005.7-assigned-task-environment-opens-with-team-bound-scope-token

## Implements

`executor` — `### Requirement: K8s Executor opens assigned task environments using a team-bound scope token`.

`executor` — `### Requirement: K8s Executor is scope-aware and provider-neutral`.

## Intent

Verify that the assigned K8s Executor in the bound `team_id` opens an
environment only after the State Registry verifies every v0002-inherited
claim, header, algorithm, timing, and assignment condition; that the
valid request returns env-style values injected solely into the
assigned task's Pod; that a plaintext-free audit entry is recorded;
and that every invalid or unavailable variation returns the same
non-revealing `404 environment_unknown_or_unavailable` shape with
zero provider decrypt operations and no plaintext in any log, audit,
or response. The K8s Executor carries the State Registry-issued scope
token verbatim and never inspects or names the cryptography provider.

## Preconditions

State Registry and PostgreSQL are running. A `pending` task
`task_id_env` has `team_id = team-A`,
`required_tag = k8s-cluster-A`, and references an environment
identifier with one non-secret `KEY=VALUE` entry and one encrypted
secret. An authenticated K8s Executor service identity `k8s-exec-A`
bound to `team_id = team-A` is registered with `scope = team` and
`authorized_tag = k8s-cluster-A`. `k8s-exec-A` issues
`POST /v1/executors/k8s-exec-A/claim` for `task_id_env` and receives
`200 claimed`, with `tasks.owner_command_id`, `tasks.executor_id`,
`tasks.resolved_image`, `tasks.image_source`, and the State
Registry-issued compact scope token carried in the response; the
assigned state of the task is `created`, and `k8s-exec-A` is therefore
the assigned Executor. The State Registry's documented active key
window for the `state-registry.environment.open` audience contains
exactly one active `key_id` (call it `key_active`) and one retired
`key_id` (call it `key_retired`) with a documented rotation
timestamp.

## Steps

1. As `k8s-exec-A` (configured `team_id = team-A`, registered
   `scope = team`, `authorized_tag = k8s-cluster-A`) over plain
   HTTP, request
   `GET /v1/environments/{environment_id}/open?task_id=task_id_env`
   carrying the compact three-part signed scope token
   `<header>.<payload>.<signature>` in the `X-FlowAI-Scope-Token`
   request header only (no scope-token fields appear in the body or
   other headers), whose protected header carries `alg = HS256`,
   `kid = key_active`, and `typ = scope-token+json`, and whose
   payload claims list `team_id = team-A`,
   `project_id = project_env` (a non-null project),
   `task_id = task_id_env`, `environment_id = environment_id`,
   `executor_id = k8s-exec-A`,
   `audience = state-registry.environment.open`,
   `key_id = key_active`, `issued_at = now`, and
   `expiry = now + 5 minutes`; capture the response status code, body
   shape, audit entries, and provider decrypt operation count made by
   the Registry.
2. Have the K8s Executor inject the returned env-style values into
   `task_id_env`'s Pod and discard the plaintext after Pod startup.
3. As `k8s-exec-A`, repeat the same open request with one variation
   at a time, capturing the response shape, audit entries, and
   provider decrypt operation count for each:
   3a. `team_id` claim mutated to `team-B`.
   3b. `executor_id` claim mutated to `k8s-exec-B`.
   3c. `project_id` claim mutated to an unrelated project.
   3d. `task_id` claim mutated to an unrelated task in the same team.
   3e. `environment_id` claim mutated to a foreign-team environment.
   3f. `audience` claim mutated to a foreign audience.
   3g. `key_id` mutated to `key_retired` (a retired key).
   3h. Protected-header `kid` set to a value different from the
   payload `key_id` (kid/key_id mismatch) while keeping the same
   algorithm and remaining claims.
   3i. Signature mutated (MAC tampered) but other claims unchanged.
   3j. `expiry` mutated to a past timestamp (`expiry < issued_at`,
   equivalent to `expiry <= issued_at`).
   3k. `expiry - issued_at` extended beyond five minutes while still
   in the future (TTL violation).
   3l. `issued_at` set to `now + 5 minutes` (premature beyond the
   `server_now + 30 seconds` skew window).
   3m. `project_id` set to `null` while the canonical environment
   has a project scope (project_id null for project-scoped
   environment).
   3n. `project_id` claim removed entirely (missing project_id).
4. Drive `task_id_env` to terminal state by appending the assigned
   Executor-emitted `finished` event, then as `k8s-exec-A` repeat the
   open request with the otherwise-valid token from step 1.
5. As a second K8s Executor `k8s-exec-B` configured
   `team_id = team-B` (registered in its own team, with no
   assignment to `task_id_env`), repeat the same open request
   with a valid signed token whose `team_id` claim equals
   `team-B`.
6. Inspect K8s Executor logs and durable storage for plaintext, and
   inspect the State Registry for any open-environment audit entries
   and provider decrypt operations produced by the requests in steps
   3, 4, and 5.

## Expected outcome

Step 1 returns `200` with the env-style values including the
decrypted secret. The values reach only `task_id_env`'s Pod and are
discarded after Pod startup. The State Registry records one
open-environment audit entry for `team_id = team-A` containing
`environment_id`, `executor_id = k8s-exec-A`,
`task_id = task_id_env`, `audience =
state-registry.environment.open`, `key_id = key_active`, and the
access time, without plaintext. K8s Executor logs and durable storage
contain no plaintext. Every variation in step 3 (3a–3n), step 4, and
step 5 returns the same non-revealing `404
environment_unknown_or_unavailable` shape indistinguishable from
"resource does not exist"; the State Registry performs zero provider
decrypt operations for any of those requests; no plaintext is
appended to any audit, log, or response; no K8s Executor state shows
any Pod receiving foreign-team values; the only audit entry produced
across all steps is the single plaintext-free entry from step 1.
