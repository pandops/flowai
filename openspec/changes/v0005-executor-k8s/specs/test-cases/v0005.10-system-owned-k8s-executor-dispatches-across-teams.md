# Test case: v0005.10-system-owned-k8s-executor-dispatches-across-teams

## Implements

`executor` — `### Requirement: K8s Executor participates in State Registry FIFO task claims`.

`executor` — `### Requirement: K8s Executor is scope-aware and provider-neutral`.

## Intent

Happy-path and isolation test verifying that the concrete K8s Executor can
register once with system scope, discover matching work across teams, and use
the claimed task's immutable team as every Pod and event envelope without
changing task ownership.

## Preconditions

- The concrete service identifier is `executor_k8s_openhands` and its agent
  tool is OpenHands.
- State Registry contains `team-A` and `team-B`, each with one pending task
  whose `required_tag = k8s-system`, ordered deterministically by
  `(ingested_at, task_id)`.
- An authenticated system-owned Executor identity is authorized for the
  `k8s-system` tag and is not bound to a team.

## Steps

1. Register the K8s Executor with `scope = system`, no `team_id`, and
   `executor_type = "executor_k8s_openhands"`.
2. Discover pending work and inspect the returned summaries.
3. Claim the oldest eligible task with a stable `command_id`.
4. Observe the created Pod labels and append `running` followed by one
   terminal event.
5. Read both canonical tasks and event histories through trusted operator
   paths.

## Expected outcome

Registration succeeds without a team binding. Discovery is FIFO across teams
for the registered tag and exposes metadata-only summaries. Claim returns the
oldest eligible task with its immutable `team_id`; the Pod labels and task
event envelopes use that task team and `flowai.executor_scope = system`.
State Registry retains the original `tasks.team_id`, appends exactly one first
`created` event and the Executor's ordered events, and does not authorize any
unassigned task resource merely because the Executor has system scope.
