# Test case: v0005.3-team-isolated-discovery-and-claim-no-leak

## Implements

`executor` — `### Requirement: K8s Executor scopes discovery, claim, task events, environment opens, and control reads to its bound team`.

`executor` — `### Requirement: K8s Executor participates in State Registry FIFO task claims`.

## Intent

Verify that collection-level discovery of `pending` tasks filters by
`team_id` BEFORE shaping results, so a tag whose matching `pending`
tasks all belong to other teams yields the NORMAL empty result (`204
No Content` or `200` with an empty task list and no count, cursor,
total, or pagination metadata), indistinguishable from "no tasks match
this tag anywhere"; that point-resource lookups for a foreign-team
`task_id` (claim, task detail read) return a non-revealing `404`
indistinguishable from "resource does not exist"; and that the K8s
Executor never creates a Pod and never appends an event for any
cross-team identifier. Verify also that the FIFO claim contract is
honored: a request for an eligible non-oldest `pending` task returns
`409 older_task_must_be_claimed_first` and the same `(task_id,
command_id)` retry by the original Executor returns the original
`200 claimed` body without appending an additional event.

## Preconditions

State Registry and PostgreSQL are running. Two authenticated Executor
service identities exist: `k8s-exec-A` bound to `team_id = team-A`
and `k8s-exec-B` bound to `team_id = team-B`. Each K8s Executor is
registered with `scope = team` and exactly one `authorized_tag`
(`k8s-cluster-A` for `k8s-exec-A`, `k8s-cluster-B` for `k8s-exec-B`).
Two `pending` tasks exist: one with `team_id = team-A` and
`required_tag = k8s-cluster-A`, the other with `team_id = team-B`
and `required_tag = k8s-cluster-B`.

## Steps

1. As `k8s-exec-A`, request
   `GET /v1/executors/k8s-exec-A/tasks?tag=k8s-cluster-A` and record
   the returned payload and any `count`, `cursor`, `total`, or
   pagination metadata present in the response.
2. As `k8s-exec-A`, request
   `GET /v1/executors/k8s-exec-A/tasks?tag=k8s-cluster-B` and record
   the returned payload and any `count`, `cursor`, `total`, or
   pagination metadata present in the response.
3. As `k8s-exec-A`, request
   `POST /v1/executors/k8s-exec-A/claim` for the `team-B` task's
   `task_id` with a fresh `command_id`; record the response.
4. As `k8s-exec-A`, read the foreign task by `task_id` via the task
   detail read API (for example `GET /v1/tasks/{task_id}`).
5. Seed a second `pending` task in `team-A` (`task_id_A2`) with
   `ingested_at` strictly older than the existing `team-A` task
   (`task_id_A1`). As `k8s-exec-A`, request
   `POST /v1/executors/k8s-exec-A/claim` for the NON-oldest eligible
   `pending` task `task_id_A1` (i.e. the newer one) and a fresh
   `command_id`; record the response. Then claim the oldest eligible
   `task_id_A2` with the same `command_id` and capture the original
   `200 claimed` body, then retry the same `(task_id_A2,
command_id)` and capture the idempotent response.
6. Read both tasks and their event histories through the API Gateway.
7. Inspect the K8s Executor's local Pod/state for any Pod created for
   the `team-B` task and for the non-oldest `task_id_A1`.

## Expected outcome

Step 1 returns `200` with exactly the `team-A` `pending` task
summary in `(ingested_at ASC, task_id ASC)` order and no `team-B`
rows. Step 2 returns `204 No Content` (or `200` with an empty task
list); the response payload contains NO `count`, `cursor`, `total`,
or pagination metadata that would distinguish this outcome from "no
tasks match this tag anywhere". Step 3 returns a non-revealing `404`
whose body shape is indistinguishable from "resource does not exist"
for the `team-B` `task_id`. Step 4 returns a non-revealing `404`
identical in shape to step 3. Step 5 returns
`409 older_task_must_be_claimed_first` for the non-oldest task
without mutation or event append; the subsequent claim of the oldest
eligible `task_id_A2` returns `200 claimed`; the same
`(task_id_A2, command_id)` retry returns the original `200 claimed`
body without an additional event and without field changes. No Pod
exists for the `team-B` task and no Pod exists for the non-oldest
`task_id_A1`; no event has been appended to either cross-team or
non-oldest task event history. Both `team-A` task reads in step 6
return `200` with `current_state` reflecting the FIFO claim
contract: `task_id_A1` remains `pending` with `executor_id = null`;
`task_id_A2` projects to `created` with `executor_id = k8s-exec-A`
and an event history of exactly `[created]` (Registry-appended on
claim). No `dispatched` event appears at any point.
