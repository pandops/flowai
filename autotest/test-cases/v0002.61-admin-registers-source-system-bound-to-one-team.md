# Test case: v0002.61-admin-registers-source-system-bound-to-one-team

## Implements

`state-registry` — ``### Requirement: State Registry owns source-system registration through `/admin/source-systems```.

## Intent

Verify that an authenticated system administrator can register a team-owned source system through `POST /admin/source-systems` referencing an existing team, that a source-system identity belongs to exactly one team, and that the database-enforced global uniqueness on `source_systems.listener_identity` rejects any duplicate listener principal under the same team, a different team, or any other variation without persisting a row.

## Preconditions

State Registry and PostgreSQL are running; `team-a` and `team-b` each already exist; an authenticated system-administrator identity is configured; no `source_systems` row exists yet.

## Steps

1. Submit `POST /admin/source-systems` with `team_id = team-a`, a listener identity reference `L-1`, and an optional `default_image` as the authenticated system administrator.
2. Read the returned canonical source system record and confirm `source_system_id`, `team_id`, listener identity reference, and optional `default_image`.
3. Submit `POST /admin/source-systems` with `team_id = team-a` and the same listener identity reference `L-1`; observe the rejection and confirm no row was created.
4. Submit `POST /admin/source-systems` with `team_id = team-b` and the same listener identity reference `L-1`; observe the rejection and confirm no row was created.
5. Submit `POST /admin/source-systems` with `team_id` referencing a team that does not exist and observe the response.
6. Submit `POST /admin/source-systems` without an authenticated system-administrator identity and observe the response.

## Expected outcome

The first request returns `201` with the generated immutable `source_system_id`, immutable `team_id = team-a`, the listener identity reference, and the optional `default_image`. Steps 3 and 4 are rejected without persisting or partially persisting any source system row because the database-enforced global uniqueness index over `source_systems.listener_identity` rejects the duplicate listener principal under the same team and under a different team; one listener principal maps to exactly one `(team_id, source_system_id)` pair. Step 5 is rejected without persisting any source system row because the referenced team does not exist. Step 6 is rejected. Source-system rows are persisted under exactly one team; cross-team reattachment of the same `source_system_id` is rejected.
