# Test case: v0002.30-registry-appends-first-created-event-on-claim

## Implements

`state-registry` — ``### Requirement: State Registry appends the first `created` event atomically on successful claim``.

## Intent

Verify the FIRST `created` event is Registry-appended in the claim transaction, carries non-null `executor_id` identifying the claiming Executor, and persists `current_state = created` together with `tasks.executor_id`, `tasks.owner_command_id`, `tasks.claimed_at`, `tasks.resolved_image`, and `tasks.image_source` in the same transaction. No `dispatched` event exists; no event was appended at ingestion.

## Preconditions

State Registry and PostgreSQL are running; a listener and an Executor are each bound to `team-a`; the Executor has tag `openhands`; `team-a` has a registered task type `tt-a1` with `execution_tag = openhands`; no task exists for `(team-a, source-system-a, JIRA-300)`; trusted Gateway context for `team-a` can read tasks and events.

## Steps

1. Submit a task with `team_id = team-a`, `source_system_id = source-system-a`, `source_id = JIRA-300`, REQUIRED `task_type_id = tt-a1`, and payload.
2. Read task and history immediately after ingestion.
3. From the same-team, same-tag Executor, submit `POST /v1/executors/{executor_id}/claim` with `task_id` and `command_id`.
4. Read task and history immediately after claim.

## Expected outcome

Ingestion commits the durable `pending` task with no event appended (empty event history); listener acknowledgement follows commit. Claim atomically appends the FIRST Registry-emitted `created` row with non-null `executor_id` equal to the claiming Executor and payload meaning `task <task_id> loaded by <executor_id>`, sets `tasks.owner_command_id` (immutable thereafter) and `tasks.executor_id` (immutable thereafter), records `tasks.claimed_at`, persists `tasks.resolved_image` and `tasks.image_source` from the four-level precedence, and projects `current_state = created`. No `dispatched` event exists. After claim, history is `[created]` ordered by `(occurred_at, event_id)` with no Executor-emitted rows yet; the Executor subsequently emits `running` itself.
