# Test case: v0002.49-task-owned-secret-only-parent-task-can-open

## Implements

`state-registry` — `### Requirement: State Registry opens environments only for assigned same-team Executors`.

`state-registry` — `### Requirement: State Registry uses local AES-256-GCM authenticated encryption for secret values`.

## Intent

Verify that a task-owned environment and the secret under it can be opened only by the parent task's assigned same-team Executor, and that every other same-team Executor or foreign request returns the same non-revealing `404 environment_unknown_or_unavailable` shape with zero local AES-256-GCM decrypt operations.

## Preconditions

- A `team-a` task `task-1` and a separate `team-a` task `task-2` are each claimed by their own Executor (each task has `tasks.executor_id` and `tasks.owner_command_id` set).
- A `team-a` task-owned environment `env-task-1` exists with parent `task_id = task-1`, and a logical secret with encrypted versions exists under it (see `v0002.46` and `v0002.47`).
- Two same-team Executors `executor-1` and `executor-2` are registered with `team-a` and the same registered tag.
- `task-1` is claimed by `executor-1` (assignee); `task-2` is claimed by `executor-2`.
- The configured 256-bit AES-256-GCM data key is loaded and an AES-256-GCM decrypt operation counter is observable.

## Steps

1. As `executor-1`, call `GET /v1/environments/{env-task-1}/open?task_id=task-1` with a valid scope token bound to `task-1`, `environment_id = env-task-1`, and `executor_id = executor-1`. Inspect the response body.
2. As `executor-2`, repeat the open with `task_id=task-1` and `environment_id = env-task-1` using a token bound to `executor-2` instead of `executor-1`.
3. As `executor-2`, attempt to open with `task_id=task-2` and `environment_id = env-task-1` even though `task-2` is not the parent task.
4. Inspect the local AES-256-GCM decrypt operation counter and audit entries for each attempt.

## Expected outcome

Only step 1 returns `200` with the decrypted env-style values and appends a plaintext-free `team-a` audit entry; the decrypt counter records exactly one decrypt operation for step 1. Steps 2 and 3 return the same non-revealing `404 environment_unknown_or_unavailable` shape with no values returned, zero local AES-256-GCM decrypt operations attempted, and no audit disclosure of any secret material or non-terminal state. The successful step enforces task-parent applicability via the canonical `environment_id` -> `parent_task_id` relationship.
