# Test case: v0002.36-foreign-team-events-are-not-found

## Implements

`state-registry` — `### Requirement: State Registry accepts Executor-emitted lifecycle events under the Executor's ownership scope`.

`state-registry` — `### Requirement: State Registry records Executor self events under the Executor's ownership scope`.

`state-registry` — `### Requirement: State Registry returns non-revealing not-found for foreign resources`.

## Intent

Verify task-event and Executor-self-event point writes cannot cross immutable team ownership.

## Preconditions

`team-b` owns a claimed task assigned to `executor-b` (via `tasks.executor_id = executor-b`, `tasks.owner_command_id = C-b`) and a registered Executor record; authenticated `executor-a` belongs to `team-a` and is team-owned with `scope = team`.

## Steps

1. As `executor-a`, post a validly shaped `running` event to the `team-b` task identifier carrying `executor_id = executor-a`, envelope `team_id = team-a`, and the standard event envelope.
2. As `executor-a`, post a validly shaped self event to the `team-b` Executor identifier carrying `executor_id = executor-a`, envelope `team_id = team-a`, and the standard self-event envelope.
3. Repeat both calls with nonexistent identifiers.
4. As `executor-b`, post the same `running` envelope to its `team-b` task while submitting envelope `team_id = team-a` (mismatch with the authenticated `team-b` Executor).
5. Read the `team-b` resources and histories through trusted Gateway context for `team-b`.

## Expected outcome

State Registry verifies envelope `team_id` against the authenticated Executor team on every event write. Foreign and unknown point probes return identical non-revealing `404` shapes; same-team envelope writers whose `team_id` does not match their authenticated Executor team are rejected with `403 team_mismatch`. No task event or self event is appended, projected task state and mirrored capacity observations remain unchanged, and no existence or ownership detail is disclosed. No `dispatched` event exists; the FIRST `created` event on the `team-b` task is Registry-appended at claim time.
