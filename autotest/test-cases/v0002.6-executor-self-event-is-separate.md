# Test case: v0002.6-executor-self-event-is-separate

## Implements

`state-registry` — `### Requirement: State Registry records Executor self events under the Executor's ownership scope`.

## Intent

Verify that a complete Executor capacity observation is accepted only by the Executor event stream and does not enter task history.

## Preconditions

Registered Executor `executor-1` has immutable `team_id = team-a`, and one `team-a` task is assigned to it.

## Steps

1. Post an Executor self event as `executor-1` to `POST /v1/executors/executor-1/events` carrying non-null `executor_id = executor-1`, `team_id = team-a`, `event_id = 0190-capacity-0001`, `event_type = capacity_observed`, `occurred_at = 2026-07-13T10:00:00Z`, and `payload = {"max_capacity":2,"running_count":1}`.
2. Attempt to post that Executor event to `POST /v1/tasks/{task_id}/events` while supplying `team_id = team-a`.
3. Read the Executor record and both event histories through trusted Gateway context for `team-a`.

## Expected outcome

State Registry verifies that the submitted `team_id = team-a` matches the authenticated Executor's binding. The Executor endpoint returns `202 accepted`; the task endpoint rejects the wrong event scope; Executor history contains `0190-capacity-0001` exactly once with non-null `executor_id = executor-1`, `team_id = team-a`, and same-team ownership; the Executor row mirrors `max_capacity = 2` and `running_count = 1`; and task history contains no event with that `event_id`.
