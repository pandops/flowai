# Test case: v0002.47-operator-stores-task-owned-secret-version

## Implements

`state-registry` — `### Requirement: State Registry stores team-owned secrets with immutable versions`.

`state-registry` — `### Requirement: State Registry uses local AES-256-GCM authenticated encryption for secret values`.

## Intent

Verify a same-team operator can store an encrypted logical secret under a task-owned environment using local AES-256-GCM authenticated encryption; the resulting secret is itself task-owned and may be opened only by the parent task.

## Preconditions

- A `team-a` task-owned environment already exists (see `v0002.46`).
- Web UI, trusted API Gateway, State Registry, and PostgreSQL are running.
- The configured 256-bit AES-256-GCM data key is loaded.
- Trusted Gateway context contains verified `operator_id`, immutable `team_id = team-a`, display-only `team_name`, and `request_id`.

## Steps

1. Through Web UI and API Gateway under trusted Gateway context for `team-a`, create a logical secret under the task-owned environment, providing `name`, plaintext `value`, and the parent task's `task_id` applicability.
2. Read the logical secret metadata and version metadata back through the same trusted team context and inspect `team_id`, `environment_id`, scope applicability, and `latest_version`.
3. Replace the secret value through the same trusted team path with a different plaintext value and confirm a new version is appended.
4. Query the team-scoped audit entries for the create and replace actions and confirm they contain no plaintext, nonce, ciphertext, authentication tag, key material, or association-data values beyond identifier-level metadata.

## Expected outcome

The create call returns `201` with `secret_id` and a `version` number plus opaque provider-neutral `key_id` and `key_version` metadata; the logical secret metadata carries the parent `task_id` applicability and references the task-owned environment; the replace returns a higher `version` with a new ciphertext, fresh nonce, and opaque key-version metadata; local AES-256-GCM authenticated encryption was used for both operations with associated-data binding team identifier, logical secret identifier, and version; and the operator responses, application logs, and audit entries never contain the plaintext values, ciphertext bytes, nonce bytes, authentication tag bytes, key material, or derived key bytes.
