# Test case: v0002.21-claim-hides-task-from-discovery

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

## Intent

Verify that a successful claim atomically removes the `pending` task from the claimer's scope of discovery and projects the task to `created` with the FIRST lifecycle event `created` appended in the same transaction.

## Preconditions

State Registry, PostgreSQL, and two team-owned Executors are running; a `team-a` `pending` task exists with required tag `openhands`; both Executors are bound to `team-a` and registered with exactly that tag.

## Steps

1. From the first same-team Executor, discover the pending task by exact equality with authenticated `team_id = team-a` and tag `openhands`.
2. Submit `POST /v1/executors/{executor_id}/claim` with `task_id` and `command_id = C-1`.
3. From both eligible same-team Executors, repeat discovery.
4. Read the canonical task and history through trusted Gateway context for `team-a`.

## Expected outcome

Step 2 returns `200 claimed`; both subsequent discovery requests return `204` or an empty same-team collection without the task; the task stays owned by `team-a`, projects to `created`, and has the first Executor as sole immutable `executor_id`; `tasks.owner_command_id = C-1`; `tasks.executor_id` is immutable from claim onward; the ordered event list is exactly `[created]` with one Registry-appended `created` row whose `executor_id = executor-1` (the claiming Executor) and whose payload meaning encodes `task <task_id> loaded by executor-1`; no `dispatched` event was appended.
