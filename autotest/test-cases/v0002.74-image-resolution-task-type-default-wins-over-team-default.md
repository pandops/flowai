# Test case: v0002.74-image-resolution-task-type-default-wins-over-team-default

## Implements

`state-registry` — `### Requirement: State Registry resolves the effective image at claim by four-level precedence`.

## Intent

Verify the second level of image precedence: when `tasks.image` is null but `task_types.default_image` is non-null, the claim response records `resolved_image = task_types.default_image` and `image_source = task_type_default`.

## Preconditions

State Registry and PostgreSQL are running; a team-owned Executor and a task type `tt-default` are registered for `team-a`; the task type's `default_image` differs from `teams.default_image` and from `source_systems.default_image`; `source_systems.default_image` and `tasks.image` are null; one pending task exists.

## Steps

1. Submit `POST /v1/executors/{executor_id}/claim` with the task's `task_id` and a fresh `command_id`.
2. Read the claim response and confirm `resolved_image = task_types.default_image` and `image_source = task_type_default`.
3. Read the canonical task and confirm `resolved_image = task_types.default_image`, `image_source = task_type_default`, `current_state = created`.
4. Read the canonical task event history and confirm exactly one `created` event.

## Expected outcome

The image resolves at the second level of precedence because the per-task override is null but the task type default is non-null. The claim response and the persisted task carry `resolved_image` and `image_source` consistently. No `dispatched` event is appended. The Executor never needs a local image.
