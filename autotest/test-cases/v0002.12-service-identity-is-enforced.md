# Test case: v0002.12-service-identity-validates-against-canonical-records

## Implements

`state-registry` — `### Requirement: State Registry uses canonical team/source-system records for listener ownership`.

`state-registry` — `### Requirement: State Registry enforces Executor scope as a registration-time decision`.

## Intent

Verify that the State Registry validates the canonical team / source-system / task-type / Executor records at every protected surface; the deployment network policy owns the listener / Executor / Gateway / admin caller boundary after v0009; data-integrity checks remain enforced for every recorded pair.

## Preconditions

A team-a and a team-b are registered; the listener for team-a is bound to `team-a` and `source-system-a`; Executor identities each register `scope = team` (bound to exactly one existing team) or `scope = system` (no team); trusted API Gateway context contains one verified `operator_id`, `team_id`, display-only `team_name`, and `request_id`; two same-team Executors and a task claimed by the first Executor exist; the system-administrator identity is an operational concern outside the State Registry contract. v0009: the State Registry does not authenticate the connection; the X-FlowAI-* headers are trusted request data and the deployment network policy owns the caller boundary.

## Steps

1. Attempt listener ingestion using a body `team_id` that is foreign to the registered `source_system_id`, or an unregistered `source_system_id`, or a `team_id` outside any registered team.
2. Attempt claim, task-event writes (with and without matching envelope `team_id`), control reads, and environment opens using an unassigned or foreign-team Executor.
3. Attempt Gateway-only reads, subscriptions, controls, environment writes, and secret writes without the trusted Gateway context or with caller-selected tenant headers.
4. Attempt `POST /admin/teams`, `POST /admin/source-systems`, and `POST /admin/task-types` without a body that satisfies the admin validation rules (unique `team_name` + required `default_image` for teams, etc.).

## Expected outcome

Every request whose submitted identifiers disagree with the canonical records (foreign team, foreign source system, unknown task type, foreign Executor) is rejected with the documented non-revealing `403 not_authorized` or `400 invalid_request` envelope; point probes of foreign identifiers are indistinguishable from unknown identifiers; task and self event writes whose envelope `team_id` does not match the parent task's `team_id` are rejected with `403 team_mismatch`; correctly recorded one-team requests are authorized solely by canonical `team_id` and the request-time identifier predicates. Calls to `/admin/*` whose body fails data validation are rejected with `400 invalid_request`; the State Registry never authenticates the system-administrator identity, the deployment network policy owns the `/admin/*` caller boundary, and no listener, Executor, or Gateway path may create or update a team, source system, or task type.
