# Test case: v0002.12-service-identity-is-enforced

## Implements

`state-registry` — `### Requirement: State Registry enforces team-bound service identities with conditional Executor binding`.

`state-registry` — `### Requirement: State Registry enforces Executor scope as a registration-time decision`.

## Intent

Verify listener, Executor (team-owned or system-owned), gateway, and assignment authorization at every protected State Registry surface; admin-only paths reject non-administrators.

## Preconditions

Listener identities are each bound to exactly one immutable team and one immutable registered source system; Executor identities each register `scope = team` (bound to exactly one existing team) or `scope = system` (no team); trusted API Gateway context contains one verified `operator_id`, `team_id`, display-only `team_name`, and `request_id`; two same-team Executors and a task claimed by the first Executor exist; the system-administrator identity is a separate, deployment-defined credential distinct from listener, Executor, and Gateway identities.

## Steps

1. Attempt listener ingestion using another source identity, an unregistered `source_system_id`, or a `team_id` outside the listener binding.
2. Attempt claim, task-event writes (with and without matching envelope `team_id`), control reads, and environment opens using an unassigned or foreign-team Executor.
3. Attempt Gateway-only reads, subscriptions, controls, environment writes, and secret writes without the trusted Gateway identity or with caller-selected tenant headers.
4. Attempt `POST /admin/teams`, `POST /admin/source-systems`, and `POST /admin/task-types` using a listener, Executor, or Gateway identity.

## Expected outcome

Every impersonating, foreign-team, unassigned, or untrusted-Gateway request is rejected without revealing or changing protected state; point probes of foreign identifiers are indistinguishable from unknown identifiers; task and self event writes whose envelope `team_id` does not match the authenticated Executor team (team-owned) or the parent task's `team_id` (system-owned) are rejected with `403 team_mismatch`; correctly authenticated one-team requests remain authorized solely by canonical `team_id`. Calls to `/admin/*` that are not authenticated by the system-administrator identity are rejected; no listener, Executor, or Gateway path may create or update a team, source system, or task type.
