# Test case: v0002.60-admin-creates-team-with-required-default-image

## Implements

`state-registry` — `### Requirement: State Registry owns team registration through `/admin/teams```.

## Intent

Verify that an authenticated system administrator can create a team through `POST /admin/teams` only when the body contains a unique `team_name` and a required opaque `default_image`; the Registry persists the generated immutable `team_id` plus the unique `team_name` and the required `default_image`.

## Preconditions

State Registry and PostgreSQL are running; no team exists; the system-administrator authentication mechanism is an operational concern outside the State Registry contract — the deployment network policy owns the `/admin/*` caller boundary; the Registry validates only the body shape and the canonical record (uniqueness of `team_name`, presence of `default_image`). v0009: the State Registry does not authenticate the system-administrator identity; the `X-FlowAI-Admin-Subject` header (if supplied) is recorded as audit attribution data only.

## Steps

1. Submit `POST /admin/teams` with a unique `team_name` and a required opaque `default_image`.
2. Read back the returned canonical team record.
3. Submit `POST /admin/teams` again with the same `team_name` and observe the response.
4. Submit `POST /admin/teams` without `default_image` and observe the response.
5. Submit `POST /admin/teams` without `team_name` and observe the response.

## Expected outcome

The first request returns `201` with a generated immutable `team_id`, the supplied unique `team_name`, and the required `default_image`; the team row is durable across restart. The duplicate-`team_name`, missing-`default_image`, and missing-`team_name` requests are each rejected with `400` and the documented envelope (duplicate `team_name` is a body-validation or conflict error; missing fields are `invalid_request`) without creating or partially persisting a team. The State Registry never authenticates the system-administrator identity and never derives authority from the X-FlowAI-* request headers; the network policy is the documented `/admin/*` boundary.
