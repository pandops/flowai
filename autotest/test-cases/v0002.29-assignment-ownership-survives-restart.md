# Test case: v0002.29-assignment-ownership-survives-restart

## Implements

`state-registry` — `### Requirement: State Registry normalizes team-owned entity relationships`.

## Intent

Verify the claiming Executor remains immutable and is the only accepted event owner before and after a State Registry restart.

## Preconditions

One `team-a` `pending` task has tag `openhands`; `executor-1` and `executor-2` are each team-owned and registered with that tag; `executor-1` has successfully claimed the task with `command_id = C-1`; `executor-2` retains the stale `task_id`; trusted Gateway context for `team-a` can read task and event state.

## Steps

1. Submit `POST /v1/executors/{executor_id}/claim` for the same `task_id` from `executor-2` with `command_id = C-2` (different from C-1).
2. Attempt `running` as unassigned same-team `executor-2`, carrying envelope `team_id = team-a`.
3. Post valid `running` as the claiming `executor-1` carrying envelope `team_id = team-a`.
4. Restart State Registry while preserving PostgreSQL.
5. Retry claim from `executor-2` with a fresh `command_id = C-3`.
6. Read task and history as `team-a`.

## Expected outcome

State Registry verifies envelope `team_id = team-a` against the authenticated Executor team on every event write; the wrong-owner claim is rejected with `409 task_already_claimed` and the wrong-owner event with `403 not_assigned`. The assigned-owner `running` succeeds; post-restart re-claim from a different Executor returns `409 task_already_claimed`; the task retains immutable `team_id = team-a`, `owner_command_id = C-1`, and `executor_id = executor-1`; the ordered history is exactly `[created, running]` with the FIRST `created` event Registry-appended at claim time carrying non-null `executor_id = executor-1` and payload meaning `task <task_id> loaded by executor-1`; the Executor-emitted `running` row has non-null `executor_id = executor-1` with envelope `team_id = team-a`; no `dispatched` event exists; and `accepted_sequence` is never honored.
