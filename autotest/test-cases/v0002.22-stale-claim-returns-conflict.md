# Test case: v0002.22-stale-claim-returns-conflict

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

## Intent

Verify that an Executor cannot claim a task already claimed by another Executor from a stale discovery result; the second request returns `409 task_already_claimed` with no mutation and the task remains in `created` state owned by the original claimer.

## Preconditions

State Registry, PostgreSQL, and two `team-a` team-owned Executors with the same single tag are running; one `team-a` `pending` task exists; the first Executor has successfully claimed the task with `command_id = C-1` and the second Executor retains the stale `task_id`.

## Steps

1. Submit `POST /v1/executors/{executor_id}/claim` for the same `task_id` from the second same-team Executor with `command_id = C-2` (different from C-1).
2. Read the canonical task and history through trusted Gateway context for `team-a`.
3. Observe whether the second Executor posts `running` or starts a runtime.

## Expected outcome

The second request returns `409 task_already_claimed`; the task remains in `team-a`, in `created`, and assigned immutably to the first Executor with `owner_command_id = C-1`; the history remains exactly `[created]` with no additional event; and the second Executor starts no runtime and appends no event.
