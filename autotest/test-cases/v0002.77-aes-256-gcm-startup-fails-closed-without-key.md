# Test case: v0002.77-aes-256-gcm-startup-fails-closed-without-key

## Implements

`state-registry` — `### Requirement: State Registry uses local AES-256-GCM authenticated encryption for secret values`.

## Intent

Verify that the State Registry fails closed at startup when the configuration-provided 256-bit AES-GCM key is missing, that secret writes and open-environment reads are refused, and that logs and audit entries contain no plaintext, key material, nonce bytes, ciphertext bytes, or authentication tag bytes.

## Preconditions

State Registry and PostgreSQL processes are running but the configuration-provided 256-bit AES-GCM key is absent (a documented misconfiguration).

## Steps

1. Confirm the State Registry process either fails to start or refuses all `POST /v1/environments/{id}/secrets` calls.
2. Attempt a secret create through trusted API Gateway context and observe the response.
3. Attempt an open-environment read with a valid scope token (or any token) and observe the response.
4. Capture application logs and audit entries for the failures.

## Expected outcome

The Registry refuses the secret create and the open read with a fail-closed error shape. Application logs and audit entries contain no plaintext, no `key_id`, no `key_version`, no nonce bytes, no ciphertext bytes, no authentication tag bytes, and no associated-data values beyond identifier-level metadata. The startup-misconfiguration sentinel prevents accidental plaintext persistence.

## Implementation reference

`autotest/state-registry/tests/contracts/06-environments-secrets-crypto.spec.ts` — `v0002.77 AES-256-GCM startup fails closed: configured key is required before any secret write or open`
