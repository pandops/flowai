# Test case: v0002.76-image-equality-across-teams-grants-no-authority

## Implements

`state-registry` — `### Requirement: State Registry remains independent from execution and identity management`.

`state-registry` — `### Requirement: State Registry persists per-task, per-task-type, and per-source-system image overrides`.

## Intent

Verify that two teams referencing the same opaque image string do NOT grant or broaden each other's authority; image strings are not team-owned resources and image equality SHALL NEVER establish tenant ownership or weaken cross-team isolation.

## Preconditions

State Registry and PostgreSQL are running; `team-a` and `team-b` exist; `image string S` is registered on each team's `default_image` (the only way the platform permits required `default_image` is through admin registration); an executor is configured for `team-a`.

## Steps

1. Read `team-a` and `team-b` through trusted Gateway context (each under its own operator context) and confirm both `default_image` references are the same string `S` without exposing team-cross references.
2. Claim a `team-a` task under the team-owned Executor and observe `resolved_image = S`, `image_source = team_default`.
3. Attempt to send a task event for a `team-b` task from the `team-a` Executor and observe the response.
4. Attempt to read a `team-b` resource directly from the `team-a` operator context and observe the response.
5. Attempt to interpret the shared image string as evidence of cross-team authority at any layer (audit, control, claim).

## Expected outcome

Both teams may legitimately reference the same image string S, but the team-a Executor is rejected for any team-b resource with the same non-revealing `404` it would receive for any unknown cross-team task; image equality never grants access, broadens visibility, or weakens isolation. Audit entries do not include the image digest verbatim. Logs do not include any image content.
