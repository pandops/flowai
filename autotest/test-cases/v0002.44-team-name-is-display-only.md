# Test case: v0002.44-team-name-is-display-only

## Implements

`state-registry` — `### Requirement: State Registry persists team ownership in normalized 3NF PostgreSQL`.

`state-registry` — `### Requirement: State Registry requires trusted team-scoped API Gateway context`.

## Intent

Verify changing or spoofing display-only `team_name` cannot change ownership or authorization anchored to canonical immutable `team_id`.

## Preconditions

`teams` contains `team_id = team-a` with `team_name = Alpha`; trusted Gateway context for its operator carries both fields; `team-b` owns a protected resource.

## Steps

1. Read a `team-a` resource through trusted Gateway context.
2. Change the stored display name for `team-a` from `Alpha` to `Renamed Alpha` without changing `team_id`, then repeat the read.
3. Present `team_name = team-b` while retaining verified `team_id = team-a` and probe the `team-b` resource.
4. Present the old `team_name = Alpha` with verified `team_id = team-a` and repeat an authorized `team-a` operation.
5. Submit an Executor task event carrying `team_name = team-b` while envelope `team_id = team-a` matches the authenticated Executor team.

## Expected outcome

Both pre- and post-rename `team-a` operations authorize identically by `team_id`; display text and audit context may show the current name. Spoofing `team_name` never grants `team-b` access, the foreign point probe returns the unknown-resource `404` shape without changing ownership, and the Executor event is accepted only because envelope `team_id` matched the authenticated Executor team; `team_name` does not influence State Registry authorization on any surface.
