# Test case: v0002.11-assigned-executor-opens-environment

## Implements

`state-registry` — `### Requirement: State Registry opens environments only for assigned same-team Executors`.

`state-registry` — `### Requirement: State Registry uses local AES-256-GCM authenticated encryption for secret values`.

## Intent

Verify successful scoped decryption using local AES-256-GCM authenticated encryption with associated-data binding team identifier, logical secret identifier, and version; rejection of invalid or unassigned requests; and zero decrypt operations for every invalid or unavailable variant.

## Preconditions

A `team-a` task is claimed by `team-a` Executor `executor-1` with `command_id = C-1` (assignment `tasks.executor_id = executor-1`, `tasks.owner_command_id = C-1`) and references a same-team environment with non-secret values and an encrypted secret; the claim response returned a signed scope token containing `team_id`, `project_id` (required claim; null only when the canonical environment has no project scope), `task_id`, `environment_id`, `executor_id`, `audience` (literal `state-registry.environment.open`), `key_id`, `issued_at`, and `expiry`; the configured AES-256-GCM data key is loaded.

## Steps

1. Open the environment as `executor-1` with a valid token whose signature and every claim match canonical records.
2. Repeat as another team-owned Executor and with a foreign-team Executor identity.
3. Repeat with invalid signature, algorithm outside the allow-listed `HS256`/`HS384`/`HS512` HMAC set, protected-header `kid` that does not equal the payload `key_id`, audience, premature-beyond-skew `issued_at`, `expiry` not strictly later than `issued_at`, `expiry` more than five minutes after `issued_at`, team, project, task, environment, executor, and assignment bindings.

## Expected outcome

Only the assigned same-team Executor with every valid claim receives env-style values (decrypted under local AES-256-GCM with associated-data binding team identifier, logical secret identifier, and version) and a plaintext-free team audit entry; every other request returns no values and triggers zero decrypt operations; foreign identifiers use the non-revealing `404` shape where a point resource is probed. No nonce bytes, ciphertext bytes, authentication tag bytes, key material, or associated-data values beyond identifier-level metadata appear in logs, audit, or error responses.
