# Test case: v0002.27-registration-rejects-invalid-tag-count

## Implements

`state-registry` — `### Requirement: Executors register one tag and either team-owned or system-owned scope`.

## Intent

Verify the registration failure paths reject both zero tags and multiple tags without creating canonical Executor records.

## Preconditions

State Registry trusts an Executor service identity bound to `team-a`; the tested Executor identifiers do not exist.

## Steps

1. Register `executor-zero-tags` with `team_id = team-a` but omit its tag.
2. Register `executor-many-tags` with `team_id = team-a` and tags `openhands` and `k8s`.
3. Attempt another registration using `team_id = team-b` with the `team-a` identity.
4. Read all identifiers through trusted Gateway context for `team-a`.

## Expected outcome

Zero-tag and multi-tag requests return `400 invalid_tag_count`; the mismatched-team request is rejected; no Executor row is created or reparented; and subsequent same-team reads return the unknown-resource `404` shape.

## Implementation reference

`autotest/state-registry/tests/contracts/02-executor-registration-discovery.spec.ts` — `v0002.27 registration rejects zero-tag and multi-tag bodies with invalid_tag_count`
