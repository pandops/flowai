# Test case: v0002.27-registration-rejects-invalid-tag-count

## Implements

`state-registry` — `### Requirement: Executors register one tag and either team-owned or system-owned scope`.

## Intent

Verify the registration failure paths reject both zero tags and multiple tags without creating canonical Executor records.

## Preconditions

The State Registry is running with no service-auth check; the Executor submits configured `scope`, optional `team_id`, and `authorized_tag` as request data. The tested Executor identifiers do not exist. v0009: the State Registry validates the body's tag count and the canonical team record; the network policy owns the Executor-caller boundary.

## Steps

1. Register `executor-zero-tags` with `scope = team` and `team_id = team-a` but omit the `authorized_tag` field.
2. Register `executor-many-tags` with `scope = team`, `team_id = team-a`, and tags `openhands` and `k8s`.
3. Attempt another registration using `team_id = team-b` with the `team-a` registered Executor identifier.
4. Read all identifiers through trusted Gateway context for `team-a`.

## Expected outcome

Zero-tag and multi-tag requests return `400 invalid_tag_count`; the mismatched-team request is rejected by the canonical record check (the `team_id` body field is validated against the registered Executor record and against the existing `teams` row); no Executor row is created or reparented; and subsequent same-team reads return the unknown-resource `404` shape. The State Registry never authenticates the Executor connection; the network policy owns the caller boundary.
