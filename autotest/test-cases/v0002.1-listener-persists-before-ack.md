# Test case: v0002.1-listener-persists-before-ack

## Implements

`state-registry` — `### Requirement: State Registry is the canonical team-scoped task source`.

## Intent

Verify that listener acknowledgement follows durable task persistence: every ingestion commits a `pending` task with NO lifecycle event appended, `task_type_id` is REQUIRED non-null and same-team constrained, `required_tag` is server-derived from the referenced `task_type.execution_tag`, and the same-team `(team_id, source_system_id, source_id)` triple is durable across restart.

## Preconditions

State Registry and PostgreSQL are running; the listener submits configured `team_id = team-a` and a registered `source-system-a`; `team-a` has one registered task type `tt-a1` with `execution_tag = openhands`; no task exists for `(team-a, source-system-a, JIRA-142)`. v0009: the listener connection is plaintext HTTP; the X-FlowAI-* headers are trusted request data, not authentication.

## Steps

1. Submit task `jira/JIRA-142` with `team_id = team-a`, `source_system_id = source-system-a`, the REQUIRED `task_type_id = tt-a1`, and payload through the listener ingestion API.
2. Observe the successful response and immediately read the task as trusted Gateway context for `team-a`.
3. Restart State Registry and query the returned task identifier as the same team.

## Expected outcome

The listener receives success only after the `pending` task row commits in one transaction with immutable `team_id = team-a`, the REQUIRED non-null same-team `task_type_id = tt-a1`, `required_tag` derived server-side from `tt-a1.execution_tag` (the listener SHALL NOT submit an independently authoritative `required_tag`), `current_state = pending`, no lifecycle event in history, and `tasks.owner_command_id` NULL. The canonical team-owned task remains readable after restart. The FIRST `created` event is Registry-appended only after a later successful claim. The listener ownership check validates that the submitted `team_id` and `source_system_id` reference existing canonical records and that the source system is bound to the same team.

## Implementation reference

`autotest/state-registry/tests/contracts/01-ingestion-persistence.spec.ts` — `v0002.1 listener persists durable pending task before acknowledgement; REQUIRED non-null task_type_id; required_tag is server-derived`
