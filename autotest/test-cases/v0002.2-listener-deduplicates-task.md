# Test case: v0002.2-listener-deduplicates-task

## Implements

`state-registry` — `### Requirement: State Registry deduplicates listener tasks within a team`.

## Intent

Verify idempotent external-task ingestion with REQUIRED non-null same-team `task_type_id`, server-derived `required_tag`, and an empty event history at ingestion (the FIRST `created` event is appended only on a later successful claim).

## Preconditions

State Registry is running; the listener submits configured `team_id = team-a` and a registered `source-system-a`; `team-a` has a registered task type `tt-a1` with `execution_tag = openhands` and a registered source system `source-system-a`; no task exists for deduplication key `(team-a, source-system-a, JIRA-142)`. v0009: the listener connection is plaintext HTTP.

## Steps

1. Submit a task with `team_id = team-a`, `source_system_id = source-system-a`, `source_id = JIRA-142`, REQUIRED `task_type_id = tt-a1`, and payload.
2. Repeat the same team-scoped submission unchanged.
3. Query tasks and events for that key through trusted Gateway context for `team-a`.

## Expected outcome

Both submissions identify the same canonical task with immutable `team_id = team-a` and REQUIRED non-null `task_type_id = tt-a1`; `required_tag` is server-derived from `tt-a1.execution_tag` and the listener SHALL NOT submit an independently authoritative `required_tag`; exactly one task record exists for `(team-a, source-system-a, JIRA-142)`; the projected `current_state` is `pending`; no lifecycle event has been appended at any point; and retrying does not reset task state or history. The canonical record's `team_id` and `source_system_id` are validated against the same-team `teams` and `source_systems` rows; a request whose `team_id` is foreign to the registered source system is rejected without persisting or acknowledging.

## Implementation reference

`autotest/state-registry/tests/contracts/01-ingestion-persistence.spec.ts` — `v0002.2 listener dedup returns the existing canonical pending task for same (team_id, source_system_id, source_id)`
