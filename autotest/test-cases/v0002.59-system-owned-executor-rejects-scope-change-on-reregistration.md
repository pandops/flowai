# Test case: v0002.59-system-owned-executor-rejects-scope-change-on-reregistration

## Implements

`state-registry` — `### Requirement: State Registry enforces Executor scope as a registration-time decision`.

## Intent

Verify that an Executor's `scope` is immutable from registration onward, that a re-registration that names a different scope is rejected without mutation, and that the existing Executor row continues to operate under its original scope.

## Preconditions

- A system-owned Executor has registered with `scope = system`, `team_id = null`, and a registered tag.
- A team-owned Executor has registered with `scope = team`, `team_id = team-a`, and a registered tag.

## Steps

1. Attempt to re-register the system-owned Executor with `scope = team`, `team_id = team-a`, and observe the response.
2. Read the persisted Executor row through `GET /v1/executors/{executor_id}` under trusted Gateway context and confirm `scope = system`, `team_id = null`, and the original tag remain unchanged.
3. Attempt to re-register the team-owned Executor with `scope = system`, `team_id = null`, and observe the response.
4. Read the persisted team-owned Executor row and confirm `scope = team`, `team_id = team-a`, and the original tag remain unchanged.
5. Continue a normal system-owned discovery through the original system-owned Executor and confirm it still returns cross-team summaries.
6. Continue a normal team-owned discovery through the original team-owned Executor and confirm it still returns same-team summaries only.

## Expected outcome

Both re-registrations are rejected without mutation. The persisted rows retain the original scope and `team_id`. Subsequent discovery calls under each Executor return exactly the summaries expected for that Executor's original scope, with no leak in either direction.
