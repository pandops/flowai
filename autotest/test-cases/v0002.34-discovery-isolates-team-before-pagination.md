# Test case: v0002.34-discovery-isolates-team-before-pagination

## Implements

`state-registry` — `### Requirement: State Registry lists pending tasks by exact tag, scoped to the Executor's eligibility`.

## Intent

Verify collection discovery applies the eligibility predicate (same-team and exact-tag) before result shaping, returns only `pending` summaries (no created/running/finished/failed), reveals nothing when only foreign tasks match, and discards a tampered cursor before running any protected query.

## Preconditions

A `team-b` `pending` task has tag `openhands`; no `team-a` task matches; a `team-a` Executor is registered with exactly tag `openhands`.

## Steps

1. Request discovery as the `team-a` Executor with its registered tag, a valid one-item page limit, and an integrity-protected cursor issued under this same scope and filter.
2. Modify the cursor by flipping one byte and resubmit; observe the response and confirm no protected query ran.
3. Read the foreign task directly using the `team-a` Executor identity.

## Expected outcome

The first discovery returns `204` or an empty collection with no foreign row and no count, total, cursor, or pagination metadata that signals the `team-b` task. The tampered cursor is rejected with the same non-revealing `400 invalid_pagination` shape before any protected query runs. The point probe returns the same non-revealing `404` shape as an unknown task, and no state or assignment changes. Discovery summaries never include task payload values, decrypted environment values, secret material, or event history.
