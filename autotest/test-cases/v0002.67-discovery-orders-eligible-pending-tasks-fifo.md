# Test case: v0002.67-discovery-orders-eligible-pending-tasks-fifo

## Implements

`state-registry` — `### Requirement: State Registry lists pending tasks by exact tag, scoped to the Executor's eligibility`.

## Intent

Verify that discovery for an authenticated Executor applies the eligibility predicate first, then orders eligible pending tasks FIFO by `(ingested_at ASC, task_id ASC)`, where `ingested_at` is immutable and `task_id` is the deterministic tie-breaker.

## Preconditions

State Registry and PostgreSQL are running; a team-owned Executor is registered with `team_id = team-a` and a single tag; multiple pending tasks exist for that team and tag, including two tasks with the same `ingested_at`.

## Steps

1. Ingest three pending tasks in order (T-low, T-mid, T-tie-a, T-tie-b) where T-tie-a and T-tie-b share the same `ingested_at`.
2. Call `GET /v1/executors/{executor_id}/tasks?tag=<registered>` and capture the returned summaries.
3. Attempt to mutate `ingested_at` on T-mid through any other state transition.
4. Confirm the same FIFO order holds for a fresh re-discovery call after a no-op.

## Expected outcome

The discovery page returns summaries in `T-low, T-mid, T-tie-a, T-tie-b` order; the eligibility predicate (tag + same team) precedes ordering; pagination and counts apply only to that ordered set; `ingested_at` is immutable and `task_id` is the deterministic tie-breaker; foreign tasks do not appear in the page and reveal no metadata.
