# Test case: v0002.69-same-command-retry-is-idempotent

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

`state-registry` — `### Requirement: State Registry enforces Executor scope as a registration-time decision`.

## Intent

Verify that a same `(task_id, command_id)` retry by the same Executor returns the original `200 claimed` response without appending a second `created` event.

## Preconditions

State Registry, PostgreSQL, and a team-owned Executor are running; one pending task exists for that team and tag.

## Steps

1. Submit `POST /v1/executors/{executor_id}/claim` with `task_id = T-1` and `command_id = C-stable` and observe `200 claimed`.
2. Submit the identical claim with the same `task_id = T-1` and the same `command_id = C-stable`.
3. Read the canonical task event history and confirm exactly one `created` event exists.
4. Read the task and confirm `owner_command_id`, `executor_id`, `resolved_image`, `image_source`, and `claimed_at` match the first response.
5. Submit the same `task_id` with a different `command_id = C-other` and observe the response.

## Expected outcome

Step 1 returns `200 claimed` with the canonical `task`, `environment_id`, `scope_token`, `resolved_image`, `image_source`, and `claimed_at`. Step 2 returns the same `200 claimed` body and appends no new event. Step 3 confirms exactly one `created` event. Step 4 confirms the persisted fields are unchanged from Step 1. Step 5 returns `409 task_already_claimed` because the same `task_id` is already claimed under a different `command_id`.
