# Test case: v0002.16-executor-uses-state-registry-openapi

## Implements

`executor` — `### Requirement: Docker Executor API contract is documented as OpenAPI`.

## Intent

Verify Executor client requests conform to the consolidated State Registry contract.

## Preconditions

The State Registry OpenAPI conformance harness is running with a concrete Executor identity (the platform `executor_<runtime>_<tool>` family; current binding `executor_docker_opehands` documented in AGENTS.md) bound to one immutable `team_id` and one tag.

## Steps

1. Exercise registration, same-team exact-tag FIFO discovery, `POST /v1/executors/{executor_id}/claim`, task and self events, control reads, and team-bound open-environment calls from the Executor.
2. Exercise documented foreign point identifiers and collection discovery outcomes.

## Expected outcome

Every request and response validates against State Registry OpenAPI, including one-team identity for team-owned Executors (`/admin/teams`, `/admin/source-systems`, `/admin/task-types` are reserved to authenticated system-administrator identity only), the explicit `team_id` field on every Executor-emitted task and self event envelope that State Registry verifies against the authenticated Executor team (team-owned) or the parent task's `team_id` (system-owned), FIFO ordering for discovery followed by eligibility and pagination, `command_id` on claim with `owner_command_id` set once and immutable afterward, non-revealing `404` for foreign point identifiers, empty/`204` same-team discovery when only foreign tasks match, and complete scope-token claims; no Router or Env Registry contract is used.
