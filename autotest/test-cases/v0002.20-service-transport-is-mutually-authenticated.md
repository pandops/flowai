# Test case: v0002.20-backend-http-transport-plaintext

## Implements

`state-registry` — `### Requirement: State Registry uses Ingress-terminated transport`.

## Intent

Verify that the State Registry exposes its backend HTTP and WebSocket APIs without TLS or client certificates; that the network policy and the Ingress own the TLS boundary; and that the secure PostgreSQL transport is preserved with server-identity verification.

## Preconditions

The State Registry binary is built without the backend HTTP TLS code path. External HTTPS terminates at the Ingress. Legacy backend HTTP TLS/mTLS configuration keys (`STATE_REGISTRY_TLS_SERVER_CERT`, `STATE_REGISTRY_TLS_SERVER_KEY`, `STATE_REGISTRY_TLS_CLIENT_CA`, `STATE_REGISTRY_TLS_REQUIRE_CLIENT_CERT`) are accepted for compatibility but never read; they produce at most one deprecation warning that names only the keys. The configured AES-256-GCM data key is loaded from a secure configuration source. The configured `STATE_REGISTRY_POSTGRES_TLS_CA` and `STATE_REGISTRY_POSTGRES_TLS_MODE=verify-full` enforce PostgreSQL server-identity verification.

## Steps

1. Start the State Registry with a plain HTTP listener, valid secure PostgreSQL settings, and one or more legacy HTTP mTLS fields.
2. Send every protected HTTP and WebSocket request over plain HTTP without a client certificate.
3. Exercise encrypted PostgreSQL connections with valid and invalid server certificate chains.
4. Verify the legacy TLS env vars are accepted but ignored — startup succeeds even when they reference nonexistent files; certificate paths are never read.
5. Verify that a missing AES-256-GCM data key still fails startup closed.

## Expected outcome

The State Registry serves backend HTTP without TLS, accepts every request over plain HTTP without rejecting for missing transport authentication, and emits at most one deprecation warning naming only the legacy TLS keys. Foreign network peers can copy any `X-FlowAI-*` request-data header, so the deployment network policy is the documented boundary. PostgreSQL server identity and chain failures still fail closed before the State Registry reports ready. The configured AES-256-GCM data key is loaded from a secure configuration source at startup (fail closed if missing). No listener, Executor, or Gateway identity is required at the transport layer; canonical records authorize every protected surface.
