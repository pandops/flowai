# Test case: v0002.72-fifo-tie-break-by-task-id

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

## Intent

Verify that when two pending tasks share the same `ingested_at`, the FIFO order is `(ingested_at ASC, task_id ASC)` where `task_id` is the deterministic tie-breaker.

## Preconditions

State Registry, PostgreSQL, and a team-owned Executor are running; two pending tasks T-a and T-b are ingested in quick succession and intentionally share the same `ingested_at` (verified through direct database observation or a documented ingestion race).

## Steps

1. Confirm both T-a and T-b exist in `current_state = pending` with identical `ingested_at`.
2. From the Executor, discover eligible pending tasks and confirm the order returned is `[T-a, T-b]` where the task_id comparison yields this order.
3. Submit a claim for T-b first and observe `409 older_task_must_be_claimed_first`.
4. Submit a claim for T-a and observe `200 claimed`.
5. Submit a claim for T-b (now the only eligible pending task left) and observe `200 claimed`.

## Expected outcome

The discovery order is `[T-a, T-b]` because `task_id` is the deterministic tie-breaker. The first T-b claim is rejected with `409 older_task_must_be_claimed_first` and no mutation. The T-a claim succeeds. The follow-up T-b claim succeeds with no event other than the second `created` event on T-b.
