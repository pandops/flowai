# Test case: v0002.62-admin-registers-task-type-with-required-execution-tag

## Implements

`state-registry` — ``### Requirement: State Registry owns task-type registration through `/admin/task-types```.

## Intent

Verify that an authenticated system administrator can register a team-owned task type through `POST /admin/task-types` referencing an existing team and a required `execution_tag`.

## Preconditions

State Registry and PostgreSQL are running; a `team-a` already exists; an authenticated system-administrator identity is configured.

## Steps

1. Submit `POST /admin/task-types` with `team_id = team-a`, `execution_tag = openhands`, and an optional `default_image` as the authenticated system administrator.
2. Read the returned canonical task type record and confirm `task_type_id`, `team_id`, `execution_tag`, and optional `default_image`.
3. Submit `POST /admin/task-types` with `team_id` referencing a team that does not exist and observe the response.
4. Submit `POST /admin/task-types` without `execution_tag` and observe the response.
5. Submit `POST /admin/task-types` without an authenticated system-administrator identity and observe the response.

## Expected outcome

The first request returns `201` with the generated immutable `task_type_id`, immutable `team_id = team-a`, the required `execution_tag`, and the optional `default_image`. The non-existent-team, missing-`execution_tag`, and non-admin attempts are each rejected without persisting or partially creating a task type row.
