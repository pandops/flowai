# Test case: v0002.51-task-image-override-wins-over-team-default

## Implements

`state-registry` — `### Requirement: State Registry persists per-task, per-task-type, and per-source-system image overrides`.

`state-registry` — `### Requirement: State Registry resolves the effective image at claim by four-level precedence`.

## Intent

Verify that a per-task `image` override takes precedence over the parent team's `default_image` and over any `task_types.default_image` or `source_systems.default_image`, that the resolved image is persisted and returned in the claim response, and that a later listener retry cannot change the override.

## Preconditions

- Web UI, trusted API Gateway, State Registry, and PostgreSQL are running.
- An authenticated system administrator has created `team-a` through `POST /admin/teams` with the required opaque `default_image = default-A`.
- A `team-a` listener is authorized for `team-a` and one registered source system.
- A `team-a` Executor is registered with `team-a` and one authorized tag.
- `team-a` has a registered task type `tt-a1` whose `execution_tag` matches the Executor's registered tag.

## Steps

1. Through the listener for `team-a`, submit a new task with REQUIRED non-null `task_type_id = tt-a1`, `image` set to a different known opaque reference `override-B`, `source_system_id`, and `source_id`.
2. Re-submit the same `(team_id, source_system_id, source_id)` triple with a third opaque reference `override-C` through the same listener and confirm the response is the existing canonical task with no event append and the original `override-B` preserved.
3. From the same-team Executor, submit `POST /v1/executors/{executor_id}/claim` for the task and capture `resolved_image` and `image_source`.
4. Read the canonical task back through trusted Gateway context and confirm `resolved_image = override-B`, `image = override-B`, `image_source = task_override`, and `tasks.executor_id` plus `tasks.owner_command_id` set.

## Expected outcome

The first submission persists `image = override-B` and returns `201` with the canonical `pending` task. The retry returns `200` with the existing canonical task, `image` still `override-B`, no event appended (still `pending`), and no new task created. The `200 claimed` response contains `resolved_image = override-B` and `image_source = task_override`. The canonical task's `resolved_image` is `override-B`. The team's `default_image` is unchanged and the per-task override wins regardless of its value.
