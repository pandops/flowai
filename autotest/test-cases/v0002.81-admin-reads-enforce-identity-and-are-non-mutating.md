# Test case: v0002.81-admin-reads-enforce-identity-and-are-non-mutating

## Implements

`state-registry` — ``### Requirement: State Registry exposes `GET /admin/tags` as a system-admin-only tag projection``.

`state-registry` — ``### Requirement: State Registry exposes `GET /admin/tasks` as a system-admin-only global task projection``.

## Intent

Verify that `GET /admin/tags` and `GET /admin/tasks` reject every non-system-administrator identity (listener, Executor, API Gateway operator, anonymous) before reading any row, perform no mutation to teams, source systems, task types, tasks, assignments, or events, never expose task payload values, decrypted environment values, secret material, or event history, and never grant authority from cross-team tag equality.

## Preconditions

State Registry and PostgreSQL are running; an authenticated system-administrator identity is configured; `team-a` and `team-b` each have a registered source system and task type with `execution_tag = openhands`; at least one canonical task is `pending` in `team-a`; listener, Executor, and trusted API Gateway identities exist for each team; the test infrastructure exposes a repository/DB-call instrumentation hook that records every protected database or repository call invoked by an admin read endpoint.

## Steps

1. Snapshot the row counts and immutable columns (`team_id`, `team_name`, `default_image`, `task_type_id`, `execution_tag`, `source_system_id`, `tasks.required_tag`, `tasks.current_state`, `tasks.owner_command_id`, `tasks.executor_id`, `tasks.ingested_at`, `tasks.claimed_at`) of every team, source system, task type, task, task event, and audit row. Record the initial DB-call count for the `tasks`, `task_events`, `executor_events`, `environments`, `secrets`, `secret_versions`, `audit_entries`, and `task_control_requests` repositories.
2. As an authenticated listener for `team-a`, call `GET /admin/tags` and `GET /admin/tasks`; observe the responses and confirm the DB-call counters for the protected repositories did not change.
3. As an authenticated team-owned Executor for `team-a`, call `GET /admin/tags` and `GET /admin/tasks`; observe the responses and confirm the DB-call counters for the protected repositories did not change.
4. As an authenticated trusted API Gateway operator for `team-a` (forwarding `X-FlowAI-Team-ID`), call `GET /admin/tags` and `GET /admin/tasks`; observe the responses and confirm the DB-call counters for the protected repositories did not change.
5. As an unauthenticated caller, call `GET /admin/tags` and `GET /admin/tasks`; observe the responses and confirm the DB-call counters for the protected repositories did not change.
6. As an authenticated system administrator, call `GET /admin/tags?limit=0`, `GET /admin/tags?limit=500`, and `GET /admin/tags?limit=abc`; observe the response (non-revealing `400 invalid_pagination`) and confirm no protected repository call ran.
7. As an authenticated system administrator, call `GET /admin/tasks?cursor=<tampered-byte>` and `GET /admin/tasks?cursor=<cursor issued for a different endpoint>` and `GET /admin/tasks?cursor=<cursor issued under a different filter>` and `GET /admin/tasks?cursor=<cursor issued for a different direction>`; observe the response (non-revealing `400 invalid_pagination`) and confirm no protected repository call ran for any of the protected task repositories.
8. As an authenticated system administrator, call `GET /admin/tags` and `GET /admin/tasks` repeatedly against the same canonical state and confirm that no row counts change, no immutable columns change, no event is appended, no task is created or mutated, no environment is read, no secret version is read, and no audit entry is appended.
9. Re-snapshot the same row counts and immutable columns from step 1 and confirm equality.

## Expected outcome

Every non-system-administrator caller in steps 2 through 5 is rejected with `401 unauthenticated` or `403 not_authorized` BEFORE any `task_types`, `tasks`, `task_events`, `executor_events`, `environments`, `secrets`, `secret_versions`, `audit_entries`, or `task_control_requests` row is read — proven by the DB-call counters in steps 2 through 5 recording zero protected repository invocations for every rejection. Steps 6 and 7 are rejected with the same non-revealing `400 invalid_pagination` shape BEFORE any protected query runs — proven by the same DB-call counters recording zero invocations. The authenticated system administrator in step 8 reads paginated global projections without mutating any row. The snapshots from step 1 and step 9 are equal: no team, source system, task type, task, assignment, event, environment, secret, control, or audit row is mutated by any of the reads; no payload, decrypted environment value, secret material, nonce, ciphertext, tag, key material, or event history is exposed; equal `execution_tag` or `required_tag` strings appearing under different `team_id`s grant no cross-team authority.
