# Test case: v0002.81-admin-reads-validate-canonical-record-and-are-non-mutating

## Implements

`state-registry` — `### Requirement: State Registry exposes `GET /admin/tags` as a system-admin-only tag projection``.

`state-registry` — `### Requirement: State Registry exposes `GET /admin/tasks` as a system-admin-only global task projection``.

## Intent

Verify that `GET /admin/tags` and `GET /admin/tasks` apply the canonical record and body validation for every caller — the State Registry does not authenticate the system-administrator identity, so callers that pass data validation are accepted; callers that fail data validation are rejected before any row is read; every read is non-mutating; and no payload, decrypted environment value, secret material, or event history is exposed.

## Preconditions

State Registry and PostgreSQL are running; `team-a` and `team-b` each have a registered source system and task type with `execution_tag = openhands`; at least one canonical task is `pending` in `team-a`; the deployment network policy owns the `/admin/*` caller boundary; the State Registry never authenticates the system-administrator identity; the canonical record shape and the `team_id` filter on every projection authorize the reads. v0009: the State Registry does not perform transport-level authentication.

## Steps

1. Snapshot the row counts and immutable columns (`team_id`, `team_name`, `default_image`, `task_type_id`, `execution_tag`, `source_system_id`, `tasks.required_tag`, `tasks.current_state`, `tasks.owner_command_id`, `tasks.executor_id`, `tasks.ingested_at`, `tasks.claimed_at`) of every team, source system, task type, task, task event, and audit row. Record the initial DB-call count for the `tasks`, `task_events`, `executor_events`, `environments`, `secrets`, `secret_versions`, `audit_entries`, and `task_control_requests` repositories.
2. Call `GET /admin/tags` and `GET /admin/tasks` with valid filters; observe the responses.
3. Call `GET /admin/tags?limit=0`, `GET /admin/tags?limit=500`, and `GET /admin/tags?limit=abc`; observe the response (non-revealing `400 invalid_pagination`) and confirm no protected repository call ran.
4. Call `GET /admin/tasks?cursor=<tampered-byte>` and `GET /admin/tasks?cursor=<cursor issued for a different endpoint>` and `GET /admin/tasks?cursor=<cursor issued under a different filter>` and `GET /admin/tasks?cursor=<cursor issued for a different direction>`; observe the response (non-revealing `400 invalid_pagination`) and confirm no protected repository call ran for any of the protected task repositories.
5. Call `GET /admin/tags` and `GET /admin/tasks` repeatedly against the same canonical state and confirm that no row counts change, no immutable columns change, no event is appended, no task is created or mutated, no environment is read, no secret version is read, and no audit entry is appended.
6. Re-snapshot the same row counts and immutable columns from step 1 and confirm equality.

## Expected outcome

Every caller that fails data validation is rejected with `400 invalid_request` or `400 invalid_pagination` BEFORE any `task_types`, `tasks`, `task_events`, `executor_events`, `environments`, `secrets`, `secret_versions`, `audit_entries`, or `task_control_requests` row is read — proven by the DB-call counters recording zero protected repository invocations for every rejection. The State Registry never authenticates the system-administrator identity; the deployment network policy is the documented `/admin/*` boundary. The snapshots from step 1 and step 6 are equal: no team, source system, task type, task, assignment, event, environment, secret, control, or audit row is mutated by any of the reads; no payload, decrypted environment value, secret material, nonce, ciphertext, tag, key material, or event history is exposed; equal `execution_tag` or `required_tag` strings appearing under different `team_id`s grant no cross-team authority.
