# Test case: v0002.35-foreign-team-claim-is-not-found

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

`state-registry` — `### Requirement: State Registry returns non-revealing not-found for foreign resources`.

## Intent

Verify the claim failure path treats a foreign task identifier and a nonexistent identifier as unknown and performs no claim mutation.

## Preconditions

A `team-b` `pending` task has tag `openhands`; a team-owned `team-a` Executor is registered with that tag; a separate nonexistent task identifier is available.

## Steps

1. Submit `POST /v1/executors/{executor_id}/claim` with `task_id = <team-b task>` and any `command_id` as the `team-a` Executor.
2. Submit the same claim path for the nonexistent identifier using the same identity.
3. Read the `team-b` task and history through trusted Gateway context for `team-b`.

## Expected outcome

Both claim probes return the same non-revealing `404` status and body shape. The `team-b` task remains `pending`, unassigned, and has empty event history with `owner_command_id = null` and `executor_id = null`; no claim mutation, no event append, no audit disclosure, and no timing-visible ownership signal is produced.
