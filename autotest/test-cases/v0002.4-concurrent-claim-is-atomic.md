# Test case: v0002.4-concurrent-claim-is-atomic

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

## Intent

Verify that concurrent eligible Executors cannot claim one task twice and exactly one claim commit succeeds.

## Preconditions

One `team-a` `pending` task has required tag `openhands`; two Executors are each bound to `team-a`, registered with exactly the tag `openhands`, and can discover the task.

## Steps

1. Request same-team discovery from both Executors and retain the same returned `task_id` ordered at the head of the FIFO queue.
2. Send concurrent `POST /v1/executors/{executor_id}/claim` requests with distinct `command_id`s for that `task_id`.
3. Read discovery, the canonical task, and its event history through trusted Gateway context for `team-a`.

## Expected outcome

Exactly one claim returns `200 claimed` and the other returns `409 task_already_claimed`; the task remains owned by `team-a` and has exactly one immutable same-team `executor_id`, one immutable `tasks.owner_command_id` set to the winner's `command_id`, one immutable `tasks.claimed_at`, one immutable `tasks.resolved_image` and `tasks.image_source`; the task's `tasks.team_id` remains immutable; discovery no longer returns the task from the winner's scope; and the ordered event types are exactly `[created]` with one Registry-appended `created` event whose `executor_id` is the winning Executor (non-null) and whose payload meaning encodes `task <task_id> loaded by <executor_id>`. No `dispatched` event exists.
