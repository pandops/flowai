# Test case: v0002.57-system-owned-executor-claims-cross-team-task

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

`state-registry` — `### Requirement: State Registry enforces Executor scope as a registration-time decision`.

## Intent

Verify that a system-owned Executor can claim a `pending` task from any team that matches its tag, that the claim is atomic against both team-owned and system-owned competitors, and that the task disappears from both scopes of discovery after the only winner commits.

## Preconditions

- State Registry and PostgreSQL are running.
- A `team-a` `pending` task exists with the registered tag.
- A system-owned Executor has registered with `scope = system`, `team_id = null`, and the matching tag.
- A team-owned Executor for `team-a` has also registered with `scope = team`, `team_id = team-a`, and the same tag.

## Steps

1. As the system-owned Executor, submit `POST /v1/executors/{executor_id}/claim` with `task_id = <team-a task>` and a fresh `command_id`.
2. Capture the `200 claimed` response and inspect `tasks.executor_id`, `tasks.team_id`, `tasks.owner_command_id`, `tasks.resolved_image`, `tasks.image_source`, `resolved_image`, `image_source`, and the scope token.
3. As the team-owned Executor for `team-a`, attempt claim of the same `task_id` with a different `command_id` and confirm the response is `409 task_already_claimed`.
4. Read the canonical task through trusted Gateway context for `team-a` and confirm `tasks.executor_id = <system-owned executor_id>`, `tasks.owner_command_id = <system-owned claim command_id>`, `tasks.team_id = team-a`, and the FIRST Registry-appended `created` event has non-null `executor_id` equal to the system-owned Executor.
5. As the system-owned Executor, repeat discovery and confirm the task no longer appears.

## Expected outcome

The system-owned Executor wins the atomic claim and receives `200 claimed`. The team-owned competitor receives `409 task_already_claimed`. The canonical task records the assigned `executor_id`, the `command_id` as `tasks.owner_command_id`, and `tasks.team_id = team-a` regardless of the Executor's scope. The scope token binds to the parent task's `team_id = team-a` and to the assigned system-owned Executor identity. The task disappears from both team-owned and system-owned discovery after the winner commits.
