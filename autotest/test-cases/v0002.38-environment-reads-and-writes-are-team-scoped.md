# Test case: v0002.38-environment-reads-and-writes-are-team-scoped

## Implements

`state-registry` — `### Requirement: State Registry stores team-owned environment definitions`.

`state-registry` — `### Requirement: State Registry returns non-revealing not-found for foreign resources`.

## Intent

Verify same-team environment create/read/update/delete behavior and non-revealing denial of foreign environment identifiers.

## Preconditions

Trusted Gateway contexts represent one operator in `team-a` and one in `team-b`; `team-b` owns an environment; the configured AES-256-GCM data key is loaded; encrypt operations are observable through a counter.

## Steps

1. As `team-a`, create an environment with non-secret values and project/task applicability, then read and update it.
2. As `team-a`, attempt to read, update, and delete the `team-b` environment.
3. Compare each foreign response with the same operation on an unknown identifier.
4. Read `team-a` environment and audit collections.

## Expected outcome

Same-team writes retain immutable `team_id = team-a`, return the stable environment identifier, and append team-scoped audits; environment bodies never contain secret plaintext. Every foreign point probe returns the same `404` shape as unknown, changes no environment or secret, performs zero AES-256-GCM encrypt operations on the rejected path, and leaks no ownership detail.
