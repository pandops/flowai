# Test case: v0002.58-system-owned-executor-task-event-envelope-uses-task-team

## Implements

`state-registry` — `### Requirement: State Registry accepts Executor-emitted lifecycle events under the Executor's ownership scope`.

## Intent

Verify that a system-owned Executor's task-event envelope is verified against the parent task's `team_id` rather than against the Executor's immutable service binding (which is null), that a mismatched envelope `team_id` is rejected with `403 team_mismatch`, and that an envelope with the parent task's `team_id` is accepted and projected.

## Preconditions

- A `team-a` task is claimed and assigned to a registered system-owned Executor (`tasks.executor_id = <system-owned executor_id>`, `tasks.owner_command_id = <system-owned command_id>`, `tasks.team_id = team-a`); the FIRST Registry-appended `created` event is already in the history.
- A `running` event has not yet been accepted.

## Steps

1. As the system-owned Executor, post a `running` event to `POST /v1/tasks/{task_id}/events` with envelope `team_id = team-a`, the Executor's `executor_id`, `event_id`, `occurred_at`, `event_type = running`, and a payload.
2. Confirm the response is `202 accepted`, the projected state is `running`, and the appended `task_events` row carries non-null `executor_id = <system-owned executor_id>` and `team_id = team-a`.
3. Attempt a second post with envelope `team_id = team-b` (any other team) for the same `task_id` and confirm the response is `403 team_mismatch` without appending an event or changing projected state.
4. As a different team-owned or system-owned Executor that is not `tasks.executor_id`, attempt to post a `finished` event for the same `task_id` and confirm the response is `403 not_assigned` without appending an event or changing projected state.
5. Inspect the audit entries for the accepted and rejected attempts and confirm `executor_scope = system` is recorded on the accepted attempt only.

## Expected outcome

The first post returns `202 accepted`, projects the task to `running`, and appends one event with the parent task's `team_id`. The second post returns `403 team_mismatch` with no append. The third post returns `403 not_assigned` with no append. Audit entries record `executor_scope = system` for the accepted attempt and the corresponding denial outcomes for the rejected attempts. No `dispatched` event exists; the FIRST `created` event is Registry-appended.
