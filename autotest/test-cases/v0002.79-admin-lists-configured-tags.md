# Test case: v0002.79-admin-lists-configured-tags

## Implements

`state-registry` — ``### Requirement: State Registry exposes `GET /admin/tags` as a system-admin-only tag projection``.

## Intent

Verify that an authenticated system administrator can list every registered task-configuration-derived tag through `GET /admin/tags`; every entry contains EXACTLY `team_id`, `task_type_id`, and `execution_tag` (no `default_image`, no other columns); entries are deterministically ordered by `(team_id ASC, execution_tag ASC, task_type_id ASC)`; pagination follows the documented default and maximum; and the endpoint returns tag data only without exposing payload, secrets, environments, or event history.

## Preconditions

State Registry and PostgreSQL are running; an authenticated system-administrator identity is configured; `team-a` and `team-b` each have one registered task type with `execution_tag = openhands`, and `team-a` additionally has a registered task type with `execution_tag = cron`; listener, Executor, and trusted API Gateway identities exist for each team but none has system-administrator authorization; the test infrastructure exposes a repository/DB-call instrumentation hook that records every protected database or repository call invoked by `GET /admin/tags`.

## Steps

1. As the authenticated system administrator, call `GET /admin/tags` without filters, observe the response, and confirm every entry body contains EXACTLY `team_id`, `task_type_id`, and `execution_tag` with no other columns.
2. As the same administrator, call `GET /admin/tags?tag=openhands` and observe the response.
3. As the same administrator, call `GET /admin/tags?team_id=team-a` and observe the response.
4. As the same administrator, advance the cursor until the page is exhausted and confirm the deterministic ordering across pages.
5. Call `GET /admin/tags` with `limit=0`, `limit=500`, and a malformed `limit`; observe the response (non-revealing `400 invalid_pagination`) and confirm the DB-call counters for the protected repositories did not change.
6. Capture the canonical state of every team, source system, task type, task, event, environment, secret, control, and audit row before and after the read sequence.

## Expected outcome

The first response returns one entry per registered task type whose body contains EXACTLY `team_id`, `task_type_id`, and `execution_tag` (no `default_image`, no other columns), ordered deterministically by `(team_id ASC, execution_tag ASC, task_type_id ASC)`. The tag filter restricts the page to entries with the requested `execution_tag`; the team filter restricts the page to entries of one team. Pagination cursors advance through the global collection; the documented default page size is 50 and the maximum is 200, with `limit` outside the documented range or malformed values rejected with `400 invalid_pagination` BEFORE any row is read (proven by zero protected repository invocations). No payload, decrypted environment value, secret material, or event history is returned; no team, source system, task type, task, assignment, event, environment, secret, control, or audit row is mutated by any read; equal `execution_tag` strings appearing under different `team_id`s grant no cross-team authority.

## Implementation reference

`autotest/state-registry/tests/contracts/10-admin.spec.ts` — `v0002.79 admin lists configured tags with the documented exact allowlist (team_id, task_type_id, execution_tag)`.
