# Test case: v0002.54-system-owned-executor-registers-without-team-id

## Implements

`state-registry` — `### Requirement: Executors register one tag and either team-owned or system-owned scope`.

## Intent

Verify that an Executor can register with `scope = system` and a null `team_id`, that State Registry persists `team_id = NULL` on the `executors` row, and that a system-owned registration with a non-null `team_id` is rejected without persistence.

## Preconditions

- State Registry, PostgreSQL, and the Executor mTLS fixture are running.
- A trusted API Gateway context is verified for any team (registration does not require a team-scoped Gateway context, only an authenticated Executor service identity).

## Steps

1. The Executor issues `PUT /v1/executors/{executor_id}` with `scope = system`, `team_id = null`, one authorized tag, Executor type, runtime metadata, observed `max_capacity`, and observed `running_count`.
2. Read the persisted Executor record through `GET /v1/executors/{executor_id}` under trusted Gateway context and confirm `scope = system`, `team_id = null`, the registered tag, and the recorded `max_capacity` and `running_count`.
3. Attempt a second registration with `scope = system` and a non-null `team_id = team-a`, observing the response and confirming no row was created or changed.
4. Attempt a third registration with `scope = team` and `team_id = null`, observing the response and confirming no row was created or changed.
5. Query the team-scoped audit entries for the accepted registration and confirm `executor_scope = system` and no secret or image content.

## Expected outcome

The first call returns `200` and persists `scope = system` with `team_id = NULL`. The second call returns `400` with no persistence and no audit entry. The third call returns `400` with no persistence and no audit entry. Audit entries record `executor_scope = system` and never contain task payload or image content.
