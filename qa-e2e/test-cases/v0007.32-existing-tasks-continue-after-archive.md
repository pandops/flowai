# Test case: v0007.32-existing-tasks-continue-after-archive

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

## Intent

Lifecycle E2E test verifying each pre-existing task state remains valid after its team is archived.

## Preconditions

- One team owns separate pending, claimed/running, finished, and failed tasks plus distinguishable controls and event history.
- Eligible team and system Executors and authenticated operator read access are running.

## Steps

1. Archive the team.
2. Discover and claim the pre-existing pending task, then advance it through `created`, `running`, and `finished`.
3. Advance the pre-existing running task to `finished`; repeat in a fresh fixture with `failed`.
4. Read finished and failed task histories through REST and WebSocket and exercise every already-authorized control/event operation applicable to an existing task.
5. Attempt a new source-input `POST /v1/tasks` as a positive contrast.

## Expected outcome

Pending discovery and claim, claimed/running completion or failure, controls, ordered events, and terminal REST/WS history behave exactly as before archive; no terminal task reopens or resets. The contrast submission returns `409 team_archived` before persistence and acknowledgement, proving archival gates every task-ingestion request without stopping the lifecycle of existing tasks.
