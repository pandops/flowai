# Test case: v0002.62-admin-registers-task-type-with-required-execution-tag

## Implements

`state-registry` — `### Requirement: State Registry owns task-type registration through`/admin/task-types```.

## Intent

Verify that a system administrator can register a team-owned task type through `POST /admin/task-types` referencing an existing team and a required `execution_tag`.

## Preconditions

State Registry and PostgreSQL are running; a `team-a` already exists; the system-administrator authentication mechanism is an operational concern outside the State Registry contract; the Registry validates the body shape and the canonical records. v0009: the State Registry does not authenticate the system-administrator identity; the deployment network policy owns the `/admin/*` caller boundary.

## Steps

1. Submit `POST /admin/task-types` with `team_id = team-a`, `execution_tag = openhands`, and an optional `default_image`.
2. Read the returned canonical task type record and confirm `task_type_id`, `team_id`, `execution_tag`, and optional `default_image`.
3. Submit `POST /admin/task-types` with `team_id` referencing a team that does not exist and observe the response.
4. Submit `POST /admin/task-types` without `execution_tag` and observe the response.
5. Submit `POST /admin/task-types` without a body that satisfies the validation rules and observe the response.

## Expected outcome

The first request returns `201` with the generated immutable `task_type_id`, immutable `team_id = team-a`, the required `execution_tag`, and the optional `default_image`. The non-existent-team, missing-`execution_tag`, and invalid-body attempts are each rejected with `400` and the documented envelope (non-existent team is `team_unknown`; missing `execution_tag` is `invalid_request`) without persisting or partially creating a task type row. The State Registry never authenticates the system-administrator identity; the network policy is the documented `/admin/*` boundary.
