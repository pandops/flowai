# Test case: v0006.21-team-audit-history

## Implements

`web-ui` — `### Requirement: Web UI renders team audit history`.

## Intent

Verify same-team audit filtering, pagination, attribution, optional download, and secret-safe rendering.

## Preconditions

- A mocked proxy serves the current Web UI HTTP and WebSocket contract for `team-alpha`; no API Gateway process is required.
- The team has more than 100 audit entries including env create/update/delete, secret create/replace/revoke, and task cancellation.
- A distinct `team-beta` audit history exists.

## Steps

1. Open «Аудит» and inspect the initial query, order, count, and page size.
   Verify that the table contains only time, action, actor, affected resource,
   and result; open one entry to inspect its request identifier and safe
   structured details.
2. Filter by launch-parameter action and bootstrap actor/request attribution.
3. Exercise page sizes `10`, `25`, `50`, and `100` and navigate between pages.
4. Inspect secret-related entry details and use download when the fixture declares it supported.
5. Attempt to address a foreign audit entry directly.

## Expected outcome

The default page size is `10`; pagination is deterministic; filters and count
match the same-team query; actor and request attribution are visible; neither
entry detail nor download contains secret plaintext or cryptographic material;
download is absent when unsupported; and foreign audit data and counts are not
revealed. Request identifiers are detail-only, while database identifiers and
cryptographic metadata are absent from both the table and details.

`qa-e2e/web-ui/tests/v0006-mission-control.spec.ts` — `v0006.21 audit filters and renders only useful columns`.
