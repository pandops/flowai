# Test case: v0002.48-task-owned-env-rejects-foreign-task-parent

## Implements

`state-registry` — `### Requirement: State Registry stores team-owned environment definitions`.

## Intent

Verify that submitting an environment definition with a `parent_task_id` belonging to another team is rejected without persisting, without an audit entry, and without any encrypt operation, and is indistinguishable from a foreign environment identifier.

## Preconditions

- Web UI, trusted API Gateway, State Registry, and PostgreSQL are running.
- A `team-b` task exists (foreign team) and has been ingested through the listener path.
- Trusted Gateway context is verified for `team-a` with `team_id = team-a`.
- The configured 256-bit AES-256-GCM data key is loaded.

## Steps

1. Through trusted Gateway context for `team-a`, attempt to create an environment definition whose `parent_task_id` is the `team-b` task identifier.
2. Attempt a follow-up read of the rejected definition through the same trusted team context.
3. List team-owned environments for `team-a` and confirm the rejected row is not present.
4. Inspect any encrypt operations and audit entries during the attempt.

## Expected outcome

The create call returns the same non-revealing `404 environment_unknown_or_unavailable` shape used for every invalid or unavailable case; the read also returns `404 environment_unknown_or_unavailable`; no environment row is persisted; the audit log contains no entry for the rejected attempt; and no encrypt operation is performed (zero AES-256-GCM encryptions for the rejected write).
