# Test case: v0002.33-cross-team-deduplication-is-independent

## Implements

`state-registry` — `### Requirement: State Registry deduplicates listener tasks within a team`.

## Intent

Verify the cross-team edge case where identical external source identities create independent canonical tasks because `team_id` is part of the deduplication key.

## Preconditions

Listener identities are separately bound to `team-a` and `team-b`; `team-a` has a registered task type `tt-a1` referencing `execution_tag = openhands`; `team-b` has a registered task type `tt-b1` referencing `execution_tag = openhands`; each team has its own registered source system (`source-system-a` under `team-a`, `source-system-b` under `team-b`); neither team has a task for the triple below.

## Steps

1. Submit `(team-a, source-system-a, SHARED-33)` with REQUIRED non-null `task_type_id = tt-a1` through the `team-a` listener identity.
2. Submit `(team-b, source-system-b, SHARED-33)` with REQUIRED non-null `task_type_id = tt-b1` through the `team-b` listener identity.
3. Retry both submissions unchanged.
4. Read each returned task and history through trusted Gateway context for its owning team.

## Expected outcome

The first submissions return two different canonical `task_id` values with immutable owning teams, REQUIRED non-null same-team `task_type_id` on each, `current_state = pending`, server-derived `required_tag` from each team's own `task_type.execution_tag`, and no lifecycle event appended at ingestion. Each retry returns its own team's existing task without a duplicate event; neither response or read crosses team ownership.
