# Test case: v0006.15-task-live-streaming-log

## Implements

`state-registry` — `### Requirement: State Registry stores and streams ordered task logs`.

`web-ui` — `### Requirement: Web UI renders a live task execution log`.

## Intent

Verify ordered replay, live continuation, automatic reconnect, and tenant isolation for
task execution logs without rendering Executor events as a task-screen list.

## Preconditions

- A running `team-alpha` task is assigned to one authenticated Executor.
- A distinct `team-beta` task exists.
- Mocked proxy integration mode forwards the browser-selected `team-alpha`.

## Steps

1. Open the `team-alpha` task detail and observe its empty log.
2. Append two chunks from the assigned Executor and observe live delivery.
3. Append another chunk and verify automatic following of the newest line.
4. Interrupt the connection and let the UI reconnect automatically from the last committed cursor.
5. Attempt an unassigned append and a `team-beta` log read.

## Expected outcome

The task screen contains a non-interactive read-only live streaming log with
visually distinct `work` («Работа») and agent-published `reasoning`
(«Рассуждения агента») entries and no buttons, links, menus, input, copy,
manual follow, manual reconnect, clear, or Executor-event list; chunks appear
exactly once in ascending offset order; the viewport follows the newest line;
automatic reconnect resumes without gaps or duplicates;
lifecycle and control events remain separate; unauthorized operations reveal
no log or task existence signal.

`qa-e2e/web-ui/tests/v0006-state-runtime-ui.spec.ts` — `v0006.15 appends live work and agent-published reasoning without log controls`.
