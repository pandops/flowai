# Test case: v0006.25-registered-executors-appear-in-ui

## Implements

`web-ui` — `### Requirement: Web UI renders Executor inventory and detail`.

## Intent

Verify, for both concrete Executor implementations, that registration in
State Registry makes the Executor visible in the configured team's UI
inventory without a browser-side registration action.

## Preconditions

- Run this test in the two isolated Playwright runtime scenarios for
  `executor_k8s_openhands` and `executor_docker_openhands`.
- Each scenario executes after the successful `v0006.24` step and uses the
  same run's captured `team_id`.
- The mocked proxy adapts live Executor reads from the real State Registry and
  does not serve a static Executor list.
- No Executor with the run's unique `executor_id` is registered before the
  test.

## Steps

1. Start the current project's concrete Executor with `scope=team`, the
   captured `team_id`, one authorized execution tag, and free capacity.
2. Wait for its successful `PUT /v1/executors/{executor_id}` registration in
   State Registry and capture the canonical `executor_id` and `executor_type`.
3. Open or refresh «Исполнители» in the Web UI.
4. Wait until the exact captured `executor_id` appears and open its detail.
5. Compare the visible type, team scope, team identity, authorized tag, and
   activity projection with the State Registry record.

## Expected outcome

The K8s project displays one newly registered Executor with
`executor_type=executor_k8s_openhands`; the Docker project displays one newly
registered Executor with `executor_type=executor_docker_openhands`. Each record
belongs to the team created for that project, its detail matches the canonical
State Registry values, and no foreign or cross-project Executor appears. The
UI contains no Executor registration, deletion, rebinding, start, or stop
control.

## Implementation reference

- K8s: `qa-e2e/executor_k8s_openhands/tests/v0006.23-25-mission-control-lifecycle.spec.ts` — the UI opens the captured real `executor_k8s_openhands` registration.
- Docker: `qa-e2e/state-registry/tests/contracts/12-v0005-real-docker-runtime-smoke.spec.ts` — the UI displays the captured real `executor_docker_openhands` registration.
- GREEN evidence uses the same isolated real-runtime commands and results recorded in `v0006.23`; neither mocked proxy fixture seeds an Executor record.
