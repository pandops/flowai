# Test case: v0006.33-revoked-secret-is-absent-from-new-runtimes-and-ui

## Implements

`web-ui` — `### Requirement: Web UI manages scoped launch parameters`.

`state-registry` — `### Requirement: State Registry stores team-owned secrets with immutable versions`.

`state-registry` — `### Requirement: State Registry resolves scoped launch parameters`.

## Intent

Verify end to end, for both concrete Executor implementations, that revoking a
logical secret removes its active reference from State Registry, the reloaded
UI, and every newly started task runtime without exposing plaintext or deleting
immutable history.

## Preconditions

- Run this case in both the `executor_docker_openhands` and
  `executor_k8s_openhands` Playwright projects after `v0006.27` has proved
  that the unique secret reaches a real runtime.
- Reuse each project's real State Registry, PostgreSQL, mocked proxy,
  deterministic OpenHands runtime, team, task type, and concrete Executor.
- The first runtime that proved availability has completed. The plaintext is
  registered with the test redactor and is never attached to reports.
- Revocation SHALL be initiated only through visible Web UI controls. The test
  SHALL NOT revoke or modify the secret through State Registry, the mocked
  proxy, SQL, a fixture, or the Executor.

## Steps

1. Drive a real browser to «Параметры запуска» and locate the redacted
   team-scoped
   `FLOWAI_E2E_SECRET` created by `v0006.27`.
2. Revoke the secret through the confirmation flow and wait for the UI success
   state.
3. Read safe metadata directly from State Registry and verify that the logical
   secret reference is absent from the current definition, revocation and
   definition history were appended, and no plaintext or cryptographic
   material is returned.
4. Reload «Параметры запуска» and verify that the secret is absent from the
   active list while its plaintext-free version and revocation history remain
   available through history views.
5. Only after revocation commits, ingest a new uniquely identified task for
   the same team and task type and wait for the current concrete Executor to
   claim and start a new runtime.
6. In the Docker project, locate the new container by
   `flowai.task_id=<new task_id>` and perform a presence-safe check for
   `FLOWAI_E2E_SECRET`. In the K8s project, perform the same check in the new
   Pod's agent container. Do not print the value in command output.
7. Allow the task to finish and scan UI, responses, browser storage, traces,
   screenshots, reports, audit entries, and service logs for plaintext.

## Expected outcome

Both matrix projects pass independently. State Registry keeps immutable,
plaintext-free history but omits the revoked logical reference from the
current definition and every post-revocation resolution. The active secret is
absent from the UI before and after reload. A newly created Docker container
and a newly created K8s Pod do not contain `FLOWAI_E2E_SECRET`; State Registry
does not decrypt its old versions for those launches. No persisted or emitted
artifact contains the secret plaintext.
No direct backend mutation is used to revoke the secret.
