# Test case: v0007.18-gateway-registers-oidc-team-mapping

## Implements

`api-gateway` — `### Requirement: Gateway owns OIDC-to-canonical-team mappings`

## Intent

Happy-path and conflict test verifying that OIDC mapping registration belongs only to API Gateway.

## Preconditions

- State Registry already owns canonical `team-alpha`; `team-missing` does not exist, and its API can be made unavailable or slower than `endpoint_timeout`.
- `oidc-team-alpha` is not mapped and `oidc-team-existing` is already mapped in API Gateway.

## Steps

1. Register `(issuer, oidc-team-alpha) -> team-alpha` through `POST /admin/v1/oidc-team-mappings` with a valid provider-neutral admin JWT.
2. Repeat the identical request, then attempt conflicting external-ID and canonical-team mappings.
3. Attempt the same mapping with an issuer other than the configured operator OIDC issuer.
4. Attempt mappings to `team-missing` and to `team-alpha` while State Registry is unavailable and while it exceeds `endpoint_timeout`.
5. Log in with `oidc-team-alpha`, read `GET /auth/v1/teams`, and inspect the State Registry team through its public admin API.
6. Assert the exact mapping row and unique constraints in Gateway's schema and the unchanged canonical team row and absence of identity fields in State Registry as supplementary database evidence.

## Expected outcome

Gateway returns `201` for creation, `200` with the same representation for the identical retry, and `409 mapping_conflict` for both conflicts. Another issuer returns `400 invalid_request` without any State Registry call or Gateway read/write. Missing canonical team returns `404 canonical_team_not_found`; dependency outage or timeout returns `503 state_registry_unavailable`. Those failures create no row. Login resolves `team-alpha`; exact database values show one Gateway mapping and no partial row. State Registry's public representation and row still contain only canonical team data and no issuer, OIDC-team, operator, or membership field.
