# Test case: v0006.24-created-team-appears-in-ui

## Implements

`web-ui` — `### Requirement: Web UI renders one selected-team operator surface`.

## Intent

Verify that a team created through the State Registry administrative API is
shown as the configured team in the Web UI without any team-creation action in
the browser.

## Preconditions

- State Registry and PostgreSQL are running with an authenticated
  system-administrator test identity.
- The Web UI and mocked proxy are running, and the proxy can be configured with
  the newly created canonical `team_id` and optional display-only `team_name`.
- No team with the test's unique `team_id` or `team_name` exists before the
  test.

## Steps

1. Call `POST /admin/teams` directly on State Registry with a unique team name
   and required `default_image`; capture the returned `team_id` and require
   `201 Created`.
2. Configure the mocked proxy's current team context with that exact
   `team_id` and returned `team_name`.
3. Open or refresh the Web UI.
4. Inspect the visible team context and browser requests.

## Expected outcome

The Web UI displays the created team's canonical `team_name` as its current
team context and loads only resources for the captured `team_id`. The browser
contains no create, edit, or delete team control and sends no request to
`/admin/teams`. The visible result therefore comes from the State
Registry-created team through the mocked proxy, not from a UI-created or
hard-coded fixture.
