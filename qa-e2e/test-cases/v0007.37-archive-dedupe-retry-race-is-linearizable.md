# Test case: v0007.37-archive-dedupe-retry-race-is-linearizable

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

## Intent

Concurrency E2E test verifying archive serialization against retry of a task persisted before archive.

## Preconditions

- An active team already owns a canonical task for a known `(team_id, source_system_id, source_id)` dedupe key.
- Valid system-admin and source-input identities and controlled real transaction locks are available.
- Read-only task/team assertions and acknowledgement observations are available.

## Steps

1. Hold the dedupe retry after it locks the active team, start archive, release retry, and wait for both requests.
2. In a fresh fixture, hold archive after it locks the team, start the same dedupe retry, release archive, and wait for both requests.
3. Compare the canonical task row, events, audit, response bodies, and acknowledgement observations with their pre-race sentinels.

## Expected outcome

When retry owns the serial order, it returns `200` with the unchanged existing canonical task before archive commits. When archive owns the order, retry returns `409 team_archived` without returning the task representation or acknowledging ingestion. Both orders preserve exactly one byte-for-byte-equivalent canonical task row with no event, state, timestamp, or audit mutation caused by the retry.
