# Test case: v0007.13-browser-bearer-stops-at-gateway

## Implements

`api-gateway` — `### Requirement: Gateway contains browser bearer credentials`

## Intent

Security test verifying that browser authentication secrets do not cross the Gateway-to-State-Registry boundary for REST or WebSocket traffic.

## Preconditions

- A valid browser bearer token is available.
- State Registry captures full child-request and WebSocket-subscription headers.

## Steps

1. Send an authenticated REST request through API Gateway.
2. Open an authenticated WebSocket through API Gateway.
3. Inspect both child contexts received by State Registry.

## Expected outcome

Both child contexts contain canonical operator/team/request headers and no `Authorization` header, bearer token, refresh token, login credential, cookie credential, or equivalent browser authentication secret.

## Implementation reference

- REST: `qa-e2e/api-gateway/tests/v0007-authenticated-rest.spec.ts` — downstream header capture.
- WebSocket: `qa-e2e/api-gateway/tests/v0007-authenticated-websocket.spec.ts` — downstream upgrade header capture for browser subprotocol and non-browser bearer transports.
- Production: `svc/api-gateway/internal/httpapi/server.go` strips `Authorization`, `Cookie`, browser bearer subprotocol, and client `X-FlowAI-*` headers.
