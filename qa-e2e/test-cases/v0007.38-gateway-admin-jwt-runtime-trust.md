# Test case: v0007.38-gateway-admin-jwt-runtime-trust

## Implements

`api-gateway` — `### Requirement: Gateway authenticates mapping administrators without provider coupling`

## Intent

Provider-neutral authentication E2E test verifying API Gateway consumes every runtime admin JWT trust and key-rotation rule.

## Preconditions

- Gateway has valid admin trust and mapping fixtures.
- JWT fixtures vary issuer, audience, algorithm, signature, `kid`, `iat`, `exp`, token age, role pointer, and exact role.
- Admin JWKS supports cached-key success, key rotation, unavailable response, and timeout; Gateway DB and State Registry request observers are available.

## Steps

1. Call mapping registration with wrong issuer, audience, disallowed or symmetric algorithm, invalid signature, missing `iat`, expired token, and age exceeding `admin_token_max_age`.
2. Register successfully with a cached valid key.
3. Rotate JWKS to a new valid key and register successfully after refresh.
4. Present unknown `kid` during JWKS outage and timeout.
5. Assert response-specific errors and exact absence of Gateway mapping reads/writes and State Registry requests for rejected tokens.

## Expected outcome

Every invalid identity or time variant returns `401 invalid_admin_token`; cached and rotated valid asymmetric keys authorize the exact-role request. Unknown `kid` plus outage or timeout returns `502 admin_identity_provider_unavailable`, never falls back to an unrelated cached key, and performs no mapping read/write or State Registry request.

## Implementation reference

- E2E: `qa-e2e/api-gateway/tests/v0007-keycloak-compatibility.spec.ts` — production Gateway mapping registration with a Keycloak-issued administrator JWT.
- GREEN: complete Keycloak 26.6.3 file passed on 2026-08-28.
