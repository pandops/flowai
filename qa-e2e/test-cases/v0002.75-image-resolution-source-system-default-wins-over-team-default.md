# Test case: v0002.75-image-resolution-source-system-default-wins-over-team-default

## Implements

`state-registry` — `### Requirement: State Registry resolves the effective image at claim by four-level precedence`.

## Intent

Verify the third level of image precedence: when `tasks.image` and `task_types.default_image` are null but `source_systems.default_image` is non-null, the claim response records `resolved_image = source_systems.default_image` and `image_source = source_system_default`.

## Preconditions

State Registry and PostgreSQL are running; a source system `ss-default` is registered for `team-a` with a non-null `default_image`; the source-system default differs from `teams.default_image`; `task_types.default_image` and `tasks.image` are null; one pending task references `source-system-default` and a registered task type with no `default_image`; a team-owned Executor is registered.

## Steps

1. Submit `POST /v1/executors/{executor_id}/claim` with the task's `task_id` and a fresh `command_id`.
2. Read the claim response and confirm `resolved_image = source_systems.default_image` and `image_source = source_system_default`.
3. Read the canonical task and confirm `resolved_image` and `image_source` are persisted at this level.
4. Read the canonical task event history and confirm exactly one `created` event.

## Expected outcome

The image resolves at the third level of precedence because the per-task override and the task type default are both null and the source-system default applies. The claim response and the persisted task carry `resolved_image` and `image_source` consistently. No `dispatched` event is appended.
