# Test case: v0007.35-team-name-writer-races-are-atomic

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

## Intent

Concurrency E2E test verifying every writer of unique `team_name` resolves races atomically.

## Preconditions

- Production State Registry runs against PostgreSQL with valid system-admin authentication.
- The fixture can coordinate real handler transactions without directly creating final team state.
- Read-only database assertions are available.

## Steps

1. Race two `POST /admin/teams` requests that use the same new `team_name`.
2. In a fresh fixture, race creation of a new team against update of an existing team to the same new name.
3. In another fixture, race updates of two different teams to the same new name.
4. Repeat each race with reversed lock acquisition and inspect responses, canonical rows, unique constraints, and audit.

## Expected outcome

For every writer pair and lock order, exactly one operation commits the unique name and every loser returns `409 team_conflict`. There is no duplicate, partially created, or partially updated team row; losing updates preserve all prior field values, and audit identifies only committed mutations.
