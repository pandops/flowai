# Test case: v0006.32-deleted-env-is-absent-from-new-runtimes-and-ui

## Implements

`web-ui` — `### Requirement: Web UI manages scoped launch parameters`.

`state-registry` — `### Requirement: State Registry stores immutable launch-parameter revisions`.

`state-registry` — `### Requirement: State Registry resolves scoped launch parameters`.

## Intent

Verify end to end, for both concrete Executor implementations, that deleting
an ordinary env variable removes it from State Registry's current projection,
the reloaded UI, and every newly started task runtime while preserving history.

## Preconditions

- Run this case in both the `executor_docker_openhands` and
  `executor_k8s_openhands` Playwright projects after `v0006.26` has proved
  that the unique variable reaches a real runtime.
- Reuse each project's real State Registry, PostgreSQL, mocked proxy,
  deterministic OpenHands runtime, team, task type, and concrete Executor.
- The first runtime that proved availability has completed. Runtime absence
  is checked only in a newly claimed task created after deletion commits.
- Deletion SHALL be initiated only through visible Web UI controls. The test
  SHALL NOT delete or modify the variable through State Registry, the mocked
  proxy, SQL, a fixture, or the Executor.

## Steps

1. Drive a real browser to «Параметры запуска» and locate the team-scoped
   `FLOWAI_E2E_VISIBLE` variable created by `v0006.26`.
2. Delete the variable through the confirmation flow and wait for the UI
   success state.
3. Read the definition directly from State Registry and verify that the key is
   absent from its current projection and that the next immutable revision
   records its removal.
4. Reload «Параметры запуска» and verify that the variable is absent from the
   active list while its removal remains visible in «История изменений».
5. Only after the deletion commit, ingest a new uniquely identified task for
   the same team and task type and wait for the current concrete Executor to
   claim and start a new runtime.
6. In the Docker project, locate the new container by
   `flowai.task_id=<new task_id>` and run a presence-safe environment check for
   `FLOWAI_E2E_VISIBLE`. In the K8s project, run the same check in the newly
   created Pod's agent container. Require the command to distinguish an absent
   key from an empty value.
7. Allow the task to finish and reload the UI once more.

## Expected outcome

Both matrix projects pass independently. State Registry's current definition
and every post-deletion resolution omit `FLOWAI_E2E_VISIBLE`; immutable history
retains the prior value and its removal revision. The active variable is absent
from the UI before and after reload. A newly created Docker container and a
newly created K8s Pod do not contain the key at all. The test does not inspect
an already-running runtime and therefore cannot pass because environment is
immutable after process start.
No direct backend mutation is used to remove the variable.
