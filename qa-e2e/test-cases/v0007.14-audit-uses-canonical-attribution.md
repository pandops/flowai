# Test case: v0007.14-audit-uses-canonical-attribution

## Implements

`api-gateway` — `### Requirement: Gateway provides canonical audit attribution context`

## Intent

Security test verifying that State Registry audit records attribute mutations to canonical token-bound operator/team context rather than browser input.

## Preconditions

- A valid token identifies `operator-1` and `team-alpha`.
- A `team-alpha` task accepts a control request and State Registry exposes its canonical audit record through a supported API.

## Steps

1. Submit the control request with forged browser operator, `team-beta`, team-name, and request-ID headers while the canonical team carries `team_name=Alpha Team`.
2. Read the resulting control record and audit event through API Gateway.
3. Repeat with another canonical team whose `team_name` is absent.

## Expected outcome

State Registry records both mutations and audit attribution with the canonical operator, stable `team_id`, and Gateway-generated request ID. It receives canonical `Alpha Team` only for the first team and omits `X-FlowAI-Team-Name` for the unnamed team; forged identifiers are absent and display-name presence never determines ownership.
