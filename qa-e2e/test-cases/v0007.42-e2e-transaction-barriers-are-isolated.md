# Test case: v0007.42-e2e-transaction-barriers-are-isolated

## Implements

`state-registry` — `### Requirement: State Registry test coordination is isolated from production behavior`

## Intent

Container E2E test proving that deterministic concurrency coordination controls real State Registry transactions only in explicitly configured E2E runtime and exposes no production business surface.

## Preconditions

- The normal and E2E-configured State Registry instances use the same built service image.
- The E2E instance has a dedicated test-network bind address, random non-empty bearer token, and explicit integer `barrier_timeout_ms` in inclusive range `1000..60000`.
- Public API identities, PostgreSQL read-only assertions, and all fixtures needed by `v0007.31`, `v0007.35`, `v0007.36`, `v0007.37`, and `v0007.39` are available.

## Steps

1. Start the image without test-control configuration and prove that no test-control listener or route is reachable while public readiness succeeds.
2. Start separate containers with test control enabled but missing its bind address, token, or `barrier_timeout_ms`; then use timeout with wrong type, `999`, and `60001`, requiring startup/readiness failure for each. Prove boundary values `1000` and `60000` start successfully and expose the listener.
3. Start the valid E2E instance; call `POST /test-control/v1/barriers` with a missing or wrong bearer and with an unknown barrier name, requiring the OpenAPI-defined rejection without any public API or database change.
4. For each allowlisted point `team_archive_after_lock`, `task_ingest_after_team_lock`, `task_claim_after_team_lock`, `team_default_image_update_after_lock`, and `team_name_write_after_constraint_before_commit`, arm one barrier through `POST /test-control/v1/barriers`, trigger the matching real public request, long-poll `GET /test-control/v1/barriers/{barrier_id}?wait_ms=30000` until `state=reached`, start its competing real public request, release through `POST /test-control/v1/barriers/{barrier_id}/release`, and verify both public results and committed rows.
5. While one matching handler is paused, send a second matching request; prove only the first is captured and the second follows ordinary database locking and production logic.
6. Attempt duplicate arm, release before arrival, and second release; require the exact conflict contracts, then read the terminal observation, delete it once with `204`, require `404 barrier_not_found` from every later GET, release, or DELETE for that identifier, and prove a later unrelated request does not pause.
7. In separate runs, cancel the paused public request, let a reached barrier expire, and initiate graceful shutdown; require at-most-once cleanup, observe the applicable cancellation/timeout/shutdown signal, and prove a restarted or subsequent request is not captured by the consumed barrier.

## Expected outcome

Normal runtime exposes no test-control listener. Valid enabled configuration always exposes the complete isolated contract; invalid enabled configuration never becomes ready. Only the isolated listener with its exact bearer can control one allowlisted, one-shot barrier. Every controlled request still authenticates and executes through its real public handler and PostgreSQL transaction; the harness can establish both serial orders required by the concurrency cases. Exactly one matching request is captured. A terminal observation remains readable until its one successful cleanup DELETE, after which every operation returns `404`. Invalid, duplicate, reused, cancelled, timed-out, or shutdown-interrupted controls cannot mutate unrelated business data, choose a business response, bypass authorization, deadlock a later request, or leave an armed barrier behind.
