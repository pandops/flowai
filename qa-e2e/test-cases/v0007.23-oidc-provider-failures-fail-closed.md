# Test case: v0007.23-oidc-provider-failures-fail-closed

## Implements

`api-gateway` — `### Requirement: Gateway obtains canonical OIDC teams from OIDC provider`

`api-gateway` — `### Requirement: Gateway enforces deterministic membership freshness`

## Intent

Failure-path test verifying bounded fail-closed behavior for every OIDC endpoint contacted during startup, login, validation, and membership refresh.

## Preconditions

- A controllable OIDC fixture can independently fail or exceed `endpoint_timeout` for discovery, token exchange, JWKS refresh, and UserInfo.
- `membership_max_age=0` requires provider refresh for every token issue.
- State Registry records attempted child requests; read-only Gateway database assertions are available.

## Steps

1. Start Gateway while discovery is unavailable and observe listener readiness.
2. Run callback while token exchange is unavailable.
3. Present a validly shaped token with unknown `kid` while JWKS refresh is unavailable.
4. Complete login or request a working token while configured `source=userinfo` is unavailable.
5. Repeat each contacted-endpoint case with a response slower than `endpoint_timeout`.
6. Assert that no failed attempt creates a session, membership observation, derived access, or working-token record in Gateway's database.

## Expected outcome

Discovery failure prevents Gateway readiness. Every runtime outage or timeout returns `502 oidc_provider_unavailable` with `{code,message,request_id}`, returns no provider body or credential, issues no working token, creates no State Registry request, and commits none of the named Gateway rows. An unknown `kid` is never accepted with a stale unrelated key.
