# Test case: v0007.39-archive-pending-claim-race-preserves-both

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

## Intent

Concurrency E2E test verifying archival never prevents the valid claim of a task already pending before archive.

## Preconditions

- Each fresh active-team fixture owns an oldest eligible pending task whose image resolution reaches team-default precedence.
- A valid system administrator and eligible authenticated team-owned and system-owned Executors are available.
- The fixture can hold the real archive or claim transaction after team-row locking; read-only team, task, assignment, event, and image assertions are available.

## Steps

1. With the team-owned Executor, hold claim after it locks the team, start archive, release claim, and wait for both public requests.
2. In a fresh team-owned fixture, hold archive after it locks the team, start claim, release archive, and wait for both public requests.
3. Repeat both controlled commit orders with the system-owned Executor and a fresh team/task per cell.
4. Retry claim and archive requests to exercise their idempotency/conflict behavior in each scope.
5. Read canonical team, task, assignment, first event, resolved image, and audit rows after each scope/order cell.

## Expected outcome

For both team-owned and system-owned Executors, claim succeeds whether it commits before or after archive; archive succeeds and preserves one non-null `archived_at`. Exactly one immutable scope-correct Executor assignment, `owner_command_id`, and first `created` event exist, and the task is no longer pending. `resolved_image` and `image_source` reflect the canonical values visible inside the successful claim transaction. Retries create no duplicate assignment or event, neither operation loses the other's state, and no deadlock occurs.
