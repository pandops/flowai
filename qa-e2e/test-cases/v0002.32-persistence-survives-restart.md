# Test case: v0002.32-persistence-survives-restart

## Implements

`state-registry` — `### Requirement: State Registry persists team ownership in normalized 3NF PostgreSQL`.

## Intent

Verify durable team-owned State Registry state survives restart with immutable ownership, team-scoped source-system deduplication, immutable claim assignment, ordered events, Executor observations, environments, logical secrets and versions, controls, and audit entries. Exact 3NF structure remains an integration-level migration assertion.

## Preconditions

State Registry and PostgreSQL are running; listener, two Executors, and trusted Gateway context are authorized for `team-a`; both Executors each register `team_id = team-a` (referencing an existing team) and one tag `openhands`; a `team-a` environment, logical secret, and local-AES-256-GCM ciphertext secret version exist; no task exists for `(team-a, source-system-a, JIRA-310)`; `team-a` has a registered task type `tt-a1` with `execution_tag = openhands`.

## Steps

1. Submit a `team-a` task with `source_system_id = source-system-a`, `source_id = JIRA-310`, REQUIRED `task_type_id = tt-a1` (so `required_tag` is server-derived); from `executor-1` claim the oldest eligible pending task with `command_id = C-1` and capture `200 claimed`; append valid ordered `running` and `failed` task events from `executor-1` carrying envelope `team_id = team-a` (verified by State Registry against the authenticated Executor team), `executor_id = executor-1`; append one self event with non-null `executor_id` and `team_id = team-a`; create a team-scoped cancel control; and read its audit entry.
2. Restart State Registry while preserving PostgreSQL.
3. Resend the original `(team-a, source-system-a, JIRA-310)` listener submission.
4. Read the task, task events, Executor and self events, environment, secret and version metadata, control, and audit entry through trusted Gateway context for `team-a`.

## Expected outcome

The retry returns the existing team-owned task without another `created` event and with no `pending` row created. Every resource retains immutable `team_id = team-a`. The task's `ingested_at` is unchanged. `tasks.executor_id = executor-1`, `tasks.owner_command_id = C-1`, `tasks.claimed_at`, `tasks.resolved_image`, and `tasks.image_source` survive restart and are immutable thereafter. Task history remains strictly ordered with the FIRST Registry-appended `created` row carrying non-null `executor_id = executor-1` (payload meaning `task <task_id> loaded by executor-1`) and the Executor-owned `running` and `failed` rows preserving their submitted `team_id = team-a` and non-null assigned `executor_id`; `executor_events.executor_id` remains non-null with `team_id = team-a`; environment and logical `secrets`/`secret_versions` relationships survive with opaque `key_id` and `key_version`; control and audit records remain team-scoped and plaintext-free. No `dispatched` event exists.
