# Test case: v0006.26-env-persists-and-reaches-docker-container

## Implements

`web-ui` — `### Requirement: Web UI manages scoped launch parameters`.

`state-registry` — `### Requirement: State Registry resolves scoped launch parameters`.

## Intent

Verify end to end, for both concrete Executor implementations, that an
ordinary team-wide env variable added in the Web UI is persisted in State
Registry, remains visible in the UI, and is available inside the task runtime.

## Preconditions

- Run this case in both the `executor_docker_openhands` and
  `executor_k8s_openhands` Playwright projects after
  `v0006.24-created-team-appears-in-ui` and
  `v0006.25-registered-executors-appear-in-ui`.
- Reuse each project's real State Registry, PostgreSQL, deterministic
  OpenHands runtime, team, task type, and concrete Executor setup from the
  existing Docker and K8s successful-runtime tests named in `v0006.23`.
- The mocked proxy adapts live launch-parameter reads and writes between the
  Web UI and the real State Registry; it does not persist or inject the test
  variable itself.
- The deterministic task runtime can remain in `running` long enough for the
  harness to inspect its container before allowing successful completion.
- The variable does not exist before the browser journey. Test setup SHALL NOT
  create it through State Registry, the mocked proxy, a fixture, SQL, or the
  Executor; its only creation path in this case is the Web UI form.

## Steps

1. Drive a real browser to «Параметры запуска» and choose team scope using
   visible UI controls.
2. In the create-variable form, enter `FLOWAI_E2E_VISIBLE` into the editable
   required «Имя ключа» field and enter a unique non-secret value; submit once
   and require the UI success state.
3. Read the applicable team-scoped launch-parameter definition directly from
   State Registry and verify that the exact key/value pair and a new immutable
   revision are stored for the captured `team_id`.
4. Reload «Параметры запуска» and verify that the same ordinary variable name
   and value are still displayed and editable.
5. Ingest one uniquely identified task for the team's existing task type and
   let `executor_docker_openhands` discover, claim, and start its container.
6. In the Docker project, locate the running container by
   `flowai.task_id=<captured task_id>` and run
   `printenv FLOWAI_E2E_VISIBLE` inside it. In the K8s project, locate the Pod
   by the same canonical label and run the same command in its agent container.
7. Allow the deterministic OpenHands branch to finish and verify the task
   reaches `finished` in State Registry and the Web UI.

## Expected outcome

Both matrix projects pass independently. The UI write produces one
team-scoped State Registry mutation and immutable revision; direct State
Registry reading and the reloaded UI show the same ordinary key/value pair.
The key equals the exact value entered by the operator and is not generated or
renamed by the UI, mocked proxy, or State Registry.
Each concrete Executor opens the resolved launch parameters for its captured
task, starts exactly one runtime, and `printenv FLOWAI_E2E_VISIBLE` returns the
unique value inside the Docker container and the K8s Pod respectively. The
value is not supplied by the test process, mocked proxy, Executor
configuration, image, or inspection command. Each task then displays
`finished` in the UI with `created → running → finished`, proving that env
injection did not replace or bypass execution.
No direct backend mutation is used to create the variable.
