# Test case: v0017.1-runtime-services-use-owned-container-images

## Implements

- `state-registry` — `### Requirement: State Registry runs from its service-owned image`
- `executor` — `### Requirement: Concrete Executors run from service-owned images`

## Intent

Cross-service E2E test verifying that images are built from the current source before testing, every test uses a fresh real-service container or Pod, all requests target only its exposed port, and no real FlowAI service runs as a host binary or in-process replacement.

## Preconditions

- A Docker-compatible runtime and a group-readable/writeable configured runtime socket are available.
- A k3d test cluster can load locally built images.
- The suite-level setup can build immutable State Registry, Docker OpenHands Executor, and K8s OpenHands Executor image references from the current checkout.
- Test-only external-system fakes are available; they do not replace the real FlowAI service under test.

## Steps

1. Run the suite-level image build and pass the three resolved immutable image references to Playwright.
2. Run test `v0017.1 / state-registry uses a fresh owned-image container`; start fresh PostgreSQL and State Registry containers, discover the published State Registry port, exercise its public API only through that port, inspect the running image identity, and complete teardown.
3. Run test `v0017.1 / docker executor uses a fresh owned-image container`; preflight the configured runtime socket, start a fresh Docker Executor container with only the socket's supplemental GID and exact socket mount, address its published port, execute one task, inspect image/mount/user/group identity, and complete teardown.
4. Run test `v0017.1 / k8s executor uses a fresh owned-image pod`; load the prebuilt image into the run-scoped shared k3d cluster, create a fresh namespace and Executor Pod, address only its test-exposed port, execute one task, inspect the Pod image identity, and delete the namespace. The root E2E runner deletes the one shared cluster after all suites finish.
5. Run the static E2E guard that rejects imports or commands capable of starting real State Registry or Executor host binaries.
6. Force one assertion failure in each lifecycle fixture and verify teardown still removes the test-owned service container or Pod and its owned network/namespace resources.

## Expected outcome

All three tests use the images built from the current checkout. Each test creates a new service instance, sends requests only to its published container or Pod port, verifies the exact image identity, and removes all owned runtime resources. Docker Executor is non-root, non-privileged, and receives only the validated socket mount plus supplemental socket GID. No E2E path starts or contacts a real FlowAI service on the host.

GREEN evidence:

`npm --prefix qa-e2e/containerized-runtime-services test` returned `4 passed (3.2m)` with no skipped test. It started two fresh State Registry containers with separate TLS-PostgreSQL dependencies, inspected a Docker Executor container launched from the immutable ID, loaded the K8s image into a fresh k3d cluster and addressed the fresh Pod only through `kubectl port-forward`, then removed every owned container, network, namespace, Pod, imported tag, and cluster.

Shared-cluster follow-up evidence: the v0017 K8s Pod test and the existing K8s Executor registration test ran sequentially against the same externally owned cluster and passed (`1 passed (32.4s)` and `1 passed (1.2m)`). Suite teardown removed owned namespaces while preserving the shared cluster between suites; root teardown then removed the cluster, and `k3d cluster list` was empty afterward.
