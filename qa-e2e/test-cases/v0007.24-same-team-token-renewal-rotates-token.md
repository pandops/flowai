# Test case: v0007.24-same-team-token-renewal-rotates-token

## Implements

`auth` — `### Requirement: Each working token has one immutable active team`

`auth` — `### Requirement: Gateway owns secure browser session lifecycle`

## Intent

Happy-path and revocation test verifying same-team token renewal, fresh membership enforcement, server-side session ownership, and logout.

## Preconditions

- An OIDC login resolves `operator-1` to `team-alpha` and creates a Gateway server-side session.
- `membership_max_age=0`; the provider fixture records membership refreshes.
- Read-only Gateway database assertions can inspect session and token metadata without exposing credential plaintext.

## Steps

1. Issue a `team-alpha` working token through `POST /auth/v1/token`.
2. Issue another token for the same team and compare verified claims.
3. Remove the granting provider membership and attempt another token issue.
4. Restore membership, issue a token, call `DELETE /auth/v1/session`, then retry team listing and token issue with the expired session cookie.
5. Assert exact session status, membership-observation timestamps, token identifiers, and absence of plaintext provider credentials in Gateway's database.

## Expected outcome

The first two tokens retain `team-alpha` but have distinct `jti`, `iat`, and `exp`; every issue triggers a provider refresh. Revoked membership returns `403 team_not_accessible` and no token. Logout returns `204`, deletes or irreversibly revokes the server-side session, expires the cookie, and subsequent session requests return `401`. Provider credentials never appear in browser responses or database plaintext.
