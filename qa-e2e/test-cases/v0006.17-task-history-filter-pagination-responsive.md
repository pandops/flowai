# Test case: v0006.17-task-history-filter-pagination-responsive

## Implements

`web-ui` — `### Requirement: Web UI renders searchable paginated task history`.

`web-ui` — `### Requirement: Web UI does not create tasks`.

## Intent

Verify combined task-history filters, deterministic pagination, configured page sizes, task navigation, and adaptive table-to-card rendering.

## Preconditions

- A mocked proxy serves the current Web UI HTTP and WebSocket contract for `team-alpha`; no API Gateway process is required.
- The team has more than 100 deterministically ordered tasks spanning all lifecycle states and periods.
- Fixture task `task-alpha-running` has searchable canonical metadata.

## Steps

1. Open task history and inspect the initial request, rows, count, page size, and creation actions.
   Verify that the table exposes only task identifier, task type, status,
   Executor, time, and duration/completion columns, despite extra fixture API
   fields.
2. Apply a search matching `task-alpha-running`, status `running`, and period `month`.
3. Select page sizes `25`, `50`, `100`, then restore `10`; move forward and backward one page.
4. Open the matching task and navigate back.
5. Repeat the filtered view at tablet and mobile viewport widths.
6. Configure an empty result, then a recoverable backend-contract failure, and retry.

## Expected outcome

The initial page size is `10`; only `10`, `25`, `50`, and `100` are offered;
filters, count, URL, requests, and rows remain consistent; paging never
duplicates or skips a task; no task-create, launch, clone, or retry-as-new
action exists; a row opens task detail; desktop uses a table while mobile uses
readable task cards without horizontal clipping; and empty, error, and retry
states preserve the safe filter state. Internal team ownership, deduplication,
request, cursor, and scope-token fields are absent from table columns and
mobile cards.
