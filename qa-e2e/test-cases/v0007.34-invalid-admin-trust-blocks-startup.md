# Test case: v0007.34-invalid-admin-trust-blocks-startup

## Implements

`api-gateway` — `### Requirement: Gateway authenticates mapping administrators without provider coupling`

`state-registry` — `### Requirement: State Registry authenticates team administrators without local accounts`

## Intent

Configuration E2E test verifying API Gateway and State Registry reject incomplete or unsafe provider-neutral admin trust before opening a listener.

## Preconditions

- Production API Gateway and State Registry images are available to the container-native E2E harness.
- The harness can supply isolated configuration variants and observe process exit, readiness, bound ports, and sanitized startup logs.
- A valid provider-neutral admin trust configuration is available as a positive control.

## Steps

1. Start each production image with valid admin issuer, audience, asymmetric algorithm allowlist, JWKS URL, RFC 6901 role-claim pointer, positive `admin_jwks_timeout`, positive `admin_token_max_age`, and bounded clock skew; verify readiness and one authorized admin request.
2. Restart each image once per missing required trust field.
3. Restart each image with zero and negative `admin_jwks_timeout`, then zero and negative `admin_token_max_age`.
4. Restart each image with a symmetric-only algorithm configuration and with an empty asymmetric allowlist.
5. Inspect exit status, listener/readiness probes, and sanitized logs for every invalid variant.

## Expected outcome

The positive controls become ready and authorize the exact-role request. Every invalid variant exits non-zero before opening its HTTP listener or reporting readiness, emits a safe field-specific configuration error without tokens, keys, URLs containing credentials, or other secrets, and performs no database migration or application read/write.
