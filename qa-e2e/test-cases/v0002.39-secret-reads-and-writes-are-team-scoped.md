# Test case: v0002.39-secret-reads-and-writes-are-team-scoped

## Implements

`state-registry` — `### Requirement: State Registry stores team-owned secrets with immutable versions`.

`state-registry` — `### Requirement: State Registry returns non-revealing not-found for foreign resources`.

## Intent

Verify logical secrets and immutable versions remain inside the owning environment's team for writes and metadata reads.

## Preconditions

`team-a` and `team-b` each own an environment; trusted Gateway context represents a `team-a` operator; the configured AES-256-GCM data key is loaded; encrypt operations are observable through a counter.

## Steps

1. Create a secret under the `team-a` environment and replace its value.
2. Read the logical secret and version metadata through `team-a` Gateway context.
3. Attempt create, replacement, deletion, secret metadata read, and version metadata read using `team-b` environment, secret, or version identifiers.
4. Compare foreign responses with unknown identifiers and inspect local encrypt operations and `team-a` audits.

## Expected outcome

One same-team logical secret and multiple immutable local-AES-256-GCM-encrypted versions with opaque `key_id` / `key_version` metadata are created and readable as metadata without plaintext. Every foreign point probe returns the unknown-resource `404` shape, performs zero AES-256-GCM encrypt operations, stores no secret/version, changes no prior version, and discloses no foreign audit entry.
