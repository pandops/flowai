# Test case: v0002.80-admin-lists-all-tasks-with-states

## Implements

`state-registry` — `### Requirement: State Registry exposes`GET /admin/tasks` as a system-admin-only global task projection``.

## Intent

Verify that the canonical record of every task summary across every team is available through `GET /admin/tasks`; every entry contains EXACTLY `task_id`, `team_id`, `task_type_id`, `source_system_id`, `source_id`, `required_tag`, `current_state`, `owner_command_id`, `executor_id`, `ingested_at`, and `claimed_at` (no `image`, no `resolved_image`, no `image_source`, no `project_id`, no `environment_id`, no task payload); ordering is deterministic `(ingested_at DESC, task_id DESC)`; pagination follows the documented default and maximum; and the endpoint returns summary fields only without exposing payload, secrets, environments, or event history.

## Preconditions

State Registry and PostgreSQL are running; `team-a` and `team-b` each have a registered source system and task type; tasks are ingested across both teams with mixed `current_state` values (`pending`, `created`, `running`, `finished`, `failed`); some tasks are claimed and others are unclaimed; the deployment network policy owns the `/admin/*` caller boundary — the State Registry validates the body and the canonical records and never authenticates the system-administrator identity. v0009: the State Registry does not perform transport-level authentication; the network policy prevents non-admin callers.

## Steps

1. Call `GET /admin/tasks` without filters, observe the response shape, ordering, and total entries, and confirm every entry body contains EXACTLY the eleven required fields with no `image`, no `resolved_image`, no `image_source`, no `project_id`, no `environment_id`, and no task payload.
2. Call `GET /admin/tasks?state=pending`, `GET /admin/tasks?team_id=team-a`, `GET /admin/tasks?tag=openhands`, and `GET /admin/tasks?task_type_id=tt-a1`; observe each response and confirm the exact allowlist.
3. Combine filters and verify that all four filters must match exactly when combined.
4. Advance the cursor until the page is exhausted and confirm the deterministic `(ingested_at DESC, task_id DESC)` ordering across pages.
5. Call `GET /admin/tasks` with `limit=0`, `limit=500`, and a malformed `limit`; observe the response (non-revealing `400 invalid_pagination`) and confirm the DB-call counters for the protected repositories did not change.
6. Verify that no entry contains `image`, `resolved_image`, `image_source`, `project_id`, `environment_id`, task `payload`, decrypted environment values, secret material, ciphertext, nonce, tag, key material, or event history.
7. Capture the canonical state of every team, source system, task type, task, assignment, event, environment, secret, control, and audit row before and after the read sequence.

## Expected outcome

The first response returns one entry per canonical task across every team whose body contains EXACTLY `task_id`, `team_id`, `task_type_id`, `source_system_id`, `source_id`, `required_tag`, `current_state`, `owner_command_id`, `executor_id`, `ingested_at`, and `claimed_at` (no `image`, no `resolved_image`, no `image_source`, no `project_id`, no `environment_id`, no task payload), ordered deterministically by `(ingested_at DESC, task_id DESC)`. The optional exact-match filters (`team_id`, `state`, `tag`, `task_type_id`) each narrow the page; combining filters requires all to match. Pagination cursors advance through the global collection; the documented default page size is 50 and the maximum is 200, with `limit` outside the documented range or malformed values rejected with `400 invalid_pagination` BEFORE any row is read (proven by zero protected repository invocations). The response never includes task payload values, decrypted environment values, secret material, nonce bytes, ciphertext bytes, authentication tag bytes, key material, or event history; the response never mutates any team, source system, task type, task, assignment, event, environment, secret, control, or audit row; equal `required_tag` strings appearing under different `team_id`s grant no cross-team authority; "all" tasks means a traversable, paginated global collection whose response is never unbounded. This admin projection does NOT change the canonical `Task` resource returned by claim, by same-team Gateway reads, by same-team Executor discovery, or by any other non-admin endpoint.
