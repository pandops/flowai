# Test case: v0007.25-concurrent-mapping-registration-is-atomic

## Implements

`api-gateway` — `### Requirement: Gateway owns OIDC-to-canonical-team mappings`

`api-gateway` — `### Requirement: Gateway exposes versioned auth and mapping APIs`

`api-gateway` — `### Requirement: Gateway authenticates mapping administrators without provider coupling`

## Intent

Concurrency and authorization test verifying provider-neutral administrator authentication, mapping idempotency, conflict handling, and database atomicity.

## Preconditions

- Provider-neutral admin JWT fixtures cover valid configured issuer/audience/role, missing role, wrong audience, invalid signature, unknown `kid`, and an operator working token; the separately configured admin JWKS endpoint can fail or exceed `admin_jwks_timeout`.
- State Registry owns `team-alpha` and `team-beta`.
- Gateway initially contains none of the attempted mappings, and read-only test connections can inspect exact rows and constraints.

## Steps

1. Call `POST /admin/v1/oidc-team-mappings` with every invalid or unauthorized token variant.
2. Present unknown `kid` while admin JWKS fails and while it exceeds `admin_jwks_timeout`.
3. Send concurrent identical valid requests mapping `oidc-team-alpha` to `team-alpha`.
4. In a fresh fixture, send concurrent valid requests mapping the same external identifier to different canonical teams.
5. In another fresh fixture, send concurrent valid requests mapping different external identifiers to the same canonical team.
6. Log in through the winning mapping and read `GET /auth/v1/teams`.
7. Assert exact Gateway rows, unique constraints, transaction results, and unchanged State Registry team rows.

## Expected outcome

Invalid admin authentication returns `401 invalid_admin_token`; authenticated non-admin and operator tokens return `403 insufficient_admin_role`. Admin JWKS outage and timeout return `502 admin_identity_provider_unavailable`, never accept the unknown `kid`, and cause no database or State Registry access. Identical concurrent requests yield one `201`, remaining `200` responses, and one logical row. Each conflicting race has one winner and `409 mapping_conflict` losers with no partial row. Login resolves only the winner, Gateway constraints match the one-to-one contract, and State Registry rows are unchanged.

## Implementation reference

- Integration: `svc/api-gateway/internal/store/mappings_integration_test.go` exercises concurrent atomic registration.
- E2E boundary: `qa-e2e/api-gateway/tests/v0007-keycloak-compatibility.spec.ts` exercises create plus idempotent retry through the public API.
