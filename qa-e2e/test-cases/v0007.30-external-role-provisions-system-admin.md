# Test case: v0007.30-external-role-provisions-system-admin

## Implements

`api-gateway` — `### Requirement: Gateway authenticates mapping administrators without provider coupling`

`state-registry` — `### Requirement: State Registry authenticates team administrators without local accounts`

## Intent

Authorization E2E test verifying that exact external role assignment provisions a system administrator and role removal revokes the next request without local administrator state.

## Preconditions

- The provider-neutral admin identity fixture issues valid JWTs for the configured issuer, audience, key, and role-claim pointer.
- API Gateway and State Registry expose their supported system-admin operations.
- Read-only Gateway and State Registry database assertions are available.

## Steps

1. Issue otherwise valid admin JWTs with the role absent, case-changed, prefixed, suffixed, under the wrong claim pointer, and with a wrong claim type; call Gateway mapping and State Registry team create, update, and archive operations.
2. Assign exact external role `flowai-system-admin`, issue a new JWT, and repeat every operation.
3. Remove the role, retain the old bounded JWT, issue a new JWT without the role, and retry before and after the old token reaches `admin_token_max_age`.
4. Search both service-owned schemas for administrator accounts, administrator membership, or locally assigned role rows and inspect audit attribution.

## Expected outcome

Every lookalike, absent, misplaced, or wrongly typed role returns `403 insufficient_admin_role`; the exact role authorizes mapping and all three team operations. After removal, the newly issued token is rejected immediately; the previously issued stateless token works only before the earlier of `exp` or `admin_token_max_age` and is then rejected. Neither service stores or exposes a local administrator account or role-assignment API or row, while audit records the externally authenticated administrator subject without treating it as team membership.
