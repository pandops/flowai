# Test case: v0006.19-executor-inventory-detail

## Implements

`web-ui` — `### Requirement: Web UI renders Executor inventory and detail`.

## Intent

Verify Executor navigation, inventory, detail parameters, Executor events, active-task links, tenant isolation, and absence of management controls.

## Preconditions

- A mocked proxy serves the current Web UI HTTP and WebSocket contract for `team-alpha`; no API Gateway process is required.
- `executor-alpha` is a team-scoped active Executor with two assigned running tasks and events.
- A system-scoped Executor eligible for the team and a foreign `team-beta` Executor also exist.

## Steps

1. Open «Исполнители» from the primary navigation.
2. Inspect inventory rows/cards and open `executor-alpha`.
   Verify that inventory columns are limited to identifier, concrete type,
   scope, authorized tag, activity, and available capacity even when fixture
   responses carry additional protocol fields.
3. Verify canonical parameters, scope, tag, health/activity, events, and active tasks.
4. Open an active task and return.
5. Open the visible system-scoped Executor, then attempt to address the foreign Executor directly.

## Expected outcome

Inventory and detail use configured-team data only; `executor-alpha` shows its
canonical parameters, ordered events, and exactly its current tasks; each task
link opens task detail; the system-scoped record is read-only; no register,
delete, stop, or rebind control exists; and the foreign Executor returns the
same non-revealing unavailable state as an unknown identifier. Internal
timestamps, team identifiers, and transport fields are not inventory columns.
