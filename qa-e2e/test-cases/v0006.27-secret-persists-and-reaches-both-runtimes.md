# Test case: v0006.27-secret-persists-and-reaches-both-runtimes

## Implements

`web-ui` — `### Requirement: Web UI manages scoped launch parameters`.

`state-registry` — `### Requirement: State Registry stores team-owned secrets with immutable versions`.

`state-registry` — `### Requirement: State Registry resolves scoped launch parameters`.

## Intent

Verify end to end, for both concrete Executor implementations, that a
team-wide secret created in the Web UI is stored as an opaque logical secret
and immutable version, remains redacted in the UI, and is available only
inside the assigned task runtime.

## Preconditions

- Run this case in both the `executor_docker_openhands` and
  `executor_k8s_openhands` Playwright projects after
  `v0006.24-created-team-appears-in-ui` and
  `v0006.25-registered-executors-appear-in-ui`.
- Reuse each project's real State Registry, PostgreSQL, deterministic
  OpenHands runtime, team, task type, and concrete Executor setup from the
  existing Docker and K8s successful-runtime tests named in `v0006.23`.
- The mocked proxy forwards secret operations but never stores, logs, returns,
  or injects plaintext itself.
- The test harness registers the unique secret value with its redactor before
  submission and may compare captured command output in memory, but SHALL NOT
  attach or print the plaintext on success or failure.
- The logical secret does not exist before the browser journey. Test setup
  SHALL NOT create it through State Registry, the mocked proxy, a fixture,
  SQL, or the Executor; its only creation path in this case is the Web UI form.

## Steps

1. Drive a real browser to «Параметры запуска», choose team scope using visible
   UI controls, and create a logical secret by
   entering `FLOWAI_E2E_SECRET` into the editable required «Имя ключа» field
   and a unique plaintext value into the secret-value field.
2. Require the UI success state, then verify that the dialog closes and no UI
   element, browser storage entry, trace, screenshot, or subsequent response
   contains the submitted plaintext.
3. Read the logical secret and immutable version metadata directly from State
   Registry; verify its team ownership, version number, and opaque reference
   without decrypting or returning plaintext or cryptographic material.
4. Reload the UI and verify that the secret name, redacted state, replace
   action, and version history appear while its value does not.
5. Ingest one uniquely identified task for the team's task type and let the
   current project's concrete Executor claim and start its runtime.
6. In the Docker project, locate the running container by
   `flowai.task_id=<captured task_id>` and read `FLOWAI_E2E_SECRET` inside it.
   In the K8s project, locate the Pod by the same canonical label and read the
   variable inside its agent container.
7. Compare each captured value in memory with the submitted secret, redact the
   command output, allow execution to finish, and inspect UI, service logs,
   Playwright artifacts, and audit records for plaintext leakage.

## Expected outcome

Both matrix projects pass independently. State Registry stores one logical
secret and one encrypted immutable version for the correct team; ordinary
reads, history, audit, mocked-proxy traffic, and UI expose only identifier and
version metadata. The secret is absent from browser storage, screenshots,
traces, reports, service logs, and error text. The assigned Docker container
and K8s agent container each receive the exact unique secret value for their
captured task, while no other runtime or task receives it. Both tasks finish
with `created → running → finished`, and every persisted or emitted test
artifact remains redacted. The runtime key equals the exact key entered by the
operator and is not generated or renamed by the UI, mocked proxy, or State
Registry.
No direct backend mutation is used to create the secret.

## Implementation reference

- K8s and Docker use the same test files and GREEN commands recorded in `v0006.26`.
- Both secret creations originate from visible Mission Control controls, direct State Registry reads remain opaque, and the generated plaintext is asserted only in memory inside the captured Pod/container. The Docker secret test disables trace, video, and screenshots; the K8s project retains artifacts only on failure, and the final GREEN run retained none.
