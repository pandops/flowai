# Test case: v0007.2-invalid-or-stale-token-rejected

## Implements

`auth` — `### Requirement: Gateway validates operator and team claims`

## Intent

Failure-path test verifying issuer, algorithm, key, signature, audience, expiry, operator/team shape, and stale OIDC-team-to-platform-team access checks before proxying.

## Preconditions

- State Registry records all child requests and subscriptions.
- Test tokens can be issued with wrong issuer, disallowed algorithm, unknown `kid`, invalid signature, wrong audience, past expiry, missing operator, multiple team identities, and a formerly valid team whose granting OIDC team has been removed.

## Steps

1. Send protected REST requests with each invalid token variant.
2. Attempt a WebSocket upgrade with the stale-team token.
3. Inspect State Registry observations.

## Expected outcome

Every request/upgrade returns `401 invalid_working_token` or `403 team_not_accessible` as applicable, and State Registry observes no child REST request or WebSocket subscription.
