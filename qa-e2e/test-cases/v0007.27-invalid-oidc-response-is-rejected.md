# Test case: v0007.27-invalid-oidc-response-is-rejected

## Implements

`api-gateway` — `### Requirement: Gateway obtains canonical OIDC teams from OIDC provider`

## Intent

Security test verifying that authorization-response and ID Token validation fail closed before creation of Gateway or State Registry authority.

## Preconditions

- A controllable provider fixture can return mismatched or missing `state`, mismatched `nonce`, wrong issuer or audience, disallowed algorithm, unknown `kid`, invalid signature, expired token, and token outside configured clock skew.
- It can return a standard provider error callback containing untrusted `error_description`.
- Read-only Gateway database assertions and State Registry request observations are available.

## Steps

1. Start login and complete the callback once for every invalid authorization response or ID Token variant.
2. Complete callbacks with standard provider `error`, matching `state`, and hostile `error_description`, then with mismatched `state`.
3. Attempt callbacks that contain both `code` and `error`, then neither, while carrying matching `state`.
4. Inspect each HTTP status and `{code,message,request_id}` envelope.
5. Assert exact absence of browser session, membership observation, derived access, and working-token rows in Gateway's database and absence of State Registry child requests.

## Expected outcome

Every invalid identity variant returns `401 invalid_oidc_identity`, creates no cookie or authority row, and makes no State Registry request. Both-present and neither-present callback forms fail the formal `oneOf` contract with `400 invalid_request`. A valid-state provider error is handled without reflecting `error_description`, credentials, claims, or provider bodies; mismatched state is rejected. Unknown `kid` is never accepted with an unrelated cached key.
