# Test case: v0002.24-failed-lifecycle

## Implements

`state-registry` — `### Requirement: State Registry defines the task lifecycle as pending then created then running then terminal`.

`state-registry` — ``### Requirement: State Registry appends the first `created` event atomically on successful claim``.

## Intent

Verify the failure path projects `pending -> created -> running -> failed` and preserves the claiming Executor's failure details.

## Preconditions

State Registry and PostgreSQL are running; a listener and an Executor are each bound to `team-a`; the Executor is registered with the task's exact tag; trusted Gateway context for `team-a` can read tasks and events.

## Steps

1. Submit a new `team-a` task through the listener and retain its `task_id`; the task is `current_state = pending` with empty event history.
2. From the same-team Executor, claim the oldest eligible pending task with `command_id` and observe `200 claimed`.
3. Post `running` with envelope `team_id = team-a` that State Registry verifies against the authenticated Executor team, non-null assigned `executor_id`, and a strictly later ordering tuple.
4. Post `failed` with `team_id = team-a`, the same Executor, and a strictly later tuple.
5. Read the task and history through trusted Gateway context for `team-a`.

## Expected outcome

State Registry verifies `team_id = team-a` against the authenticated Executor team for every Executor-emitted write. The task retains immutable `team_id = team-a`, immutable `tasks.executor_id = claiming_executor`, `tasks.owner_command_id`, and projects through exactly `[created, running, failed]`. The Registry-appended `created` row has non-null `executor_id` equal to the claiming Executor; the Executor-emitted `running` and terminal `failed` rows have non-null `executor_id = claiming_executor`, submitted `team_id` equal to the task team, preserved payloads, preserved ordering tuples, and no `finished` event exists; no `dispatched` event exists.

`qa-e2e/state-registry/tests/contracts/04-lifecycle-events.spec.ts` — `v0002.24 failure path projects [created, running, failed] without a finished event`
