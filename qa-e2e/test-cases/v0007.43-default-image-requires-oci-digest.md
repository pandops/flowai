# Test case: v0007.43-default-image-requires-oci-digest

## Implements

`state-registry` — `### Requirement: State Registry requires a mutable team default image`

## Intent

API and database E2E test proving that team creation and update share one provider-neutral OCI digest-reference contract and preserve accepted values verbatim.

## Preconditions

- An authenticated system administrator and separate active and archived team fixtures are available.
- The State Registry OpenAPI document is available to the contract test.
- Read-only access can inspect exact `teams.default_image` values.

## Steps

1. Validate the OpenAPI schema and create a team with a valid `sha256` digest reference.
2. Update active and archived teams with valid references whose algorithm names include allowed letters, digits, and separators and are not `sha256`.
3. Attempt create and update with a tag-only reference, whitespace, missing repository, missing or repeated `@`, missing algorithm, missing `:`, empty encoded digest, and invalid algorithm or digest characters.
4. Read every affected team through the canonical point-read API and inspect exact database values.

## Expected outcome

OpenAPI and server validation accept the same algorithm-qualified OCI reference grammar without pinning one digest algorithm. Accepted references are persisted and returned byte-for-byte. Every tag-only or malformed value returns `400 invalid_request` before mutation; rejected create leaves no team row, rejected update leaves the prior `default_image` unchanged, and archived-team validation is identical to active-team validation.
