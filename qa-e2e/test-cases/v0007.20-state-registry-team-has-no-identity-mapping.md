# Test case: v0007.20-state-registry-team-has-no-identity-mapping

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

## Intent

Boundary test verifying that canonical team registration remains independent from OIDC and operator membership.

## Preconditions

- An authenticated system administrator exists.
- API Gateway and State Registry are running with their supported administrative APIs.
- API Gateway has an authenticated system-administrator mapping-registration identity.

## Steps

1. Create `Alpha Team` with a valid required default image through State Registry.
2. Attempt a second team creation through State Registry with otherwise valid canonical fields plus OIDC issuer, subject, OIDC-team, and operator-membership fields.
3. Repeat canonical team creation with the rejected request's `team_name` and no identity-provider fields; require success, proving that the rejected request created no team.
4. Record API Gateway's outbound State Registry requests, then register an OIDC-team-to-`Alpha Team` mapping through the API Gateway administrative API and resolve that mapping through the OIDC login flow.
5. Repeat `POST /admin/teams` for `Alpha Team` with only canonical fields and require the normal duplicate-name rejection.

## Expected outcome

The supported requests create exactly the two canonical teams and return only State Registry-owned fields. The request carrying identity-provider or membership fields returns HTTP 400 and performs no mutation. Gateway registration and OIDC resolution succeed; recorded Gateway-to-Registry traffic contains no OIDC identifier or operator-membership payload and performs no team mutation. The final duplicate request receives the same canonical duplicate-name rejection.
