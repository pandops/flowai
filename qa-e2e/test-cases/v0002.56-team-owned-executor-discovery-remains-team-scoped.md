# Test case: v0002.56-team-owned-executor-discovery-remains-team-scoped

## Implements

`state-registry` — `### Requirement: State Registry lists pending tasks by exact tag, scoped to the Executor's eligibility`.

## Intent

Verify that introducing the system-owned scope does not weaken the team-owned Executor's isolation: a team-owned Executor still sees only same-team `pending` tasks matching its tag, and the existence of system-owned Executors does not change what a team-owned Executor can discover. Discovery is metadata-only and never includes task payload values, decrypted environment values, secret material, or event history.

## Preconditions

- State Registry and PostgreSQL are running.
- `team-a` and `team-b` each have at least one `pending` task with the same tag, each referencing a REQUIRED non-null same-team `task_type_id` whose `execution_tag` matches the Executor's registered tag.
- A team-owned Executor for `team-a` has registered with `scope = team`, `team_id = team-a`, and the shared tag.
- A system-owned Executor has also registered with the same tag.

## Steps

1. As the team-owned Executor for `team-a`, call `GET /v1/executors/{executor_id}/tasks?tag=<registered_tag>` and inspect the response.
2. Confirm every returned `TaskSummary` carries `team_id = team-a` and `task_type_id` referencing a same-team task type.
3. Confirm the response does not include summaries for `team-b` even though a system-owned Executor registered for the same tag exists.
4. Confirm the response is byte-equivalent to a discovery made before the system-owned Executor registered.
5. Confirm the response is metadata-only and never includes task payload values, decrypted environment values, secret material, or event history.

## Expected outcome

The team-owned Executor only sees `team-a` `pending` summaries. The presence of a system-owned Executor with the same tag does not change this result. Foreign-team summaries are not present, and no count, cursor, or pagination metadata reveals the foreign team's existence. The payload is delivered only in a successful `200 claimed` response for the assigned task.
