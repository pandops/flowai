# Test case: v0002.68-claim-succeeds-only-on-oldest-eligible-task

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

## Intent

Verify that `POST /v1/executors/{executor_id}/claim` succeeds only when the requested `task_id` is the oldest currently eligible `pending` task for the authenticated Executor; that the claim atomically appends the FIRST `created` lifecycle event with non-null `executor_id = claiming_executor` and a payload encoding `task <task_id> loaded by <executor_id>`; and that older-task attempts return `409 older_task_must_be_claimed_first` with no mutation.

## Preconditions

State Registry, PostgreSQL, and a team-owned Executor with `team_id = team-a` and one tag are running; two pending tasks T-older (older `ingested_at`) and T-newer exist for `team-a` and the registered tag.

## Steps

1. From the team-owned Executor, submit `POST /v1/executors/{executor_id}/claim` with `task_id = T-newer` and `command_id = C-n` and observe the response.
2. Read the canonical task T-newer back through trusted Gateway context and confirm `current_state = created`, `executor_id = <claimant>`, `owner_command_id = C-n`, `resolved_image` present, `image_source` set, and `claimed_at` set.
3. Read the canonical task event history for T-newer and confirm exactly one event of `event_type = created` with `executor_id = <claimant>` and a payload whose string content encodes `task <task_id> loaded by <executor_id>`.
4. Read T-older and confirm it remains `current_state = pending` with no event and `owner_command_id` still NULL.
5. From the same Executor, submit a follow-up claim for T-older and observe success.
6. Attempt the same claim with a third Executor after T-older has already been claimed and observe the response.

## Expected outcome

The first claim for T-newer returns `409 older_task_must_be_claimed_first` with no mutation, no event, and no assignment change. T-newer remains pending. The follow-up claim for T-older succeeds with `200 claimed`, sets `owner_command_id` to the supplied `command_id`, sets `executor_id`, appends the first `created` event with non-null `executor_id`, and projects the task to `created`. No `dispatched` event is appended. The retry by the third Executor against T-older after T-older is already claimed returns `409 task_already_claimed`.
