# Test case: v0007.28-system-admin-updates-active-team

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

`state-registry` — `### Requirement: State Registry requires a mutable team default image`

## Intent

Happy-path and validation E2E test verifying that a system administrator can change only active-team display metadata and default image without changing ownership identity or prior image resolution.

## Preconditions

- State Registry contains active `team-alpha` with `team_name=Alpha`, a digest-bearing default image, owned resources, and one task already claimed through team-default image precedence.
- A valid external admin JWT with exact role `flowai-system-admin`, non-admin JWTs, and read-only State Registry database assertions are available.

## Steps

1. Call `PATCH /admin/teams/team-alpha` separately with `team_name` only, `default_image` only, and both fields; then repeat against an archived team.
2. Read the canonical team and existing owned resources through supported APIs, then claim a new task whose image resolution reaches team-default precedence.
3. Attempt separate updates as a non-admin, against a missing team, and with an empty body, `team_id`, empty or tag-only `default_image`, duplicate active or archived `team_name`, and OIDC identity fields.
4. Race two valid updates to the same fields, then race a valid update against archive; read the returned versions and final canonical row.
5. Assert exact team, resource, old-task, new-task, and audit values through read-only database connections as supplementary evidence.

## Expected outcome

Each valid partial or combined update returns `200` with unchanged `team_id` and only the requested mutable values changed, for active and archived teams. Existing ownership links and resources are unchanged; the previously claimed task retains its original `resolved_image`, while the later claim uses the latest committed team default. Missing-team, unauthorized, empty, or closed-schema-invalid updates return the specified `400`, `403`, `404`, or `409` error without partial mutation. Concurrent updates are linearizable with no mixed row; update versus archive preserves one serial order and never loses `archived_at` or an acknowledged update.
