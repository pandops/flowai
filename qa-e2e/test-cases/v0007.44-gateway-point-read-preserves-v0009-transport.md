# Test case: v0007.44-gateway-point-read-preserves-v0009-transport

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

## Intent

Cross-service E2E test proving canonical-team point read preserves the accepted credential-free Gateway backend transport and does not introduce an implicit service JWT.

## Preconditions

- API Gateway and State Registry run on the E2E backend network with distinguishable active and archived canonical teams.
- Gateway has no State Registry service token, signing key, issuer, audience, or JWKS configuration.
- A valid system-admin bearer and malformed, expired, and insufficient-role admin bearers are available.

## Steps

1. Register a Gateway OIDC-team mapping and list mapped teams, capturing the Gateway-to-State-Registry point-read request.
2. Require that backend `GET /internal/v1/teams/{team_id}` request to contain no `Authorization` header or other replacement Gateway credential and verify the canonical point-read response is consumed.
3. Call separate `GET /admin/teams/{team_id}` with the valid system-admin bearer, then with each invalid admin bearer; prove none reaches the internal route or receives anonymous fallback.
4. Attempt collection `GET /admin/teams` and inspect State Registry and Gateway configuration and database state.

## Expected outcome

Gateway validates mappings and refreshes active or archived presentation through the credential-free backend point read. The system-admin bearer also succeeds. Invalid presented admin bearers return `401` or `403` without falling back to credential-free Gateway treatment. No collection route, Gateway service credential configuration, service-key persistence, or replacement JWT trust exists, and canonical team data remains owned only by State Registry.
