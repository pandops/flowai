# Test case: v0007.31-archive-ingestion-race-is-linearizable

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

## Intent

Concurrency E2E test verifying the atomic boundary between canonical-team archive and source-input task ingestion.

## Preconditions

- Active teams and authenticated system-admin and source-input identities are available.
- The test fixture can hold the team-row lock inside either real State Registry transaction without bypassing production handlers.
- Read-only database assertions and acknowledgement observations are available.

## Steps

1. Hold ingestion after it locks the active team, start archive concurrently, release ingestion, and wait for both public requests.
2. In a fresh team, hold archive after it locks the team, start ingestion concurrently, release archive, and wait for both public requests.
3. Race concurrent archive retries with a new ingestion, then retry both a rejected source submission and a source ID persisted before archive.
4. Read the canonical team and tasks and correlate every response with committed rows.

## Expected outcome

When ingestion owns the serial order, it commits and acknowledges exactly one task before archive commits; that task remains processable. When archive owns the order, it commits `archived_at` and ingestion rejects without acknowledgement or a task row. Concurrent archive retries return one logical archived state. After archive, retry of either a rejected source ID or a previously persisted source ID returns `409 team_archived`; any earlier row remains unchanged. No execution produces an acknowledged task without a row, a task committed after visible `archived_at`, or a duplicate row.
