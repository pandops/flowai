## Implements

`web-ui` — `### Requirement: Web UI renders task detail and executor navigation`.

`web-ui` — `### Requirement: Web UI shows canonical task source identifiers`.

## Intent

Verify task metadata, lifecycle timeline, resolved launch values, pending semantics, cancellation placement, and navigation to the assigned Executor.

## Preconditions

- A mocked proxy serves the current Web UI HTTP and WebSocket contract for `team-alpha`; no API Gateway process is required.
- One pending task has never been claimed.
- One running task is assigned to `executor-alpha`, has canonical source identifiers, resolved ordinary env values, and logical secret references.

## Steps

1. Open the pending task and inspect its status and lifecycle timeline.
2. Open the running task and inspect status, cancellation control, canonical metadata, resolved env values, secret references, timeline, and live log placement.
3. Verify the Executor identity is interactive and activate it.
4. Navigate from Executor detail back to the originating task.

## Expected outcome

The pending task has no fabricated event before claim; the running task shows
`source_system_id`, `source_id`, `task_type_id`, all returned ordinary env
names and values, and secret references without plaintext; lifecycle events
follow `created → running`; the live log precedes the bounded lifecycle/control
feed; cancellation is adjacent to status and has no separate block; and the
Executor link opens `executor-alpha`, whose active-task link returns to the
same task.
