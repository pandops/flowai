# Test case: v0002.40-open-environment-verifies-every-team-bound-claim

## Implements

`state-registry` — `### Requirement: State Registry opens environments only for assigned same-team Executors`.

`state-registry` — `### Requirement: State Registry uses local AES-256-GCM authenticated encryption for secret values`.

## Intent

Verify environment opening succeeds only for a fully matching signed scope token and fails closed before local AES-256-GCM decryption for every mismatched binding.

## Preconditions

A `team-a` task is claimed by `executor-a` (assigned `tasks.executor_id`, immutable `tasks.owner_command_id`) and references an applicable `team-a` environment and an AES-256-GCM-encrypted secret; a valid token includes `team_id`, `project_id` (required claim; null only when the canonical environment has no project scope), `task_id`, `environment_id`, `executor_id`, expected `audience` (literal `state-registry.environment.open`), `key_id`, `issued_at`, and unexpired `expiry` (`expiry > issued_at`, `expiry - issued_at <= 5 minutes`); `issued_at <= server_now + 30 seconds`; the protected-header `kid` equals the payload `key_id`; the algorithm is an allow-listed HMAC (`HS256`/`HS384`/`HS512`); the configured AES-256-GCM data key is loaded; and the AES-256-GCM decrypt operation counter is observable.

## Steps

1. Open the environment with the claiming Executor via `GET /v1/environments/{environment_id}/open?task_id={task_id}` carrying the compact three-part scope token in the `X-FlowAI-Scope-Token` request header (no scope-token fields in the body).
2. Repeat with invalid signature, algorithm outside the allow-listed HMAC set, protected-header `kid` not equal to payload `key_id`, missing or non-`scope-token+json` `typ`, audience, premature-beyond-skew `issued_at`, `expiry` not strictly later than `issued_at`, `expiry` more than five minutes after `issued_at`, team, project, task, environment, executor, and assignment values one at a time, including a query `task_id` that is absent, malformed, or does not match the payload `task_id` claim or the canonical claimed task.
3. Repeat using a validly signed token that names a real `team-b` environment.
4. Inspect the local AES-256-GCM decrypt operation counter and audit entries.

## Expected outcome

Only the canonical same-team request decrypts and returns authorized env-style values, then appends a plaintext-free `team-a` audit entry; the decrypt counter records exactly one decrypt operation for step 1. Every mismatch — including algorithm, `kid`/`key_id` equality, `issued_at`/`expiry` window, audience, claim, identity, terminal, and not-assigned — returns no value, performs zero local AES-256-GCM decrypt operations, and returns the same non-revealing `404 environment_unknown_or_unavailable` shape; the foreign point probe is non-revealing and indistinguishable from an unknown environment.
