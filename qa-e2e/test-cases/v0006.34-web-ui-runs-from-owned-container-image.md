# v0006.34 — Web UI runs from its service-owned container image

## Contract

Web UI owns `svc/web-ui/Containerfile`. Browser E2E builds and starts that
image, obtains the operator artifact from the running container, and keeps the
mocked proxy as the browser's only backend origin. Reading the HTML directly
from the repository or starting a host Web UI binary does not satisfy the
test.

## Steps

1. Build the Web UI image from `svc/web-ui/Containerfile`.
2. Start the image with an ephemeral published HTTP port.
3. Wait for `GET /healthz` to return HTTP 200.
4. Start the mocked proxy with the container as its HTML upstream.
5. Open `/` through the mocked-proxy origin and verify the Mission Control
   entry point.
6. Assert that the harness recorded a non-empty Web UI image identity.

## Expected result

- The Web UI container serves `/healthz` and the embedded browser artifact.
- Browser traffic still uses the mocked proxy as its sole origin.
- The test fails if no image was built or no Web UI container was started.

## Implementation reference

`qa-e2e/web-ui/tests/harness_smoke.spec.ts` — `mocked proxy starts and
preserves the supplied team list`.

RED: the fixture only read `web/index.html` from the host and exposed no image
identity. GREEN: the service-owned image is built once per worker, started for
the suite, and its identity plus proxied entry point are asserted.
