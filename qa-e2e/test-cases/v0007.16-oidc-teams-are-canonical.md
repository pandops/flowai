# Test case: v0007.16-oidc-teams-are-canonical

## Implements

`api-gateway` — `### Requirement: Gateway obtains canonical OIDC teams from OIDC provider`

## Intent

Compatibility and security test verifying provider-neutral normalization of string-array and object-array team claims and proving that browser-supplied values cannot broaden the resolved teams.

## Preconditions

- Provider A returns `teams: ["oidc-team-alpha", "oidc-team-alpha"]` from configured `source=id_token` under `string_array` with `claim_pointer=/teams`.
- Provider B returns `membership.teams: [{"id":"oidc-team-alpha","name":"Alpha","alias":"forged-authority"}]` from configured `source=userinfo` under `object_array` with `claim_pointer=/membership/teams`, `id_field=id`, optional `name_field=name`, and records requested scopes.
- Provider B configuration includes `additional_scopes=["membership.read"]`.
- A malformed fixture returns an object where the configured `string_array` adapter requires an array.
- Gateway can start with absent and unsupported adapter configuration.
- API Gateway's database maps `oidc-team-alpha` to `team-alpha` and `oidc-team-beta` to `team-beta`.
- Test-only read-only Gateway database assertions and State Registry request observations are available as supplementary evidence.

## Steps

1. Complete login with Provider A and read `GET /auth/v1/teams`.
2. Complete login with Provider B, verify `membership.read` was requested only because it is explicitly configured, and read `GET /auth/v1/teams`.
3. Add forged `oidc-team-beta`, `team-beta`, and operator values to each browser callback or follow-up request.
4. Attempt login with the malformed fixture and inspect State Registry observations.
5. Attempt Gateway startup with absent, unsupported, malformed pointer, and source-incompatible adapter configuration.
6. Assert the exact normalized membership and derived-access rows in the Gateway database and absence of OIDC identity columns or values in State Registry as supplementary database evidence.

## Expected outcome

Both valid profiles normalize to exactly one `oidc-team-alpha` and the response contains only `team-alpha`. Object names, aliases, other fields, and all forged browser values are ignored for authority. No adapter adds an implicit scope. The malformed claim fails authentication before any mapping lookup or State Registry request, and State Registry never receives an OIDC identifier. Gateway startup fails before opening a listener when adapter configuration is absent or unsupported.
