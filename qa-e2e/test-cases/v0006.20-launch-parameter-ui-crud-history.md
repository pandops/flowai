# Test case: v0006.20-launch-parameter-ui-crud-history

## Implements

`web-ui` — `### Requirement: Web UI manages scoped launch parameters`.

`web-ui` — `### Requirement: Web UI renders launch-parameter revision history`.

`web-ui` — `### Requirement: Web UI exposes consistent asynchronous and validation states`.

## Intent

Verify the complete launch-parameter UI for ordinary env variables and logical secrets at team and task-type scope.

## Preconditions

- A mocked proxy serves the current Web UI HTTP and WebSocket contract for `team-alpha`; no API Gateway process is required.
- An administrator-managed global definition and one same-team task type exist.
- Team and task-type definitions contain ordinary env variables, secret references, and immutable history.

## Steps

1. Open «Параметры запуска» and inspect global, team, and task-type scope descriptions.
2. Add an ordinary env variable at team scope by entering its «Имя ключа» and
   value, edit its value, then open its «История изменений».
3. Add a task-type env variable without `task_type_id`, correct validation, and submit it with the same-team identifier.
4. Create a logical secret by entering its «Имя ключа» and secret value,
   replace its value, and inspect version history.
5. Delete the env variable and revoke the secret with confirmation.
6. During a pending write, attempt a duplicate submission; then simulate a recoverable write failure.

## Expected outcome

Global scope is read-only; team scope is explained as applying to all team
launches; task-type scope requires `task_type_id` and explains precedence; env
both create forms expose a required editable «Имя ключа», preserve the exact
operator-supplied key, and reject a missing or invalid key before making a
request; env values are visible and editable; secret values are accepted only by create or
replace dialogs and are never redisplayed or present in history; delete and
revoke append history; pending submits are disabled; validation happens before
the request; and recoverable errors retain only safe non-secret input.
