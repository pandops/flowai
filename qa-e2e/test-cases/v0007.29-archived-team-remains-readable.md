# Test case: v0007.29-archived-team-remains-readable

## Implements

`state-registry` — ``### Requirement: State Registry owns team registration through `/admin/teams` ``

`api-gateway` — `### Requirement: Gateway owns OIDC-to-canonical-team mappings`

`auth` — `### Requirement: Gateway validates operator and team claims`

`web-ui` — `### Requirement: Web UI renders one selected-team operator surface`

## Intent

Lifecycle E2E test verifying idempotent team archival, durable historical ownership, continued operator visibility, and rejection of new task ingestion.

## Preconditions

- Active `team-alpha` owns distinguishable tasks, events, controls, environments, secrets, executors, source systems, task types, and audit rows.
- Gateway maps an OIDC team to `team-alpha`; an operator session, an unexpired one-team working token, REST access, and a WebSocket connection are active.
- Valid system-admin and non-admin identities, public API observers, and read-only Gateway and State Registry database assertions are available.

## Steps

1. Archive `team-alpha` through `POST /admin/teams/team-alpha/archive`, then repeat the identical request.
2. Use the token issued before archive, then open the Web UI, list and select the archived team, issue a new token, read its existing data through REST, and receive its existing events through the old and a new WebSocket connection.
3. Submit a previously unseen source task through authenticated source-input `POST /v1/tasks`, then retry a different source ID that was persisted before archive.
4. Register a new OIDC-team mapping to a separately archived canonical team, then list, select, issue a token, and read through REST and WebSocket.
5. Update the archived team's display name and default image, claim a pending pre-archive task that reaches team-default precedence, and attempt unsupported `DELETE` and unarchive operations.
6. Assert exact `archived_at`, unchanged ownership/resource/history rows, retained authorizing Gateway mapping/history rows, absence of newly ingested task rows, and absence of physical deletion through read-only database connections.

## Expected outcome

The first archive returns `201`; the retry returns `200` with the same non-null `archived_at`. Old and new tokens work for existing data. Gateway permits both pre-archive and post-archive mapping, lists the archived state, and Web UI marks the team archived while REST and old/new WebSockets remain readable. Both the new submission and retry of a pre-archive source ID return `409 team_archived` before acknowledgement; the earlier canonical task remains unchanged. Archived metadata remains mutable; a pre-existing pending task claimed after the default-image change uses the new digest. Delete and unarchive routes are absent, while team, resource, history, audit, and Gateway rows remain intact.
