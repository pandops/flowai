# Test case: v0002.70-one-command-may-own-multiple-tasks

## Implements

`state-registry` — `### Requirement: State Registry claims the oldest eligible task atomically under FIFO`.

## Intent

Verify that one immutable `command_id` MAY own multiple tasks while each task is limited to one command, that each successful claim sets `tasks.owner_command_id` to the same `command_id`, and that every claim returns its own `200 claimed` body with its own `created` event.

## Preconditions

State Registry, PostgreSQL, and a team-owned Executor are running; two pending tasks T-1 and T-2 exist for that team and tag in insertion order, with T-1 older than T-2.

## Steps

1. Submit `POST /v1/executors/{executor_id}/claim` with `task_id = T-1` and `command_id = C-multi` and observe `200 claimed`.
2. Submit `POST /v1/executors/{executor_id}/claim` with `task_id = T-2` and `command_id = C-multi` (same command) and observe `200 claimed`.
3. Read each canonical task and confirm `owner_command_id = C-multi` on both, while `executor_id` is the claimant on both and `created_at` / `claimed_at` differ.
4. Read each canonical task event history and confirm exactly one `created` event per task.
5. Submit a third claim for T-3 (a new pending task) with the same `command_id = C-multi` and observe `200 claimed`.
6. Confirm the totals: three tasks, three `created` events, three `owner_command_id = C-multi`, all `executor_id` equal to the claimant.

## Expected outcome

Every successful claim returns `200 claimed` with the canonical task, `resolved_image`, `image_source`, and `claimed_at`. Each task has its own `created` event whose payload encodes `task <task_id> loaded by <executor_id>`. Each task records `owner_command_id = C-multi` exactly once. One command owns multiple tasks while each task is owned by exactly one command.
