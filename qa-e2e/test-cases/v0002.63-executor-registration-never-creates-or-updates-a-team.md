# Test case: v0002.63-executor-registration-never-creates-or-updates-a-team

## Implements

`state-registry` — `### Requirement: Executors register one tag and either team-owned or system-owned scope`.

## Intent

Verify that an Executor registration body submitted under `PUT /v1/executors/{executor_id}` never creates or updates a team row; the only path that creates a team is `POST /admin/teams`. Executor registration with `team_id` referencing a non-existent team is rejected without partial persistence.

## Preconditions

State Registry and PostgreSQL are running; no team exists; an Executor identity is configured.

## Steps

1. Attempt to register an Executor with `scope = team` and `team_id = team-ghost` (no team exists) and observe the response.
2. Confirm that no `teams` row was created.
3. Authenticate the system administrator and create `team-real` through `POST /admin/teams`.
4. Re-attempt to register the Executor with `scope = team` and `team_id = team-real` and observe success.
5. Attempt to register a second Executor with `scope = system` and `team_id = team-real` (non-null) and observe the response.
6. Confirm `teams` has exactly one row.

## Expected outcome

The initial registration is rejected with no `teams` row created. The post-admin registration succeeds. The non-null `team_id` with `scope = system` is rejected. The `teams` table holds exactly the row created by `POST /admin/teams`, never by Executor registration.
