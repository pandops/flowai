# Test case: v0006.31-real-openhands-events-stream-live-in-task-ui

## Implements

`web-ui` — `### Requirement: Web UI renders a live task execution log`.

## Intent

Verify, for Docker and K8s, that multiple user-visible event kinds emitted by
the real OpenHands image appear immediately and exactly once in the open task
card's live log.

## Preconditions

- Run this case in isolated `executor_docker_openhands` and
  `executor_k8s_openhands` Playwright projects.
- Reuse `qa-e2e/agent-openhands-image` and the real-runtime setups from
  `qa-e2e/state-registry/tests/contracts/12-v0005-real-docker-runtime-smoke.spec.ts`
  and
  `qa-e2e/executor_k8s_openhands/tests/v0005.4-real-openhands-runtime-smoke.spec.ts`.
- Extend the deterministic local mock LLM sequence without replacing the real
  OpenHands agent-server: it emits one explicitly published agent message,
  the existing marker-writing tool call, its tool observation, and the
  existing finish summary. No external LLM or hidden model reasoning is used.
- The Executor maps published agent output to the `reasoning` stream and
  action, tool, observation, and completion output to the `work` stream while
  preserving each committed log offset and safe agent-event subtype.
- The task detail is open before the scripted OpenHands sequence is released;
  mocked proxy and browser record monotonic receipt/render times.

## Steps

1. Ingest a uniquely identified task using the real OpenHands image and wait
   until the current concrete Executor claims it.
2. Open that exact task's detail and verify the live log is connected and
   initially contains no scripted agent output.
3. Release the explicitly published agent message and wait for its
   `reasoning` log entry in the open UI without reload.
4. Release the existing terminal or shell tool call that writes
   `/workspace/project/flowai-real-runtime.marker`; observe its `work` entry.
5. Let real OpenHands execute the tool and emit its observation; observe the
   next `work` entry and verify the marker contains
   `flowai-real-runtime-ok` inside the Docker container or K8s Pod.
6. Release the existing finish tool call with summary
   `FlowAI marker written` and message `Task complete.`; observe the completion
   output and terminal task lifecycle.
7. Interrupt the connection after one entry and let the UI automatically
   reconnect from the last committed cursor without an operator action.
8. Compare visible log offsets, stream labels, safe event subtypes, and text
   with the task log read from State Registry; inspect the separate lifecycle
   timeline.

## Expected outcome

Both concrete Executor projects pass using the real OpenHands agent-server
image. Every committed entry appears in the already open task card within two
seconds of the mocked proxy receiving its live frame and without reload. The
explicitly published agent message appears once under «Рассуждения агента»;
the marker-writing action, tool observation, and completion output appear once
under «Работа», in ascending offset order. Pause changes only viewport
following, and automatic reconnect produces no gap or duplicate. The marker proves that
the real tool call executed. Lifecycle `created`, `running`, and `finished`
remain in the separate timeline and are not repeated as log lines; the UI
contains no buttons, links, menus, input, copy, manual follow, manual
reconnect, or clear action and makes no claim to expose hidden model reasoning.
