# Test case: v0006.14-control-events-in-task-feed

## Implements

`state-registry` — `### Requirement: State Registry records and streams task-control events`.

`web-ui` — `### Requirement: Web UI renders task controls in the task event feed`.

## Intent

Happy-path and authorization coverage verifying that cancellation acceptance
and Executor results enter the task feed without becoming lifecycle states.

## Preconditions

- A running `team-alpha` task is assigned to `executor-alpha`.
- A distinct `team-beta` task and Executor exist.
- A mocked proxy adapts live control reads, writes, and WebSocket frames between
  the Web UI and the real State Registry for `team-alpha`.

## Steps

1. Submit cancellation for the running task through the Web UI.
2. Observe the feed and cancellation button before the Executor responds.
3. Have `executor-alpha` append acknowledged and completed control events.
4. Refresh the task page and rebuild it from REST reads and the team stream.
5. Attempt the append operation as the browser and as the foreign Executor.

## Expected outcome

The accepted request produces one pending control event and disables
cancellation; acknowledged and completed appear once in deterministic order
through live delivery and after refresh; the task has no cancellation
lifecycle state; unauthorized appends cause no mutation or publication; and
no `team-beta` event or existence signal reaches the `team-alpha` browser.

`qa-e2e/web-ui/tests/v0006-state-runtime-ui.spec.ts` — `v0006.14 disables cancellation after request and keeps it beside status`.
