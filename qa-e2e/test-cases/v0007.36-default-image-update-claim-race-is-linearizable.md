# Test case: v0007.36-default-image-update-claim-race-is-linearizable

## Implements

`state-registry` — `### Requirement: State Registry requires a mutable team default image`

## Intent

Concurrency E2E test verifying a team-default image update and task claim persist one serializable image resolution.

## Preconditions

- Active and archived team fixtures each have an old digest-bearing `default_image` and two pending tasks whose resolution reaches team-default precedence.
- Eligible team-owned and system-owned Executors and a valid system administrator are authenticated.
- The fixture can hold the real update or claim transaction after team-row locking; read-only task/team assertions are available.

## Steps

1. For a team-owned Executor and active team, hold claim after it locks the team, start `PATCH /admin/teams/{team_id}` with a new digest, release claim, and wait for both requests.
2. In a fresh fixture with the same scope/state, hold update after it locks the team, start claim, release update, and wait for both requests.
3. Repeat both controlled commit orders for an archived team.
4. Repeat the active/archived × both-commit-orders matrix with a system-owned Executor.
5. Read canonical team state and exact claimed-task assignment, `resolved_image`, and `image_source` after every cell.

## Expected outcome

For team-owned and system-owned Executors against both active and archived teams, claim committed first persists the old digest and `team_default`; update committed first makes the later claim persist the new digest and `team_default`. Scope-specific eligibility remains intact. No cell persists a mixed, null, tag-only, or uncommitted value; archival state remains unchanged, and later reads and Executor consumption use the persisted claim result verbatim.
