# Test case: v0002.31-accepts-executor-emitted-events

## Implements

`state-registry` — `### Requirement: State Registry accepts Executor-emitted lifecycle events under the Executor's ownership scope`.

## Intent

Verify the State Registry accepts complete `running`/`finished`/`failed` event envelopes from the claiming Executor, projects state in the same transaction, and rejects unassigned or cross-team writers without appending events.

## Preconditions

A `team-a` task is claimed by `team-a` Executor `executor-1` with `command_id = C-1`; history is `[created]` (the FIRST `created` event is Registry-appended with non-null `executor_id = executor-1`); `tasks.executor_id = executor-1`; `tasks.owner_command_id = C-1`; same-team `executor-2` is authenticated.

## Steps

1. As `executor-1`, post valid `running` with envelope `team_id = team-a`, non-null assigned `executor_id = executor-1`, and a strictly later ordering tuple.
2. Retry that event unchanged.
3. As `executor-1`, post valid `finished` with envelope `team_id = team-a` and a strictly later tuple.
4. As unassigned `executor-2`, attempt a fresh task event carrying envelope `team_id = team-a`.
5. As `executor-1`, attempt a fresh task event carrying envelope `team_id = team-b`.
6. Read task and history through trusted Gateway context for `team-a`.

## Expected outcome

State Registry verifies envelope `team_id` against the authenticated Executor team on every event write. Valid claiming-Executor events return `202 accepted`, update projection transactionally, and append once by `(task_id, event_id)`; retry returns the original result; the unassigned same-team writer is rejected with `403 not_assigned` because the authenticated `executor-2` is not `tasks.executor_id = executor-1`; the cross-team envelope writer is rejected with `403 team_mismatch`. Final history is `[created, running, finished]`; the FIRST `created` row is Registry-appended with non-null `executor_id = executor-1` and payload meaning `task <task_id> loaded by executor-1`; the Executor-emitted `running` and `finished` rows have non-null `executor_id = executor-1` and submitted `team_id = team-a` equal to the authenticated Executor team; no `dispatched` event exists.
